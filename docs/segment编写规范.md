# 分镜编写规范（segments[].body）

> 这份文档只说一件事：**每一段的 `body` 该怎么写**。
> 人物身份、画风、胶片质感、首尾帧承接、眼神频率、画幅、时长、过场方式——全部由公用配置统一处理，
> 你不用写、不用填、也改不到。你只需要把「这一段画面里发生什么」写清楚。

> **2026-11-15 更新**：新增 **§十三 电视剧式多镜头分镜（蒙太奇）规范**，是虎牢关 s-1 项目的实测结论。
> 做「多个机位组接成一场戏」的片子时，§一~§十二 的单段规则仍然适用，但**必须再叠加 §十三**；
> §四、§八 里与实测冲突的旧说法已同步校准。单段/短片可按原规范写，多镜头长片别再全片固定机位。

**两种编写模式**

| 模式 | 适用 | 读哪些章节 |
|---|---|---|
| 单段 / 连续动作短片 | 一段一个动作、链式尾帧承接 | §一~§十二 |
| **电视剧式多镜头长片** | 8 段左右、靠景别与机位组接成蒙太奇 | §一~§十二 **+ §十三（必读）** |

模式判定：除非分镜明确采用多镜头蒙太奇（或明确给出多个镜头），默认一段一镜。长片的「多镜头」主要通过不同段落组接完成；不要仅因段长达到 6 秒就在段内新增切镜。连续动作可用 `At` 描述动作本身已有的阶段，`At` 不是新镜头，也不能借此添加新动作。静止、凝视或蓄势段不强行凑动作节拍。

### 规则冲突时的优先级

1. 用户明确指定的剧情事实、人物、参考图和导演意图；
2. 人物身份、空间方向、接触关系和关键道具连续性；
3. 当前 H3 工作流实测可执行的动作与运镜；
4. 景别、剪辑与节奏建议；
5. 篇幅、格式等体检项。

优化器负责澄清和精炼，不负责重新导演：不能为了满足节拍或字数下限擅自加镜头、动作、人物互动或运镜。必要信息缺失时，采用最少假设的写法。硬性格式校验与内容导演建议冲突时，先保内容含义，再报告格式问题，不得用虚构内容补齐。

## 一、body 的唯一职责

`body` 回答一个问题：**这 8 秒钟，画面里的人做了什么、镜头怎么摆、光从哪来、周围是什么。**

三句话原则：

1. 只写**这一段**发生的事，不写上一段、不写下一段。
2. 只写**看得见**的东西（身体、手、脚步、视线、光、物件），不写心理活动、不写剧情解释。
3. 只写**这一段独有**的信息，公用配置已经写过的内容一个字都不重复。

---

## 二、一段 body 的骨架

推荐固定四块，用空行隔开。不需要小标题的短段可以只写动作，但机位和光线最好别省——
H3 对「镜头在哪、光从哪来」的响应远强于对抽象形容词的响应。

```
她从铁门边起步，缓步走向画面右侧的金属栏杆，右手抬起搭在栏杆上。

[机位] 摄影机跟随她向右平移，保持中景，腰部高度，始终在她左侧后方。

[光线] 与上段同一档橙红夕阳，只有云层亮度极轻微变化，绝不入夜、不转蓝调。

[场景] 粗糙水泥天台，地面浅浅积水，右前方灰白金属栏杆，栏杆外楼群层叠。
```

- **动作**：谁、从哪到哪、身体哪个部位在动、动完停在什么姿态。一句一个动作，按时间顺序写。
- **机位**：摄影机的位置、高度、侧别、景别、是否移动。这一块决定构图稳不稳。
- **光线**：本段的光线状态；连续段只写「与上段一致 + 有没有变化」。
- **场景**：本段用得到的物件与方位。空间结构以空镜板为准，这里只补充「人和什么发生关系」。

### 2.1 本段人物：单独一个字段 `cast`，不要塞进 body

**一段里出现谁、谁对应哪张参考图、本段什么状态，逐段都不一样**，所以它不是全片共用的东西，
既不写进公用 head，也不写进 body，而是每段自己的 `cast` 字段（网页上是每段卡片顶部的「本段人物」框）。

跑片时它的位置是：**head → cast → body → tail**。

写什么：

```
本段出场：<Picture {pic:1}> 是吕布，紫金冠、紫金战甲、持方天画戟，位于画面右侧；
<Picture {pic:2}> 是张飞，黑甲、持丈八蛇矛，位于画面左侧。本段只有这两人，关羽不出场。
```

规则：

- **谁在场就写谁**，没接线的角色不要提，否则模型会硬加人。
- **本段的外观状态**写在这里（换装 / 淋湿 / 受伤 / 摘了头盔），别改全片 head。
- 只写「是谁 + 在哪 + 本段状态」，**不写动作**——动作归 body。
- 留空 = 该段只靠 head 里的通用绑定（`第几号图 = 第几位人物`），适合单人戏。
- `{pic:N}` 占位符在这里同样有效，引用本段没接的序号会直接报错并列出实际接线。

为什么不能写进 head：head 是**全片共用**的，在 head 里写「第一位是吕布」，等于宣称每一段都是吕布的戏。
之前就踩过这个坑——人名进了公用模板，换一部片还是那两个人。

## 三、动作怎么写

### 3.1 写「持续、缓慢、可见」的动作

H3 的实际输出是**长时间近乎静止 + 少数瞬间明显位移**。写「猛地转身 / 快速奔跑 / 剧烈挥手」
不会得到快动作，只会得到一段卡顿的形变。稳妥写法是**一个缓慢动作贯穿全段**：

- ✅ 她缓步向前走了三步，右手抬起搭在栏杆上，随后停住。
- ❌ 她快步冲向栏杆，猛地转身，又迅速跑开。

### 3.2 动作要落在具体部位

- 脚步：起步 / 停步 / 重心转移 / 步幅
- 手部：抬起 / 搭上 / 松开 / 垂下
- 肩与躯干：转向 / 前倾 / 起伏
- 头部与视线：转动 / 低垂 / 抬起 / 落点

只写「她很自然地走动」等于没写，模型会自己发挥。

### 3.3 段与段之间不要重新起步

上一段在走，这一段就接着走；上一段手搭在栏杆上，这一段手还在栏杆上。
**不要写「她重新开始走」「她摆好姿势」**——段首承接由系统自动完成，你只要保证动作状态是延续的。

### 3.4 一段只推进一件事

8 秒装不下「推门 → 走出 → 转身 → 撑伞 → 离开」。一段一个动作单元，多出来的拆成下一段。

## 四、机位怎么写

按这五项写全，缺一项模型就自由发挥：

| 项 | 例子 |
|---|---|
| 位置 | 她左侧斜后方 / 正前方 / 画面右前方 |
| 高度 | 腰部高度 / 胸部高度 / 略高于头顶俯拍 |
| 侧别 | 保持在人物左侧，不跨到另一侧 |
| 景别 | 中景 / 上半身近景 / 面部近景 / 腰部细节 |
| 运动 | 固定 / 缓慢推进 / 垂直升降 / 同速跟拍 / 轻微横移（见 §13.8 执行力清单） |

要点：

- **只改摄影机，不改人物**：切景别时写明「仅改变机位与构图，人物保持原步态与方向」。
- **不跨轴**：同一段内不要从人物左侧绕到右侧；需要换侧就换段、用转场。全片级还要守 180° 轴线，见 §13.2。
- **别写「变焦类」运镜，但别把「位移类」也一起禁掉**（2026-11-15 实测校准）：
  - ❌ 基本不生效：rack focus（移焦）、希区柯克变焦、突然变焦、复杂环绕、手持甩镜。s03 写过「焦点从军阵移到戟刃」，出片只有红缨在飘，焦点没变。
  - ✅ 明显生效：**推轨（dolly in）、垂直升降（crane）、横向平移（truck / slider）、同速跟拍**。s02 从中景一路推到近景是成立的；s01 的前景揭开 + 缓降也成立。
  - 原文「别写复杂运镜 / 固定机位最稳」只适用于**单段稳定优先**的场景，别当成全片规则。
- **固定机位是单段最稳，不是全片最优**：8 段全写「固定机位、不推进、不变焦、不切换景别」= 8 张会动的照片，没有调度。多镜头长片按 §十三 编排。
- 有运镜感又稳的写法：**一个连续运镜 + 动机 + 缓起/匀速/稳住三段节拍**，见 §13.4。

### 4.1 景别决定脸能画到多细（像素账）

H3 不会给每张脸都分配同样的清晰度——脸最后有多少像素，取决于它在画面里占多大：

| 景别 | 人物占画面高 | 1344×768 下的脸高 | 这一镜该写什么 |
|---|---|---|---|
| 大远景 / 远景（城门口、阵列、骑手） | < 40% | **10–20 px** | 只写体态、朝向、剪影、动作、兵器反光。**不要写五官和微表情**——写了也画不出来，只会得到一张白板脸 |
| 全景（完整全身） | 60–85% | 40–60 px | 脸能看出轮廓但**锁不住身份**，表情只写大方向（沉毅 / 警觉 / 疲惫） |
| 中景 / 中近景（腰或胸以上） | 脸占 1/4 以上 | 80–150 px | 可以写微表情、视线落点、眨眼 |
| 近景 / 特写 | 脸占 1/2 以上 | 200 px+ | 唯一能可靠锁住这张脸的景别 |

写死成四条规则：

1. **远景不写脸**。远景镜的「动作」块只写身体与器械，表情最多一句「神情沉毅」。
2. **要观众记住这张脸，就必须给中近景或近景**。远景负责气势，近景负责身份；两者分开写，别指望一个远景全包。
3. **别靠调像素救远景的脸**。像素翻倍只把 10 px 变成 20 px，还是白块；要到 40 px 以上得线性放大 5–6 倍（几十 MP），8G 显存做不到，H3 也吃不下。
4. **远景里区分人物靠外形**：盔甲颜色、兵器、马匹、披风、发饰，不靠脸。

实测（2026-11-15，8 秒 / 736×416）：同一帧里前景人物（约占画面高 60%）五官、胡须、盔甲纹理都清楚，远端的骑手（约占 30%）脸是一块白——模型会画脸，只是远景分不到像素。这跟提示词写得多细无关。

## 五、光线与场景怎么写

### 5.1 光线

- 连续段：`[光线] 与上段完全一致，暖金侧光从左后方来，亮度不变。`
- 变化段（用转场切时间/天气）：`[光线] 入夜，蓝调环境光 + 远处暖色灯点，人物侧脸一道暖边光。`
- **不要写**画风词：35mm、胶片颗粒、电影感、柯达色、浅景深虚化……这些在公用配置里，逐段写会互相打架。

### 5.2 场景

- 只写本段人和物件的**关系**：手搭在哪、脚踩在什么上、身体挡住什么。
- 建筑走向、道路宽度、家具布局属于空镜板，文字写不过图，写多了反而让模型改结构。
- 要新物件就写清「方位 + 材质 + 与人物的相对位置」：`右前方灰白金属栏杆，齐腰高，她右手搭在横杆上`。

## 五之一、对白、说话人与画面文字（官方规范）

官方优化器对对白有严格写法，写进 body 的动作块时照此执行（本项目正文用中文，对白原语言保留）：

- **说话人 ID**：按目标视频中真实发声的**首次出现顺序**分配 `(S1)`、`(S2)`，多人同声 `(S1,S2)`，跨镜不变。被引用主体发声时同时保留可见标签与 ID（如 `<Subject 2> (S1)`）。身份、ID、动作、语气写在 `<d>` 外。
- **对白标签**：`<d>` 内只放语言标签与原话：`<d>[Chinese] 原话</d>`。用户给的原话**逐字逐标点保留**，不翻译不润色；听不清写 `[unclear]` 不猜。只给了「说一段某意思的话」而没给原句时，可写一条简短自然台词。
- **画外音**：用 `says in an off-screen voiceover`，在 `</d>` 后说明画内人物双唇保持闭合。
- **跨镜与截断**：对白跨切镜在连接点用 `<scenetrans>` 并说明声音连续；结尾截断发声用 `<cutoff>`。
- **画面内文字**：招牌、字幕、标签、霓虹文字用**英文双引号**包围，原文与标点不变。
- **不要凭空分配 ID**：直接复用的背景音乐或音轨里的人声只作为可听来源，不生成 `(Sx)`；由具体角色或旁白实际发声才分配。

现场声与画外配乐不要写进 body——它们由全局 `tail` 统一提供（官方的 `overall_soundscape` / `non_diegetic_music` 对应本项目的 tail）。

## 六、眼神与表情：只写本段的落点

公用配置负责身份与眼部外观、眼神光（catchlight）等全片一致的约束。眨眼频率对 H3 不是可靠的全局控制，**body 不写频率句**；只写这一段特有的视线落点和表情。若剧情确实需要一次眨眼，在动作允许时把它作为单次可见动作写入 body。

⚠️ 先看 **§4.1 景别**：**远景 / 大远景不写脸**——人物占画面高不到 40% 时脸只有 10–20 像素，
写微表情、眨眼都不会出现，只会得到一块白板。那种镜只写体态、朝向、剪影、动作、器械反光。

- ✅ 她的视线落在身前的地面，随后慢慢抬向前方的门。
- ✅ 眉头轻轻收紧，嘴唇抿了一下，随即放松。
- ❌ 她的眼睛每 3–4 秒眨一次，瞳孔带细微反光点（catchlight），眼神不空洞。—— 这是公用配置的活，重复会稀释权重。

写的时候只回答：**这一段她在看哪里？脸上哪块肌肉动了一下？**

### 想让角色眨眼：只在合适时写成这一段的动作

实测（2026-11-13，5 秒 / 0.8MP / 同一 seed / 同一参考图，四组对照）：

| 写法 | 结果 |
|---|---|
| 只在公用 head 里写「每 3–4 秒眨一次」 | 5 秒内 **0 次**闭眼，眼睛越眯越垂 |
| 公用 head 精简到 235 字，body 仍不写动作 | 1 次约 0.4–0.5 秒的闭眼（偶发） |
| body 写「缓慢地闭上双眼，停留约半秒，再缓缓睁开」 | 确实闭眼，但被拉成 **约 2 秒**的慢动作（表演级闭眼，不是眨眼） |
| body 写「她很快地眨了一下眼，眼睑迅速合拢又立刻睁开」 | **1 次约 0.5 秒的闭眼，最接近自然眨眼** ✅ |

要点：

- **眨眼不是每段必做项**。只有脸清晰可见、动作允许且不破坏凝视或紧张表演时才写；远景、背影、持续凝视或高张力动作省略。
- 需要眨眼时写在 body，不要写成「缓慢」。写「缓慢闭上」会得到约 2 秒的闭眼表演；写「很快地眨一下、迅速合拢又立刻睁开」才会被压到约 0.5 秒。
- **5 秒段的对照测试中，明确描述一次快速眨眼能生成约一次闭眼**；这只是条件适合时的可用写法，不代表每段都应加入。
- **公用 head 里的眨眼频率句对 H3 基本无效**（0 次），它只稳定响应 catchlight、视线方向这类静态外观。别指望靠它。顺便把眼睛定住：body 里加一句「眼睛正常睁开、看着前方」，能压住那种一路眯下去的默认状态。

## 七、多人段落：关系必须写进 body

参考图只告诉模型「这个人长什么样」，不告诉他「这两个人怎么站」。人物关系是 `body` 的责任：

```
<Picture {pic:1}> 的女生站在画面左侧，面朝右；<Picture {pic:2}> 的男生在画面右侧，半侧身面向她，
右手搭在她左肩上，她的左肩被遮住一部分。两人相距约半步。
```

必须写全：**谁在左/右、各自朝向、有没有接触、谁挡住谁、相距多远**。
人一多脸就小，多人段落优先用中近景；0.5MP 下全身景锁不住脸。

指人物一律写 `<Picture {pic:1}>` / `<Picture {pic:2}>`（**外层尖括号别省**，裸写 `{pic:1}` 展开后只剩数字），
**不要写死 `<Picture 1>`**：链式段的首帧会占掉 P1，
人物整体后移一位，写死编号就会指到首帧上。（`<Picture {pic:plate}>` 指空镜板，一般不用在 body 里。）

## 八、篇幅与硬指标（写完必须过这一关）

**可见的动作进展优先，字数和节拍数只是诊断信号。** 若动作本身持续且清楚，不要为了满足数字重复描述或编造新动作；若成片几乎静止，先检查参考帧、动作幅度、镜头景别和是否有相互冲突的指令。

### 8.1 编写参考（不是内容硬指标）

| # | 指标 | 8 秒段 | 怎么算 | 不满足的后果 |
|---|---|---|---|---|
| 1 | **节拍数** | 按动作需要 | `第一镜/第二镜` 与 `At` 描述已有动作阶段 | 仅在成片动作显得停滞时排查 |
| 2 | **正文体量** | 无固定字数 | 去掉空行后的正文字数 | 以信息是否完整判断，不为字数扩写 |
| 3 | **动作块** | 无固定字数 | 第一个 `[机位]` 之前的文字 | 以动作是否可见、可执行判断 |
| 4 | **三块齐全** | `[机位]` `[光线]` `[场景]` | 缺一即不合格 | 空间/光线失控，段间不接 |
| 5 | **动作可观察** | 至少 1 个位移或姿态变化 | 出现 走/迈/转/抬/落/挥/握/停/前移… | 出「照片式静止」 |
| 6 | **运镜可执行** | `[机位]` 里有类型词 | 固定/推进/拉远/跟拍/横移/摇摄/升降/滑轨/环绕 | 机位随机漂移 |
| 7 | **远景不写脸** | 远景镜不出现面部细节 | 见 §4.1 | 脸上糊一块白 |

**时长不是镜头数或字数公式**：长段可用时间点梳理动作自然阶段，但不按秒数换算镜头数、节拍数或最低字数。短段也不需要为了完整模板添加无关信息。

> ⚠️ **特定动作的实测，不是通用硬规则**（2026-11-15）：连续骑马行进的一个 8 秒镜头中，4 个时间点比 2 个时间点更能维持马腿后半段运动；当时测试的是「四蹄持续交替」这一特定任务。只有动作本身需要持续运动时才采用类似密度，时间点必须描述真实动作阶段，不得强加到挥砍、凝视、短动作或静止表演。见 §13.11。

### 8.2 节拍的两种写法（选一种，别混）

- **拆镜**：`第一镜` / `第二镜`，镜与镜之间可以换机位/景别/构图，也可以是同一机位下的下一段动作。
- **时间轴**：同一镜内用 `At 00:03.500, 旗帜翻卷到最满` 标出变化点，时间严格递增、落在段长之内。

单一连续动作可以只写一镜。动作过程确有可辨阶段时可用 `At` 标出阶段；没有变化的部分不靠时间点伪造变化。一次完整转头等简单动作不要求拆成多个身体部位步骤。

### 8.3 静止题材怎么救

对峙、等待、凝视这类戏最容易出静止。不要写「保持不动」当整段，改写成**大尺度微动态**：

- 环境动：旗帜翻卷、尘土被风带起、雨丝斜落、火把晃动、远处队列踏步扬尘；
- 主体动：马匹踏步/甩头、披风被风掀起、手指在兵器上收紧、重心从一只脚移到另一只脚；
- 视线动：视线从甲处移到乙处（这是最省字、最有效的「有事发生」）。

### 8.4 其他

- 四块之间用空行分隔，读起来是一条条指令，不是一篇作文。
- 不要形容词堆叠（唯美、高级、氛围感、大片感），模型不认，还占字数。
- **别用「与上段完全一致」当占位句**：光线没变就写一句「光线不变」，其余字数留给动作。连续几段都写「与上段完全一致」等于白丢几行预算。
- 写完跑一遍体检：`python selflift_lint.py --cfg output/<片>/segments.json`，有 FAIL 就改，别硬跑。

## 九、不要写什么（公用配置已覆盖）

| 不用写 | 原因 |
|---|---|
| 不换人 / 不融脸 / 保持身份一致 | 全片统一约束 |
| 严格继承上一段真实尾帧 / 首帧承接 | 链式段自动生效，首段自动不生效 |
| 段尾收住 / 段首静息 / 留 0.5 秒 | 全片统一 |
| 眼神光 catchlight / 全片身份约束 | 全片统一；眨眼频率不作为可靠控制项，body 仅按需要写一次具体眨眼 |
| 画风、胶片颗粒、35mm、色调、质感 | 全片统一 |
| 禁止项清单（不要多余手指、不要穿模…） | 全片统一 |
| 人物长相、发型、服装 | 参考图 + 本片设定 |
| 场景建筑结构、道路走向 | 空镜板 |
| 秒数、帧率、画幅、画质、过场方式（`link.transition` 选 cut / dissolve） | 公用配置 |
| 剪辑术语本身（「这是匹配剪辑」「切到反打」） | 元术语，模型读不懂；改写成可执行的画面 |

写了也不会报错，但会**稀释真正有用的信息**，还可能和公用约束打架。

> **例外：多镜头片的 `[剪辑]` 块要写**（§13.6）。它写的是本段的**起幅 / 收幅构图**
> （哪个物体停在画面哪个位置、下一镜从哪里接），是段内画面信息，不是过场方式参数；
> `link.transition` 用 cut 还是 dissolve 仍然由配置决定，别写进 body。

## 十一、完整范例（单段模式）

同一座黄昏天台，三段连续动作。注意每段只推进一件事，机位只在段与段之间变。
**这是「单段 / 连续动作短片」模式的范例；电视剧式多镜头范例见 §13.13。**

### 第 1 段（首段，无承接）

```
她缓缓推开一扇斑驳生锈的铁门，从门后走出来，铁门在身后缓慢回落。

[机位] 摄影机在斜后方腰部高度轻微仰拍，人物位于画面偏左，极平稳地缓慢向前推进。

[光线] 橙红夕阳沉在远处楼群之间，暖金色轮廓光勾出发丝与肩膀边缘。

[场景] 粗糙灰色水泥天台，地面有浅浅积水，右前方灰白金属栏杆，栏杆外楼群层叠延伸到地平线。
```

### 第 2 段（承接上段尾帧）

```
她从铁门边起步，缓步走向画面右侧的金属栏杆，右手抬起搭在栏杆上。

[机位] 摄影机跟随她向右平移，保持中景，腰部高度，始终在她左侧后方。

[光线] 与上段同一档橙红夕阳，只有云层亮度极轻微变化，绝不入夜、不转蓝调。
```

> 没有写「严格继承上一段尾帧」，也没有写「她从静止开始」——承接是自动的，写了反而多一个矛盾点。

### 第 3 段（换时间，用转场切）

```
同一座天台的夜景，她侧身站在栏杆前，风吹动长发，右手仍扶着栏杆。

[机位] 固定机位近景侧脸特写，浅景深，背景灯点虚化成光斑。

[光线] 蓝调夜景，冷色环境光 + 暖色城市灯点，人物侧脸有一道暖边光。
```

> 用 `link.mode = "transition"` 切过来，所以这里写「同一座天台的夜景」交代新时间，
> 不需要写承接，也不需要重复人物长相。

### 多人段落

```
<Picture {pic:1}> 的女生站在画面左侧，面朝右；<Picture {pic:2}> 的男生在画面右侧，半侧身面向她，
右手搭在她左肩上，她的左肩被遮住一部分。两人相距约半步，都没有说话。

[机位] 固定机位，胸部高度，中近景，两人都在画内，女生略靠前景。

[光线] 室内暖白顶光偏左，两人脸侧各有一道柔和阴影。
```

## 十二、常见问题速查

| 症状 | 原因 | 改法 |
|---|---|---|
| 人物几乎不动 | 写的是状态不是动作 | 换成「走三步 / 抬手 / 转身」这类有起止的动作 |
| 动作突然跳一下 | 一段塞了多个动作或写了快速动作 | 一段一件事，节奏改成「缓慢」 |
| 画面自己推拉镜头 | 机位没写全，或写了变焦类运镜 | 补位置/高度/侧别/景别，运镜只留「固定/推进/升降/横移/跟拍」这类位移型 |
| 换景别后人物重新起步 | 没写「人物动作保持连续」 | 切景别处补一句「仅改变机位，人物保持原步态」 |
| 场景结构和空镜板不一样 | body 里写多了建筑/布局 | 删掉场景结构描述，只留人物与物件的接触关系 |
| 人物脸崩 / 换脸 | 段内景别太远或动作太大 | 改中近景，减小动作幅度，必要时加参考图 |
| 两人衣服越跑越像 | 两人外观太接近 | 在 body 里写死各自衣着差异（女生白裙 / 男生深色外套） |
| 八段像八张会动的照片 | 每段都写「固定机位、不推进、不变焦」 | 按 §十三 把 8 段当 8 个机位编排景别序列 |
| 转场像 PPT | 接缝全 dissolve | 6 个 cut + 收尾 1 个 dissolve，见 §13.7 |
| 后半段动作越来越小、最后定格 | 只有 2 个节拍 / 写了「收步、放缓」 | 加密到 4 个 At 节拍，全部改正向措辞 |
| 写了运镜但画面没动 | 用了 rack focus / 变焦类 | 换成推轨、升降、横移、前景物体运动 |
| 长兵器握不住 / 变成普通长枪 | 只靠文字描述形制 | 本地生图把形制画进段级参考图，再逐项点名 |
| 两匹马越走越近、转成正面 | `[场景]` 写「相向行走」、动作写「原地踏步」 | 两块口径统一，见 §13.10 |

## 十三、电视剧式多镜头分镜（蒙太奇）规范

> 来源：虎牢关 s-1 项目 2026-11-15 的 v2→v4 三轮重写 + 逐段出片实测。
> 适用：8 段左右、要「像电视剧那样镜头很溜」的长片。**单段短片不用看这章。**

### 13.1 核心原则：一段 = 一个镜头

**电视剧的镜头高级感不是一个镜头里变戏法，是多个不同机位 / 景别的镜头组接出来的。**
H3 一段 8 秒只能生成**一个**镜头，段内写「先切到特写、再切回全景」必然崩。
所以正确做法是把 8 段当成 8 个机位来编排，而不是让每段内部切镜。

每段 `[机位]` 必须有一句授权句，把模型锁死在一个连续运镜上：

```
本段唯一授权的连续运镜是 ______；不切镜、不越轴、不环绕、不突然变焦。
```

这句和全局 head 里「不无故环绕 / 不越 180 度轴线」是对齐的，**不用改全局 head**。

### 13.1.1 约 10 秒短场景：三镜组接模板

对于一次冲突、一个反应或一段情绪变化，优先用 **3 段 × 3–4 秒**，而不是把一个 10 秒生成段写成多次切镜。三个段都使用同一批角色参考图与场景锚点，第二、三段设置 `link.mode = "transition"`、`transition = "cut"`；成片通常约 10–12 秒。

| 镜 | 任务 | 推荐景别与动作 | 剪辑接点 |
|---|---|---|---|
| 1. 建立 | 交代双方关系、方向与空间 | 双人全景或中远景；前景遮挡揭示、缓降或轻横移 | 收在关键道具或视线方向 |
| 2. 行动 | 只呈现一次决定性动作 | 双人中景或道具中近景；一次挥砍、递物、转身或一步逼近 | 收在动作结果与反应姿态 |
| 3. 反应 | 让观众读到后果和情绪 | 过肩中近景、反打近景或物件特写；只保留余势 | 干净构图收束，供下一场使用 |

这类镜头之间的景别跳变依赖硬切，而不是首尾帧像素承接。每段内部仍是一条连续镜头；一致性依赖共享参考图、固定人物左右关系、同一动作轴线和可匹配的关键道具。若只有文字而没有可靠人物参考图，先做一张包含主要角色、服装和左右关系的同框锚点图，再用于三段。

### 13.2 先画俯视图：所有机位守 180° 轴线

动笔前先在一张俯视图上把 8 个机位摆出来。硬约束：

- 全部待在**动作轴线同一侧**，只变**高低 / 距离 / 景别**，不越轴；
- 越轴的后果是观众丢失左右关系 —— 上镜在左边的角色，下镜突然跑到右边，戏就断了；
- 相邻镜头的机位要在图上有**明确的位置差**（高低、远近、正侧），不能只是换个景别数字。

| 镜 | 机位（轴线同侧） | 高度 | 景别 | 唯一运镜 |
|---|---|---|---|---|
| s01 | 两军之间中轴线上方 | 高机位俯 15° | 大远景 | 缓降约 2m |
| s02 | 吕布左前方 / 守军侧 | 略低于马背、微仰 | 全景 → 中景 | 推轨前行 |
| s03 | 正对戟头、与戟头等高 | 平视 | 道具近景 | 右横移 0.2m + 微推 |
| s04 | 吕布正侧稍前 | 眼平 | 近景 | 呼吸式微推 |
| s05 | 吕布右肩后方（OTS） | 肩高 | 过肩全景 | 右横移 0.5m |
| s06 | 张飞左前方、平行同速 | 马身高度 | 跟拍中景 | 同速横移 |
| s07 | 两骑连线侧方 | 略低 | 双人中远景 | 弧移 |
| s08 | 两军之间中轴线 | 低机位 → 高处 | 中远景 → 大远景 | 垂直抬升 1.5m |

### 13.3 景别序列模板

相邻镜头的景别**必须有跳变**，同景别硬切等于没给新信息。8 段推荐序列：

```
大远景建立 → 推轨中景 → 道具插入 → 面部特写 → 反打过肩 → 同速跟拍 → 弧移对峙 → 拉升收束
```

- 前段负责**空间**：城门、军阵、左右关系一次交代清楚，后面切近景观众才不迷路。
- 中段负责**身份与细节**：兵器形制、脸、Reactions。
- 后段负责**关系和收束**：把两个主体放回同一画面，再拉回全景。

⚠️ 别把 8 段都写成「中景双人对话」—— 那是监控录像，不是分镜。

### 13.4 段内运镜：动机 + 三段节拍 + 唯一授权

**别写「8 秒匀速」**，机械且没有表演逻辑。每段运镜要有**动机**（跟着什么动）和**起落**：

```
[机位] <位置/高度/侧别/景别>；本段唯一授权的连续运镜是 <类型 + 幅度>，
动机是 <跟着人物的哪个动作/视线>：前 2 秒缓起、中间 4 秒匀速、最后 2 秒放缓稳住，
景别始终维持 <基准>；不切镜、不越轴、不环绕、不突然变焦。
镜头内调度：<见 13.5>。
```

要点：

- **幅度写数字**：下降约 2 米、向右横移约 0.2 米、景别收到人物占画面高 2/3、抬升约 1.5 米。
  模糊的「缓慢推进」模型各段理解不一致，数字才稳。
- **动机必须来自画面里正在发生的事**：「跟随吕布抬眼望向对面军阵的视线」「随云影掠过战场把观众带进两军之间」「贴住张飞迎战的行进节奏」。
- **别写元术语**：「这是一个匹配剪辑」「用蒙太奇手法」模型读不懂，只写可执行的画面。
- 收束镜头才允许「放缓」；其余段的收尾写「保持同速 / 节奏与开头一致」，见 §13.11。

### 13.5 镜头内有戏：高级感的真正来源

机位摆对了只是骨架。电视剧的高级感来自**镜头内部还有一层调度**，写进 `[机位]` 行尾的
「镜头内调度：」块（原机位约束、动作块一字不动）。四个可用手法：

| 手法 | 具体写法 | 作用 |
|---|---|---|
| **前景遮挡揭示** | 「起幅左 1/3 被三根虚化长枪杆与暗红旗面遮住，随缓降与右移依次向左掠出画，收幅前景清空露出完整战场」 | 不靠切镜就释放信息，最容易被 H3 执行 |
| **纵深走位** | 「张飞不是横向平移，而是从远景纵深走向中景、人在画面里逐渐变大」 | 制造空间厚度，比纯镜头位移有效 |
| **几何构图** | 「戟杆斜切成左下→右上的对角线」「头部落在右上三分点」「左侧留负空间给反打对象」「虚化肩甲与雉尾构成前景框」 | 让画面有设计感，而非居中站定 |
| **前景物体节拍** | 「三根暗红旗杆依次在第 2、4、6 秒从镜头前掠过」 | 用前景视差给速度感，不必让镜头加速 |

**v4 八段的调度分配**：

| 镜 | 镜头内调度 | 运动强度 |
|---|---|---|
| s01 | 前景枪杆旗面依次掠出，逐层揭开战场 | 静 |
| s02 | 戟杆对角线 + 下缘马鬃虚影随步掠动 | 渐强 |
| s03 | 戟头 1/4 → 2/3 尺度跃迁，红缨作引导线 | 凝视 |
| s04 | 呼吸式微推 + 左侧负空间 | 呼吸 |
| s05 | 过肩前景框 + 张飞从纵深由远及近 | 蓄势 |
| s06 | 三根旗杆 2/4/6 秒节拍 + 阵列视差后掠 | 动 |
| s07 | 双主体负空间 + 两支兵器连成对角对峙线 | 紧 |
| s08 | 拉升把两骑缩成棋盘里的两个点 | 放 |

> **实测（2026-11-15，SelfLift s01）**：前景遮挡揭示确实生效。抽帧显示 f0/f24 左前景是
> 虚化暗红旗面 + 长枪杆，f48 逐渐左移，f72 起前景清空、两军阵列与城门完整露出，后段贴地土雾滚动。
> 左 1/3 区域帧间 MAE **41 / 45 / 39 → 20 / 18 / 19 / 15**，正好对应「前景在动 → 揭开后稳定」。
> **结论：靠前景物体运动做镜头内蒙太奇，比纯镜头运动更容易被 H3 执行。**
> 对照 s03 的 rack focus 写了基本没反应 —— 所以变焦类设计一律换成横移微推 / 前景遮挡 / 纵深走位。

**整片运动要有强弱曲线**：`静 → 渐强 → 凝视 → 呼吸 → 蓄势 → 动 → 紧 → 放`，别八段同速。

### 13.6 新增第五块 `[剪辑]`：起幅 / 收幅构图

多镜头片在四块之外**再加一块 `[剪辑]`**。它写的是本段开头和结尾的画面落在哪儿，
是让相邻镜头真能「接上」的关键。注意：**写画面，不写剪辑术语，也不写 transition 类型**。

```
[剪辑] 起幅保留城门、军阵与完整的赤兔马，吕布在画面中央偏左；最后两秒推进放缓，
收幅时戟头稳定停在画面右上三分之一、不再横移也不出画，双月牙刃与红缨完整清晰。
```
```
[剪辑] 起幅戟头位于画面右上三分之一、与上一镜末尾的位置和大小相近；
收幅时双月牙刃仍完整在画面内、红缨飘向右侧，画面重心干净，不出现人脸与马。
```

配套写法：

- 上段**收幅**写清某个物体停在画面哪个位置；下段**起幅**写「位于同一位置、大小相近」—— 这是道具匹配剪辑能接顺的原因。
- 视线反打：上段收幅写「视线落在画面左侧、头部不再转」，下段从那个方向起反打。
- 动作接续：上段收幅写「四蹄仍以同一节奏交替、右向运动不中断」，下段起幅「跟拍速度已与黑马同步」。
- **别把 `link.transition` 写进 body**，那是配置字段（§13.7）。

### 13.7 接缝：以硬切为主，按剪辑逻辑编排

**电视剧 90% 是硬切。** 7 个接缝全设 `dissolve` 是典型错误 —— 实测切点前后两帧两张画面
半透明压在一起、发灰发糊，观感像 PPT 转场；硬切一帧就从中景跳到戟头特写，干净利落。
尤其 s02→s03 是「上一段的戟头 → 下一段的戟头特写」的**道具匹配剪辑**，硬切才接得顺。

**推荐编排：6 个 `cut` + 收尾 1 个 `dissolve`（0.25s，表示时间收束）**

| 接缝 | transition | 剪辑逻辑 |
|---|---|---|
| s01 → s02 | `cut` | 景别跳切（大远景 → 推轨中景） |
| s02 → s03 | `cut` | **道具匹配**（戟头 → 戟头特写），最顺 |
| s03 → s04 | `cut` | 同主体接反应（兵器 → 持兵器的人） |
| s04 → s05 | `cut` | 视线接反打（OTS） |
| s05 → s06 | `cut` | 动作接动作（同一行进方向） |
| s06 → s07 | `cut` | 运动方向接续 → 对峙 |
| s07 → s08 | `dissolve` | 情绪收束（拉回整片战场） |

配置写法（`segments.json` 里每段的 `link` 字段）：

```json
{ "mode": "transition", "transition": "cut" }
{ "mode": "transition", "transition": "dissolve" }
```

- `cmd_merge` 的 `_gap_transition` 支持逐段混用 `dissolve` / `black` / `cut`，cut 走 concat、dissolve 走 xfade。
- **景别跳变处一律 `transition`，别用 `chain` 尾帧像素硬接** —— 景别不同硬接必崩。
  `chain` 只用于同景别、同机位的动作延续。
- 同片混用两条生成链路会导致各段分辨率不一致，`cmd_merge` 直接报错，见 §13.12。

### 13.8 H3 运镜执行力清单（实测）

| 生效 | 基本不生效 |
|---|---|
| 推轨 / 缓推（dolly in） | rack focus（移焦） |
| 垂直升降（crane up/down） | 希区柯克变焦、突然变焦 |
| 横向平移 / 滑轨（truck、slider） | 复杂环绕、手持甩镜 |
| 同速跟拍（tracking shot） | 段内切镜、景别突变 |
| **前景物体掠过 / 遮挡揭示** | 纯靠文字形容的「焦点变化」 |
| 纵深走位（人由远及近变大） | 多机位同时运动 |

实测依据：s02 从中景一路推到近景成立；s03 写「焦点从军阵移到戟刃」出片只有红缨飘动、焦点没变，
已换成「沿戟刃轮廓极缓右移 0.2m + 轻微推近」。

#### 打斗戏专项（2026-11-16 仙剑项目实测）

**H3 做不出连续招式，别写「劈砍→格挡→反击」这种多步接触序列。** 实测：写了
「举刀劈落→长剑格挡→火星→滑剑逼退→再格挡」，逐帧表显示 H3 把它演成**兵器反复交叉、
火星闪三四次、两人站桩举刀的机械循环**——每个「接触点」都被理解成同一个举刀碰一下的动作。

**更优解：写「一次单向的决定性挥砍」（2026-11-16 仙剑 v3 实测，效果强于纯对峙）。**
H3 做不出的是「多次你来我往」，但**一次完整的挥砍它能演**——前提是把动作节奏写细、写慢、映射到节拍：
- 结构 = 蓄力（拧腰举兵器到一侧）→ 挥出（自 A 方向 B 的单次弧线，一气呵成不回头）
  → 命中（对手后仰 / 后滑 / 披风翻飞的反应）→ 收势（收兵器站定、距离拉开）；
- 提示词**反复强调「全段唯一的一次挥砍」「方向始终向左下不回头」「做完不再重复」
  「没有第二次交手」**，刻意避开「再次 / 连续 / 反复 / 来回 / 一起一落」这类触发循环的词；
- 剑气光弧跟随刃口拖出、在挥砍最高处凝成光刃，作为力量感的视觉载体（H3 很擅长画这种光效）；
- 把 4 个 `At` 节拍精确对应蓄力 2s / 挥出 4s / 命中 6s / 收势 7.5s，H3 会照着节拍推进。

实测逐帧：先侧身蓄力 → 一道巨大青色剑气弧光自右上劈到左下横贯画面（**清晰的一次挥砍**）
→ 头领后仰手臂上扬、弯刀脱手、披风翻飞 → 收剑站定距离拉开。无卡碟循环，打斗感强。
固有限制：对手「后滑两步」的大幅位移 H3 演不全（多为原地后仰晃动），写的时候心里有数。

**退路（当挥砍也演崩时）：用渐进的氛围变化代替招式过程**（H3 擅长的「持续、缓慢、可见」）：
- 缓慢逼近：两人各自向前挪步、距离一点点缩短（脚碾碎石扬尘，位移可见）；
- 能量凝聚：剑气 / 刀光从兵器上缓缓亮起、增强、蔓延；
- 发力前一瞬定格：剑尖抬起一分、光效凝到最盛，收在「将发未发」；
- 真正的出招 / 命中留到下一段用切镜表现（见 13.7）。

这样逐帧是「远→近、光由暗到盛」的清晰递进，不会卡碟式循环。仙剑 v2 按此法从「动作太傻」
变成剑气横贯的对峙张力；v3 进一步用「一次挥砍法」演出了真正的攻击动作。备份见项目日志。

### 13.9 写之前先算像素账：主体和道具画不出来就别写动作

- **0.5MP 大远景里马腿只有 3–5px**，写再多「四蹄交替」也画不出来。
  先把段级参考图换成中景（马占画面高 1/4 以上、四条腿完整可辨），再写动作。
- **长杆兵器（方天画戟）要拿在手上**：先本地 Krea2 生成一张兵器占画幅大的段级参考图
  （中央枪尖 + 左右对称弯月牙刃 + 枪尖下红缨 + 握杆手），再逐项写形制 +
  「全程握在右手、戟头高过头顶、不插地、不靠肩、不消失、不变普通长枪」。
  实测这样能稳定握住。**早先为防漂移改成「斜插地面」是错的方向**（吕布全程没碰过兵器，用户明确不满意）。
- **双主体同框的段级参考图必须把身份特征画进图里**：Krea2 默认把两个骑手都画成一样的圆盔。
  要区分就逐项点名（A 金束发冠 + 双红雉尾 / B 蓬发 + 络腮胡），并写
  「不能都画成圆头盔、冠与羽饰不得互换」。只写「严格复刻参考图」会把两人锁成同一个。
- **段级 head 的动态豁免要限定到具体部位**：可用「XX 是动态主体、不属于固定结构」对抗空镜参考
  「已有结构不得移动」的锁定，但只豁免马腿 / 马蹄 / 鬃尾 / 尘土旗帜。
  把「马背骑手」一起豁免，会连服装、朝向一并放开，剪影就和参考图对不上；
  骑手这类要保形的部分**单独列「必须严格复刻」并逐项写外观**（圆顶黑盔、灰银鳞甲、暗红镶边鞍具、侧身握缰坐姿）。
- 0.5MP 下中景骑手约 40px，文字能锁盔甲颜色与轮廓、锁不住细纹理。要更强一致性得裁紧参考图放大主体，或全片提分辨率。

### 13.10 段内自洽：三个最容易翻车的矛盾

1. **`[场景]` 块 vs 动作块**。实测翻车：动作写「两匹马各自原地踏步、间距不变」，
   `[场景]` 却残留「两匹战马由两端向中段相向行走」→ 模型把两马越拉越近、约 3.3 秒起转成正面、腿并拢定格。
   **两块口径必须逐字对齐**，改动作时回头搜一遍 `[场景]`。
2. **动态豁免 vs 严格复刻**（见 §13.9）。别把要保形的部分一起豁免。
3. **参考图 vs 文字**。参考图主导构图：ref5 是背面视角（两骑背对镜头朝城门），
   成片就跟着变背面，提示词里「侧身相对、马头朝画面中央相对」的旧措辞压不过图。
   换参考图时同步检查描述。

### 13.11 抗后半衰减：4 节拍 + 全正向措辞

H3 的 8 秒段后半动态会固有衰减。两个节拍不够，模型会收敛回参考图的静态姿态。

**模板**（每个 At 点名具体部位，最后一个点写「仍在动」）：

```
At 00:02.000, 左马抬右前蹄、右马抬左前蹄，四蹄交替加快转为轻快小跑，蹄下扬尘变浓
At 00:04.000, 两马换腿：左马抬左前蹄、右马抬右前蹄，马鬃马尾随蹬地后摆，骑手随马背起伏
At 00:06.000, 再次换腿：左马抬右后蹄、右马抬左后蹄，步幅与步速保持，尘土持续贴地滚动
At 00:07.500, 四蹄仍在交替抬落，最后一帧保持一条前蹄抬起，节奏与开头完全一致
```

**删光所有否定式收尾措辞** —— 模型会把「不收步 / 不减速 / 不落下」也当成减速停下的指令：

| ❌ 别写 | ✅ 改成 |
|---|---|
| 此后步幅与步速保持不变，没有任何收步、减速或停下 | 此后步幅与步速一直保持不变，四蹄继续交替抬起、屈伸、落地，节奏与开头完全一致 |
| 画面不进入定格 | 每一帧马腿都处在不同的行走相位 |
| 8 秒全程不收步、不减速、不定格 | 8 秒全程保持同一节奏与步幅，最后一帧仍有一条腿抬起 |

**验收口径**：腿部 ROI 每 4 帧 MAE 前半 ~5、后半 ~3 属可用，末尾别掉到 1.x。
实测迭代：2 节拍版后半 2.88、末尾 1.1（转正面定格）→ 4 节拍 + 正向措辞版前半 5.37 / 后半 3.17、末尾 3.98。

### 13.12 蒙太奇链路选择：用 SelfLift

同提示词（4373 字）/ 同 seed / 同 3 张参考图的 A/B 实测结论：

| 项 | SelfLift | 黑鹤二采 |
|---|---|---|
| 分辨率 | 960×544 | 1216×704 |
| 同尺度锐度 LapVar | **2846** | 2204 |
| 单段耗时 | **5.9 min** | 7.1 min |
| 空间锚点 | 全程保留马全身 / 城门 / 军阵 | 推到末帧环境基本出画 |
| 参考图分工 | 238 有 `strict_prompt_tags` + 标签重写 | 核心节点按固定顺序摆图，不校验 |

**选 SelfLift**：全 cut / dissolve 组接不接首帧，两链路的硬锚优势都用不上；
跨镜头最怕丢空间参照，SelfLift 明显更稳；黑鹤一采 0.2MP ×2 放大重建把细节柔化了，
**像素多 ≠ 更清楚**。

- **别在同一片里混用两条链路**：merge 会统一缩放吃掉分辨率优势，且片级下拉切换会标全片 stale。
- 黑鹤的 `MiniMaxH3AddGuide` 能追加 `frame_idx=0` 首帧锚，但承接 MAE≈19.8，
  **不是 SelfLift `first_frame` 那种逐像素硬锚（~2.5）**，别当精确承接用。
- 核心 `MiniMaxH3ReferenceToVideo` 的 `ref_image_size='max'` 官方标注 best identity fidelity
  （2048px 短边、参考 token 每步采样都在），理论上治「跨段换人」，本机未验证且会慢几倍，8GB 卡别赌。

> 说实话：**「8 段固定机位 → 8 个机位组接」带来的提升远大于两条链路之间的差别**。先把分镜做对。

### 13.13 完整范例（s02 真实片段，直接照抄结构）

```
[机位] 摄影机位于吕布左前方、守军一侧的中轴线上，略低于马背高度、微仰拍；
本段唯一授权的连续运镜是沿中轴线向吕布推轨前行，动机是跟随吕布抬眼望向对面军阵的视线：
前 2 秒随前蹄落地缓起、中间 4 秒匀速推进、最后 2 秒放缓收住，
8 秒内景别由带阵列的全景自然收成吕布与赤兔马占画面高度约三分之二的中景，
全程不切镜、不越轴、不环绕、不突然变焦，人物在画面中的位置基本居中。
```

## 十四、导演决策层与执行边界（2026-11-16 补充）

> 前面各章讲的是「怎么写才出片」。这一章讲「写之前先决定什么」和「哪些规则冲突时谁让谁」。
> 来源：对 S-1 体系的一次系统审核——保留全部实测规则，补上真正缺的决策层与校验机制。

### 14.1 先有叙事目的，再有机位

动笔前先回答「这一镜**为什么要这样拍**」，再决定机位。同一个剧情有不同拍法，表达的情绪完全不同：

- 建立环境 → 大远景，交代空间与人物位置；
- 展示人物动作 → 全景/中景；
- 传递情绪、识别身份 → 中近景/近景（唯一能锁脸的景别）；
- 强调关键物件 → 道具近景（如戟头）；
- 展示关系 → 过肩/双人中景；
- 强化冲突、完成转折 → 靠景别跳变 + 运动强度曲线（见 §13.3 / §13.5）。

**这是内部决策，不写进 JSON**——但它决定了景别序列、运动强弱、以及哪一段必须给近景。
判据：如果一段戏观众必须认出是谁或看到情绪，却只写了远景，那这段的导演决策就是错的，加再多提示词也救不回。

### 14.2 动作复杂度自适应（修正 §3 的机械理解）

§3 的「起势→过渡→位移→缓冲→收住 3–6 步」针对**复杂动作**，不是所有动作都套：

| 动作复杂度 | 拆几步 | 例 |
|---|---|---|
| 简单 | 1–2 步 | 低头看一眼手里的信 |
| 普通 | 2–4 步 | 转身、抬手指向对方 |
| 复杂 | 3–6 步 | 上马、挥戟、推开重门 |
| 多人互动 | 按人分别写 | 拥抱、搀扶、交递物件 |

一镜**只突出一个主要动作**；衣摆摆动、呼吸起伏、重心微调是辅助动态，不要当成独立剧情动作逐条罗列——
把自然动作拆成六个「部位+方向+幅度」会产生机械感，这正是 H3 出「木头人」的诱因之一。

### 14.3 复杂交互的接触三段式

只对人-物、人-人接触动作启用（推门/拿起/拔武器/拥抱/上马/落座）：

1. **接触前**：手伸向哪里、物体在什么位置、距离多远；
2. **接触中**：哪个部位接触物体的哪一处、受力方向、物体如何响应；
3. **接触后**：物体停在哪、手是否松开、接触关系是否保持。

目的：杜绝物体凭空移动、手部穿透、接触中途丢失。普通位移（走路、转头）不用套这条。

### 14.4 chain / transition 的三个连续性概念

连续性分三种，别混为一谈：

| 概念 | 含义 | chain | transition |
|---|---|---|---|
| 剧情连续 | 时间线、因果接得上 | 要求 | 要求（除非明确换时间/地点） |
| 动作连续 | 人物姿态、动作方向、重心接得上 | 要求 | 新镜给清起始状态即可 |
| 像素级首帧连续 | 上一尾帧当下一首帧硬接 | **要求** | 不要求（景别跳变硬接必崩，见 §13.7） |

**无论哪种模式，都不得无理由改变**人物身份、服装、左右位置、关键道具。
写 transition 段时明确新镜头的起始状态（谁在哪、朝哪、什么景别），模型就不会把「独立生成」理解成「可以换人」。

### 14.5 场景描述三分：静态锚点 / 动态元素 / 互动对象

- **静态锚点**（建筑、道路、地形、家具、固定设施）→ 交给空镜板锁结构，body 不复述；
- **动态元素**（风雨烟尘、灯火变化、旗帜）→ body 写变化，作为「大尺度微动态」救静止戏（§8.3）；
- **互动对象**（门、武器、桌面、缰绳）→ body 写人如何接触、接触三段式（§14.3）。

这样切分能减少模型因 body 里重述背景而擅自改动空镜锁定的空间结构。

### 14.6 原始 body vs optimized_body：粘贴提示词质量校验

在对话里用官方 skill 生成的六段式提示词，粘进每段的「优化后」框（`optimized_body`）；运行时**优先用 optimized_body**，留空才用原 body。
每次粘贴后对照原始 body 检查三件事：

- [ ] **动作数量**：有没有把一条动作线拆成多个独立动作，或漏掉关键动作？
- [ ] **景别 / 运镜**：有没有擅自把近景改成中景、把固定机位改成推进？有没有把 H3 做不到的运镜加回来？
- [ ] **人物位置 / 接触 / 道具**：左右、朝向、接触关系、关键道具（如方天画戟）有没有被改变或丢失？

发现被改坏就用面板的「清除优化」回到原始 body；必要时把关键约束写进 `cast` 或段级 `head`（段级 head 是整段覆盖，写它要把全片统一约束逐字复制进去）。

### 14.7 规则冲突优先级（精简版，与配置规范前置章节一致）

自洽可执行 → H3 实测做得到 → 人物与空间连续 → 景别决定细节 → 导演表达 → 格式兜底。
完整说明见 `导演工作台配置与分段提示词规范.md` 前置章节。**理论正确但本机做不出 = 错**（§13.8）。
