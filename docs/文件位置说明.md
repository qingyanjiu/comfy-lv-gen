# 文件位置说明

这份文档只回答一个问题：**每个文件/目录在哪、它是干什么的、谁在读它。**

所有路径都相对仓库根目录 `h3-long-video-repo/`，除非另外注明「仓库外」。

## 0. 仓库挂在哪

仓库本体在：

```
D:/Comfy-Desktop/ComfyUI-Installs/h3-long-video-repo/
```

ComfyUI 通过一个 **junction（目录链接）** 把它挂进自定义节点目录：

```
D:/Comfy-Desktop/ComfyUI-Installs/ComfyUI/ComfyUI/custom_nodes/ComfyUI-H3-LongVideo
        └── 指向 ──> D:/Comfy-Desktop/ComfyUI-Installs/h3-long-video-repo
```

也就是说：**改仓库里的文件 = 改节点里的文件**，不需要复制。
`install_custom_node.bat` 就是建这个 junction 的脚本。


`__pycache__/`、`.pytest_cache/` 是运行时缓存，已在 `.gitignore` 里。

## 2. 逐个文件干什么

### 根目录

| 文件 | 作用 | 谁读它 |
|---|---|---|
| `__init__.py` | 把 `director.py` 里的节点类导出给 ComfyUI，并声明 `WEB_DIRECTORY = "./web"` | ComfyUI 启动时 |
| `director.py` | `H3LongVideoDirector` / `H3SingleClipDirector` 两个节点；`/h3-long-video/*` 全套路由；起 worker 线程；任务目录（改名/删除/迁移） | ComfyUI 启动时 import；前端调它的路由 |
| `run_h3_long_video.py` | 编排器：`build_graph` / `build_keyframe_graph` 现搭 API 图，串关键帧链、跑分段、修二采开头、FFmpeg 拼接 | `director.py` 用 subprocess 起它；也可由 `run_full.bat` 直接跑 |
| `config.json` | 全局默认配置；每个任务会把它复制一份到任务目录再覆盖本次参数 | `director.py`、`run_h3_long_video.py`、`tools/*.py` |
| `requirements.txt` | `requests`、`imageio-ffmpeg` | 手工安装依赖时 |
| `install_custom_node.bat` | 建 `custom_nodes/ComfyUI-H3-LongVideo` junction | 手工执行（已执行过） |
| `open_config.bat` | 记事本打开 `config.json` | 手工执行 |
| `run_full.bat` | 命令行跑完整流程 | 手工执行 |
| `run_test.bat` | `--limit 1 --no-stitch` 冒烟 | 手工执行 |

### `web/`

| 文件 | 作用 |
|---|---|
| `director.js` | 长视频面板：任务下拉框、改名/删除、关键帧卡片（替换/重画/还原）、分段脚本编辑器、分段视频与成片、全屏/独立窗口/灯箱 |
| `single_clip.js` | 单段面板：首尾帧预览、进度、成片播放 |

前端只跟 `/h3-long-video/*` 路由说话，不直接碰 Python 模块。

### `api_workflows/`

| 文件 | 作用 |
|---|---|
| `segment_one_pass_api.json` | 从原始 H3 工作流导出的「一采」API 图，**仅作对照** |
| `segment_two_pass_api.json` | 同上，「二采」版 |

程序**不读这两个文件**：`run_h3_long_video.py` 里的 `build_graph()` 用代码现搭图，
节点编号（1/11/2-3/20-28…）与导出文件一一对应，方便对照排查。

### `example_workflows/`

| 文件 | 作用 |
|---|---|
| `H3-Long-Video-Director.json` | 长视频主线：`LoadImage` ×4 + `H3LongVideoDirector`（接了参考图 2 张 + 可选首帧） |
| `H3-Single-Clip-FirstLastRefs.json` | 单段主线：11 张 `LoadImage`（首帧、尾帧 + 最多 9 张参考图，示例接了 4 张）+ `H3SingleClipDirector` |
| `Qwen2511-FirstFrame916.json` | 用 Qwen-Image-Edit 2511 出 9:16 首帧 |
| `Qwen2511-MultiAngle-Edit.json` | 同 + 多角度 LoRA（转视角） |
| `Qwen2511-Reference-Edit.json` | 多图参考改图（换装、换场景），4 步，最多 3 张参考 |
| `Qwen21-Reference-Edit.json` | 同一件事的 2.1 版：8 步 Turbo，最多 10 张参考，8GB 卡更宽松 |
| `lab/H3-One-Segment.json` | 实验：Qwen 出首尾帧 + H3 单段，一张图走完 |
| `lab/Qwen2511-PoseFix-MultiAngle.json` | 实验：姿态修正 + 转视角一起做 |

`lab/` 下的都是实验版：可以改坏、不作为基线。

### `tests/` 和 `tools/`

| 文件 | 作用 |
|---|---|
| `tests/test_graph.py` | 54 个用例。跑法：`python -m unittest tests.test_graph`（在仓库根目录） |
| `tools/build_director_workflow.py` | 输入分镜 JSON，输出 `<分镜名>.director.workflow.json`（`pipeline.py push` 用它） |
| `tools/cleanup_comfy_assets.py` | 扫 ComfyUI 的 input/output，删没人引用的图片 |

## 3. 仓库外的运行时目录

这些路径写在 `config.json` 里，跟仓库**平行**放在 ComfyUI 共享目录下：

| 配置项 | 实际路径 | 里面是什么 |
|---|---|---|
| `comfy_input_dir` | `D:/Comfy-Desktop/ComfyUI-Shared/input` | ComfyUI 的输入目录：参考图、灌进去的首尾帧 |
| `chain_input_dir` | `D:/Comfy-Desktop/ComfyUI-Shared/input` | 链式段复制进去的帧（和上面同一个目录） |
| `comfy_output_dir` | `D:/Comfy-Desktop/ComfyUI-Shared/output` | ComfyUI 输出根目录 |
| `final_output_dir` | `D:/Comfy-Desktop/ComfyUI-Shared/output` | 成片根目录 |
| `jobs_dir` | `D:/Comfy-Desktop/ComfyUI-Shared/output/h3-long-video/jobs` | 每个任务一个子目录 |

`output/` 下具体长这样：

```text
D:/Comfy-Desktop/ComfyUI-Shared/output/
├── h3_long_video/              长视频的分段视频、关键帧草稿、long_video.mp4
├── h3_single_clip/             单段成片
└── h3-long-video/
    └── jobs/
        └── 20261101-宿舍试穿/    ← 一个任务一个目录（名字 = 日期-名称）
            ├── config.json      本次实际配置（含每段提示词）
            ├── status.json      状态：scheduled/running/awaiting_review/completed/failed
            ├── .state.json      关键帧链、分段结果、手动帧覆盖、各类 sha1
            ├── run.log          runner 的完整日志
            ├── reference_*.png  参考图副本（任务自包含）
            ├── opening_frame.png
            └── keyframes/
                └── segNN_start_manual.png …   手动替换的帧
```

> 任务目录和 `output/h3_long_video/` 是两回事：前者是「这个任务怎么跑」的记录（很小），
> 后者是「跑出来的片子」（几十 MB 级）。`output_prefix` 是全局配置，所以
> `h3_long_video/` 是所有长视频任务共用的，按 seed 命名，不按任务分文件夹。
