# 提示词须知

> 这份文件只讲**怎么写提示词**。字段含义看 `分镜JSON.md`，参数含义看
> `参数配置.md`，整体流程看 `长视频流程.md`。
>
> 下面每条规则后面都标了依据：`[实测]` = 用同一首帧同一种子做过 A/B；
> `[代码]` = 由程序行为决定，不用试也必须遵守。

## 0.0 先确认你写的是哪套字段（很容易搞错）

仓库里有**两套不同的分镜 schema**，字段名不通用，写错名字不报错、只静默不生效：

| | A. Director 节点 / `config.json` | B. 长视频流水线（`skills/h3-long-video`） |
|---|---|---|
| 入口 | ComfyUI 里 `H3-Long-Video-Director` 节点的 `storyboard` 框；或 `<jobs_dir>/<id>/config.json` | `assets/<分镜名>.json` + `pipeline.py` |
| 一段长什么样 | `{seconds, prompt, end_frame_prompt, start_frame_prompt, free_end, ...}` | `{seconds, shot, frame, open_action, end_action, motion, beats, amplitude, dir, gaze}` |
| 身份/服装 | 节点 `reference_notes` 输入框，自动前置到每条提示词 | **没有这个字段**：模板已写死方向锁/服装锁/闭嘴/固定机位，身份靠参考脸图 |
| 关键帧谁出 | Director 用 H3 跑「5 秒草稿取帧」；也可被人工图覆盖 | Qwen-Image-Edit 2511 + 参考脸，或你自己放图（`adopt`） |
| 提示词怎么来 | 你手写四个字段 | 模板渲染，可用 `prompt_first/last/pose_fix/video/segment` 整段覆盖 |

**本文档 §1~§9 讲的是 A 套字段。** 如果你走的是 B（也就是平时那条流水线），
字段名对不上，别照 §9 的 JSON 抄——去看 `skills/h3-long-video/SKILL.md` 的字段表。
下面这张表说明 B 套里哪些字段会进到哪份提示词（由 `pipeline.py` 的 `render_prompts()` 自动拼，不用手写）：

| B 套产物 | 取哪些字段 | 送进哪个工作流 |
|---|---|---|
| `prompt_first` | `shot` `open_action` `frame` `gaze` `dir` + 全局 `chars` `style` `wardrobe` | `Qwen2511-FirstFrame916.json` 首帧生成 |
| `prompt_last` | `end_action` `head` `move` `frame` `gaze` `dir` `wardrobe` | `Qwen2511-Reference-Edit.json` 尾帧编辑 |
| `prompt_pose_fix` | `dir` `wardrobe`（仅 `dir.body` 为 left/right 时生成） | 同上，只修正首帧朝向 |
| `prompt_video` | `shot` `motion` `gaze` `pace` | `H3-Single-Clip-FirstLastRefs.json` |
| `prompt_segment` | `shot` `open_action` `end_action` `motion` `gaze` `wardrobe` | `H3-Long-Video-Director.json` 整段 |

还没写进分镜的那一层（`beats` / `amplitude`）不直接进提示词：`check` 用它校验「动作量配不配这段时长」。

## 0. 先记住一句话

**提示词不是剧本，是「锚点的说明书」。**

模型每次只演 6~15 秒。它需要知道的只有三件事：这一段开头长什么样、结尾长什么样、
中间怎么动。写超出这个范围的信息（长剧情、人物小传、5 段节拍表），模型不会照着演，
只会把注意力分散到「脸」「服装」这些容易命中的词上，反而更容易崩。

## 1. 四条提示词各管什么

| 字段 | 管什么 | 什么时候生效 | 系统会自动追加什么 |
|---|---|---|---|
| `prompt` | 这一段的**运动**：走 / 停 / 坐 / 转身、镜头怎么动、环境声 | 永远 | `reference_notes`（前置） |
| `start_frame_prompt` | 这一段的**开场画面**长什么样（静态构图） | 第 1 段永远用；之后只在断开的镜头（`continue_from_previous: false` 或 `chain_segments: false`）用 | `reference_notes`（前置） |
| `end_frame_prompt` | 这一段的**终点画面**长什么样（静态构图） | 只要不是 `hold_composition` / `free_end` | `reference_notes`（前置）+ 机位段（后置）+ 身份重锚定（可选） |
| `transition_prompt` | 两段之间那条生成式转场怎么演 | 仅 `transition_mode: "generated"` | `reference_notes`（前置） |

尾帧 prompt 的最终形态（`[代码]`）：

```
<reference_notes>
<你的 end_frame_prompt>
<身份重锚定提示词>      ← 仅 keyframe_reanchor_every > 0 时，默认关闭
<机位提示词>            ← keyframe_camera_continuity: true（默认开）
```

**顺序是有意的**：采样器对 prompt **尾部**权重最高，所以机位这类「必须遵守」的约束永远压在最末。

## 2. 六条硬规则

### ① `end_frame_prompt` 一定要单独写 `[代码]`

不写的话会退化成整段 `prompt`（含全部动作描述），等于要求「一张静态图」表达整段的运动终点。
这是最容易踩、后果最严重的一条。

### ② 尾帧的动作预算 = `keyframe_draft_seconds`（默认 5 秒）`[代码]`

尾帧的生成方式是这样（`run_keyframe`）：

```
start 帧 = 从「本段起点」生成一段 5 秒草稿 → 取第 0 帧
end   帧 = 从「start 帧」接着生成一段 5 秒草稿 → 取最后一帧
```

也就是说，**尾帧只有 5 秒的演化时间**，而真实段落可能是 15 秒。

> ⚠️ 这一条只对 **A 套（Director 自己生成关键帧）** 成立。走 B 套流水线时，尾帧是
> Qwen-Image-Edit 把首帧当输入、按 `end_action` 直接编辑出来的，没有「草稿」这一步，
> 所以不受 5 秒限制；那边对应的约束是**首尾帧姿态差不能过大**——`check` 用
> `beats`/`amplitude` 对 `seconds` 做校验（见 SKILL.md 的幅度对照表）。

判断方法：把 `end_frame_prompt` 里的动作念一遍，问自己「5 秒做得完吗」。

- 做得完（坐下、转身、抬手、走近两步）→ 正常锚定
- 做不完（走 10 米、起身 + 转身 + 走远、穿过整条街）→ **拆短段**，或者这一段用 `free_end`

`[实测]` 反例：15 秒「走向长椅」。尾帧写成「已经站在长椅左侧」→ 5 秒走不完，模型只能靠
**把镜头推近**来假装到达，结果尾帧是胸像特写，长椅顶到镜头前。

### ③ 不要写「不要移动镜头」`[实测]`

人朝镜头走 + 机位锁死 = 物理上必然放大成胸像。这不是模型不听话，是几何矛盾。

要表达的是「**景别不变**」，不是「机位不变」。写法见第 3 节。

`[实测]` A/B：同一首帧同一种子，`identical camera position / do not move the camera closer`
出胸像；`Tracking shot ... pulls back ... full body from head to feet` 出全身且身份一致。

### ④ 不要在尾帧 prompt 里讲脸 `[实测]`

「脸型、五官、发型、肤色必须与参考图完全一致」这类句子会把采样注意力拉到脸上，
镜头随之推近，抵消掉上一条的跟拍指令。所以 `keyframe_reanchor_every` 默认是 **0（关闭）**。

身份一致性靠三件事：参考图质量 + 链式继承（上一段尾帧就是这一段首帧）+ 段长别太长。

### ⑤ 身份、服装、禁止项写在 `reference_notes`，不要每段重复 `[代码]`

`reference_notes` 会**自动前置**到每一条 prompt（`prompt` / `start` / `end` / `transition`），
一处维护、全局生效。每段再抄一遍的后果是 prompt 越来越长、不同段的措辞互相打架。

### ⑥ 越重要的指令越靠后 `[代码]`

采样器对尾部权重最高。「不许裁切」「保持全身」「不要推镜头」这类**硬约束**放最后一句，
不要塞在开头。

## 3. 机位怎么写（目前唯一实测有效的句式）

**推荐**（跟拍 / 景别不变）：

```text
Tracking shot: the camera moves with her and pulls back as she walks forward,
so she keeps exactly the same size in the frame and stays fully visible from
head to feet. The background slides past her. Never zoom into her face, never
crop her feet or head.
```

**反例**（会出胸像）：

```text
identical camera position, do not move the camera closer, fixed camera, static shot
```

**为什么**：9:16 的取景框是固定的。人朝镜头走近几米，框不变就只能裁掉腿或放大脸。
你要的「她一直全身在画面里」＝镜头必须后退，所以指令里必须出现 **dolly / pull back / tracking**。

这段文字默认由 `keyframe_camera_prompt` 自动追加到尾帧 prompt（`keyframe_camera_continuity: true`）。
如果你有自己的镜头语言（手持、环绕、摇臂），把它改成你的措辞，或者关掉自动追加自行写入。

> 顺便记一笔：把同一段话也塞进**视频** prompt（`video_camera_continuity: true`）实测
> **压不住中段推近**，默认关闭。视频段的镜头呼吸只能靠缩短段长或改走位解决。

## 4. 段长 vs 能演多少

| 段长 | 这一段适合演 | 尾帧锚定 |
|---|---|---|
| 4~6 秒 | 一个动作：坐下、起身、转身、点头、伸手 | 稳，优先用这个 |
| 6~10 秒 | 两个动作，或 3~5 米的短位移 | 可以，尾帧要写得保守 |
| 10~15 秒 | 一段连续位移（走过一段路、推门进屋） | 危险，建议 `free_end` |
| >15 秒 | —— | 不建议（肢体崩坏概率明显上升） |

判断标准不是「时长」，而是 **动作能不能用一张静态图概括**：

- 能（坐在长椅上、站在门边）→ 正常锚尾帧
- 不能（走到长椅旁、坐上公交）→ `free_end: true`

## 5. 景别和构图

### 5.1 「全身」必须有参考图依据 `[实测]`

如果参考图全是头肩近景，模型没有身体比例、裤子、鞋子的依据，只能自己编——
这是「要求全身却出半身/胸像」反复出现的根因之一。

参考图建议组合（同一个人、同一套服装）：

| 张数 | 内容 | 作用 |
|---|---|---|
| 1 | **全身正面**，站直，脚在画面内 | 身体比例、裤子、鞋子（最关键） |
| 2 | 中性表情的近景正脸 | 脸部基准，别用大笑 |
| 3 | 侧脸或 3/4 侧脸 | 防「每段都是正脸」 |

避免：三张全是大笑、三张全是近景、三张服装不同、不同光线。

每张图分别负责什么（`Picture 1 / 2 / 3` 的分工写法）见 `参数配置.md`
的「参考图说明 reference_notes」——那段文字会前置到每一条提示词，是全局唯一的身份声明。

### 5.2 「9:16 完整全身」不是万能咒语 `[实测]`

它只约束**这一帧不裁切**，不约束「人走到远处时不变小」「镜头不推近」。
后半句必须靠机位指令（第 3 节）或分镜（横着走，而不是朝镜头走）解决。

### 5.3 横向走动最省事 `[推断]`

「平行于画面走过」的段落，景别天然稳定，5 秒草稿也够用，尾帧锚定最稳。
如果剧情允许，**把「走向镜头」改成「从画面一侧走到另一侧」**，能省掉一大半问题。
（这条是从「朝镜头走必然放大」的几何关系推出来的，还没做过严格 A/B，但方向不会错。）

## 6. `free_end` 什么时候用

一句话：**这一段结束时人在哪，一句话说不清，就别锚尾帧。**

| 情况 | 用 `free_end` 吗 |
|---|---|
| 走一段路到某处、上车、推门离开、起身走远 | ✅ 用 |
| 坐下、站定、转身看镜头、转头、抬手 | ❌ 不用，锚定更好 |

`free_end` 的行为（`[代码]`）：

- 这一段的尾帧**不生成**，视频自己决定停在哪
- 下一段的起始帧 = **这一段视频真实的最后一帧**（面板显示「接视频末帧」）
- 若下一段还没渲，面板显示「待定首帧」，等按顺序渲完自动填入

所以它不只是省一张图，而是**消除了「锚点 vs 视频实际结尾」的错配**——
那个错配正是「下一段首帧倒退」的根源。

## 7. 常见翻车对照表

| 症状 | 根因 | 改法 |
|---|---|---|
| 尾帧是胸像特写、脸占半屏 | 机位锁死 + 人朝镜头走 | 换成跟拍句式（第 3 节） |
| 尾帧换脸（圆脸 + 露齿笑） | 参考图里有大笑那张，6 步采样会集中命中它 | 换掉大笑图，补一张全身 |
| 下一段明显「倒退」（长椅变远） | 锚点只演了 5 秒，视频演了 15 秒 | `free_end`，或把段拆到 6 秒 |
| 整片像 PPT（画面不动但有人声） | 后处理后遗症，与提示词无关 | 已修（`build_two_pass_repair_filter` 权重写反） |
| 中段人越走越近、后半段又拉回去 | 模型自身的镜头呼吸 | 拆短段或改横向走位，提示词压不住 |
| 片子最后一帧是竖向拖影/鬼影 | 时长正好落在 H3 合法帧数上（如 8 秒 = 192 帧），末尾坏帧没被裁掉 | 不是提示词问题，`tail_guard_frames`（默认 2）已修；见 CONFIGURATION |
| 每段表情都一模一样 | 参考图表情统一 + 链式继承 | 参考图给中性表情，链式段别拖太长 |
| 人物手/腿变形、脚踩在地面下 | 段太长 + 全身镜头 | 段压到 6~10 秒 |
| 画面里多出一个人 | 场景描述里出现了「人群」「路人」 | 删掉，或明确 `no other people in frame` |

## 8. 提交前自检（8 条）

1. `end_frame_prompt` 写了，而且和 `prompt` 不一样
2. 尾帧里的动作，5 秒做得完（做不完 → 拆段或 `free_end`）
3. 段长 ≤ 10 秒；超过 10 秒的段都有 `free_end` 或足够的理由
4. 尾帧 prompt 的最后一句是机位/构图约束，不是动作描述
5. 没有任何「不许移动镜头」「固定机位」类表述
6. 尾帧 prompt 里没有大段讲脸/五官的话
7. 参考图里有 1 张**全身**，且三张表情不冲突
8. 身份、服装、禁止项只写在 `reference_notes`，段内没有重复

### 改完提示词怎么验证（别直接渲视频）

先只出关键帧，几分钟就能看到结果，不满意再改，别浪费 10 分钟的渲染：

```bash
python run_h3_long_video.py --config jobs/<job>/config.json --stage keyframes --force
```

看四件事：首帧是否全身、尾帧是否落在预期位置、尾帧的身份有没有漂、景别有没有突然变化。
四张都对了，再 `--stage videos` 往下跑。

只改某一段时，用 `--from-segment N --to-segment N` 缩小范围；重渲后别忘了它的下一段起始帧
会跟着变（链式），需要连带重渲。

## 9. JSON 怎么写

提示词不是「一段自由文本」，它必须落在固定的 JSON 结构里。这一节把结构、字段、
常见语法坑和两种入口一次讲清。

### 9.1 顶层结构（两种写法都行，推荐对象形式）

```json
{ "segments": [ { "seconds": 6, "prompt": "第一段提示词" } ] }
```

也接受**裸数组**：

```json
[ { "seconds": 6, "prompt": "第一段提示词" } ]
```

两者等价（`_normalize_storyboard` 里 `dict` 会取 `segments`）。推荐对象形式，
以后加字段不破坏结构。**段数 = 数组长度**，不要求固定几段。

### 9.2 一段的完整字段表

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `seconds` | 数字 | ✅ | —— | 段长（秒），必须 > 0。4~10 秒是稳定区间 |
| `prompt` | 字符串 | ✅ | —— | 这一段的运动描述，不能为空 |
| `end_frame_prompt` | 字符串 | ⚠️ 强烈建议 | 等于 `prompt` | **省略 = 用整段 prompt 当尾帧描述**，等于让静态图演完整个动作（见 2.①） |
| `start_frame_prompt` | 字符串 | 可选 | 等于 `prompt` | 只在第 1 段、或断开的镜头（`continue_from_previous: false`）生效 |
| `two_pass` | 布尔 | 可选 | `false`（config.json 里是 `two_pass_default`） | 是否二采放大；节点 `two_pass_mode` 可整体覆盖 |
| `hold_composition` | 布尔 | 可选 | `config.stabilize_full_body` | 尾帧直接用首帧（定格），不生成新图 |
| `free_end` | 布尔 | 可选 | `false` | 不锚尾帧，下一段接本段真实末帧（见第 6 节） |
| `continue_from_previous` | 布尔 | 可选 | `config.chain_segments` | `false` = 本段与上段断开，单独生成首帧 |
| `transition_seconds` | 数字 | 断开段必填 | `config.transition_default_seconds` | > 0 |
| `transition_prompt` | 字符串 | 可选 | 内置转场文案 | 仅 `transition_mode: "generated"` 用 |

> 顺序不重要，字段名区分大小写，不认识的字段会被**静默忽略**（写错名字不会报错，只会不生效）。

### 9.3 四种可直接复制的写法

**① 最小单段**

```json
{
  "segments": [
    {
      "seconds": 6,
      "prompt": "<女主角>从长椅左侧沿步道向前走，步伐自然放松；镜头后退跟拍，保持全身入镜。",
      "end_frame_prompt": "<女主角>停在步道中段，长椅出现在右侧前方；全身入镜，头顶和鞋底都在画面内。"
    }
  ]
}
```

**② 三段链式（默认打法，每段接上一段真实尾帧）**

```json
{
  "segments": [
    {
      "seconds": 6,
      "prompt": "第一段：走两步后停下",
      "end_frame_prompt": "第一段终点：站在步道中间，全身入镜"
    },
    {
      "seconds": 6,
      "prompt": "第二段：原地转身侧向镜头",
      "end_frame_prompt": "第二段终点：侧身站定，长椅在画面右侧，全身入镜"
    },
    {
      "seconds": 6,
      "prompt": "第三段：在长椅上坐下",
      "end_frame_prompt": "第三段终点：端坐在长椅上，双手放膝上，全身入镜"
    }
  ]
}
```

链式段的 `start_frame_prompt` 不会生效（首帧来自上一段），不用写。

**③ 断开 + 转场（跳场景、跳时间）**

```json
{
  "segments": [
    {
      "seconds": 6,
      "prompt": "在宿舍走廊里向前走",
      "end_frame_prompt": "站在走廊尽头，全身入镜"
    },
    {
      "seconds": 6,
      "continue_from_previous": false,
      "transition_seconds": 1.0,
      "transition_prompt": "镜头平移过渡到室外，光线从室内暖光变为日光",
      "start_frame_prompt": "站在公园入口，正面看向镜头，全身入镜",
      "prompt": "从公园入口沿步道向前走",
      "end_frame_prompt": "走到步道中段，长椅在右侧，全身入镜"
    }
  ]
}
```

注意：**断开的段必须给 `transition_seconds > 0`**，否则直接报错（见 9.5）。

**④ 长位移段用 `free_end`（推荐）**

```json
{
  "segments": [
    {
      "seconds": 15,
      "free_end": true,
      "prompt": "<女主角>沿步道一路走到木质长椅旁，镜头后退跟拍，始终全身入镜。"
    },
    {
      "seconds": 6,
      "prompt": "<女主角>在长椅旁侧身坐下，双手放在膝上。",
      "end_frame_prompt": "<女主角>端坐在长椅上，全身入镜，长椅占据画面右侧。"
    }
  ]
}
```

第一段没有 `end_frame_prompt`（写了也不生效，`free_end` 优先）。第二段首帧 = 第一段视频真实末帧。

### 9.4 写 JSON 的 6 个坑

| 坑 | 表现 | 正确写法 |
|---|---|---|
| 字符串里直接回车 | JSON 语法错（`Invalid control character`） | 用 `\n` 表示换行：`"prompt": "第一句\n第二句"` |
| 引号没转义 | 语法错 | 文本里的英文双引号写 `\"`；中文「」不用转义 |
| 最后一项多逗号 | 语法错（`Expecting property name`） | 最后一个 `}` 后不加逗号 |
| 写注释 | 语法错 | JSON 不支持 `//` 和 `#`，说明文字写到 `reference_notes` 里 |
| 数字加引号 | 类型错或时长异常 | `"seconds": 6`，不是 `"6"` |
| 字段名写错 | **不报错**，静默不生效 | 对照 9.2 抄，注意 `continue_from_previous` 不要写成 `continue` |

### 9.5 会直接报错的校验（报错原文对照）

| 报错 | 原因 |
|---|---|
| `Storyboard JSON is invalid: ...` | 语法错，后面会带行列号 |
| `Storyboard must contain a non-empty segments array` | 顶层不是数组，或 `segments` 是空数组 |
| `Segment N has an empty prompt` | 第 N 段 `prompt` 是空字符串 |
| `Segment N has an invalid duration` | `seconds` 缺失、≤ 0 或不是数字 |
| `Segment N has an invalid transition duration` | 断开的段 `transition_seconds` ≤ 0 |
| `Segment N must be an object` | 数组里塞了字符串或数字 |

### 9.6 两个入口，别搞混

| | Director 节点（面板） | 命令行 / `config.json` |
|---|---|---|
| 分镜写在哪 | 节点 `storyboard` 输入框（JSON 字符串） | `config.json` 的 `segments` 数组 |
| 身份说明 | 节点 `reference_notes` 输入框，**自动前置**到每条提示词 | ❌ **没有这个字段**，必须自己写进每段 `prompt` 开头 |
| 二采模式 | 节点 `two_pass_mode`（跟随每段 JSON / 全部一采 / 全部二采） | 每段 `two_pass` + 全局 `two_pass_default` |
| 执行阶段 | 节点 `stage`（关键帧 → 确认 → 视频 / 一次跑完 / 继续生成视频） | 命令行 `--stage keyframes/videos/all` |
| 适用 | 日常用这个 | 批量、脚本、复跑 |

**`config.json` 的写法**（`segments` 数组，字段与 9.2 完全一致，只是少了 `reference_notes`）：

```json
{
  "comfy_url": "http://127.0.0.1:8188",
  "base_seed": 287977160601974,
  "final_width": 832,
  "final_height": 1472,
  "segments": [
    {
      "seconds": 6,
      "two_pass": true,
      "prompt": "<Subject 1> 是参考图中的同一位成年女性……（身份说明写这里）\n<女主角>从长椅左侧沿步道向前走……",
      "end_frame_prompt": "<Subject 1> 是参考图中的同一位成年女性……\n<女主角>停在步道中段……"
    }
  ]
}
```

因为每个字段都要重复身份段，真实任务里这一段通常是脚本拼的；
用 Director 节点就不必，`reference_notes` 会自动前置。

## 10. 文本模板（抄进 JSON 时记得转义）

这三段就是 9.3 里那些 `prompt` / `end_frame_prompt` 的正文，单独列出来方便对照。

### 10.1 `prompt`（视频，中文，6~10 秒）

```text
<女主角>从长椅左侧沿步道向前走，步伐自然放松，双臂轻微摆动；
镜头跟随她后退，保持全身入镜、人物大小不变；脚踩在砖石路面上，环境是安静的公园。
```

要点：只写运动和镜头；不写身份、不写服装（在 reference_notes 里）、不写「9:16 全身」
（构图约束交给机位那句）。

### 10.2 `end_frame_prompt`（尾帧，只写终点画面）

```text
<女主角>停在木质长椅右侧站定，身体略微侧向镜头，双手自然下垂；
全身入镜，头顶和鞋底都在画面内；长椅在画面右侧，步道向前延伸。
```

要点：静态构图 + 位置 + 朝向 + 关键物体，**不要写过程**（「她走过去」是过程）。

### 10.3 `reference_notes`（全局身份与禁止项，只填在节点里）

```text
<Subject 1> 是参考图中的同一位成年女性：脸型、五官、发型、肤色、身体比例保持一致，
不得混入其他人物的脸或年龄感。服装与场景按当前段落描述延续。
画面内不要出现其他人、文字、水印、字幕、分屏或黑边。
```

## 11. 一句话总结

**段要短、尾帧要写「终点」而不是「过程」、机位要写「跟拍」而不是「锁死」、
身份交给参考图、说不清终点就用 `free_end`；落进 JSON 时字段名照抄、多行用 `\n`。**
