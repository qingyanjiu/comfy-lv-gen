## 1. 跨模型通用规律

以下每一条都在本机实测过（详见各模型章节的实测记录），换模型后建议先按这些写，再针对模型微调。

### 1.1 写"终态"，不写"过程"

模型不理解动作的先后，只会画最终那一帧。

- ❌「刚收起雨伞」→ 出撑开的伞
- ✅「握着一把合拢的长柄伞，伞尖朝下，水珠顺着伞骨滴落」

**凡是"刚…/正在…/即将…"这类过程描述，一律改写成画面里能看见的状态。**

### 1.2 抽象的量、质、过渡 → 会被"物化"成贴图

模型把不可视的描述当成可以直接平涂的色块。

| 写法 | 实际结果 |
|---|---|
| 「两种色温在颧骨处柔和过渡」 | 颧骨上多一块青蓝色块 |
| 「轻微泛红」/「淡淡的血丝」 | 两颊出现成团腮红 |
| 「淡淡的红晕」 | 整片粉 |

**改法：把光/色落到具体的面。**
✅「冷蓝光只打在左侧颧骨的高光点上，右颊是吊灯的暖橙，过渡落在鼻梁的侧面」

### 1.3 皮肤描述里不能出现"红"字

实测最硬的一条：同 seed、同提示词，只改一句皮肤描述——

| 用词 | 结果 |
|---|---|
| `鼻翼两侧淡淡的血丝` | 两颊出现明显粉斑 |
| `鼻翼两侧能看到极细的血管走向` | 皮肤干净均匀，毛孔质感保留 |

**可用清单**：`毛孔` `细小绒毛` `浅褐色小雀斑` `下唇的细微干纹` `眉毛边缘的零星杂毛`
`轻微的不对称` `极细的血管走向` `鼻尖和颧骨的油脂高光`
**禁用**：`血丝` `泛红` `红晕` `微红` `潮红`

### 1.4 单一主光 + 明确方向，胜过一堆氛围词

固定好用的句式：`光从画面左侧以四十五度打来，右侧脸颊落在柔和的阴影里，背景比主体暗一档`。
多光源叠加、只写「氛围感 / 光影高级 / 电影感」会让脸变平、失去体积。

### 1.5 必须写"焦点落在哪"

只写「浅景深」会把主体一起虚掉（手、脸都糊）。补一句：
`焦点落在她的眼睛和睫毛上，睫毛根根分开`

### 1.6 材质要写织法，不写形容词

| ❌ 无效 | ✅ 有效 |
|---|---|
| 质感很好 / 高清布料 | 精纺斜纹 / 羊绒绒面纤维 / 羊毛呢粗纺颗粒 / 皮革纹路与手肘磨痕 / 牛仔膝部褪色 |

### 1.7 主体在画面里的像素决定细节上限

脸占画面 1/3–1/2 才有五官细节；全身景别下"内双眼型"这类描述已经不可控。
反过来也成立：**写"毛孔""睫毛"会把镜头拉近**，想要环境人像就别写它们。

### 1.8 长度不是瓶颈，"画面里要装多少东西"才是

**先把话说死：单纯写长不会让画质变差。**
Qwen2.1 实测，把同一句核心描述重复 6 遍（318 字）和只写一遍（53 字）出图几乎完全一致，
耗时也一样（45.1s vs 48.2s）；MOSS / ZIT 跑同一组对照，规律一致。

真正让画面崩的是**清单膨胀**。现代 DiT 的 LLM 编码器不截断（ComfyUI 里 `max_length` 设成 9.99e7），
提示词被当成"**这张图里有什么**"的清单来读，而不是"该怎么拍"的指令。
清单里每多一条，就得在画幅里给它找个位置——装不下，模型只能把镜头拉远。

表现出来的三条：
- 写了"裤子 / 腰带 / 鞋 / 地面" → 半身像自动变全身，脸小一半，"好看"直接掉档
- 只堆五官、毛孔、皮肤 → 镜头被推到胸像特写（Qwen 172 字就发生了）
- 两个取景要求打架（"半身" + "看得见地面水磨石"）→ 模型任选一个，且通常不是你要的那个

**补一句"这是半身像，不要全身"救不回来**：664 字的 prompt 末尾加上这句（变 686 字），
出图仍然是全身。详见 §5.12。

操作规则：**同一信息只说一次；一条 prompt 只留一个场景；写环境只写"这个景别里能看见的东西"。**

### 1.9 负向提示词的有效性取决于 CFG

- CFG > 1（如 MOSS 3.0）：负向生效
- **CFG = 1（如 Z-Image-Turbo）：负向完全无效**，出问题只能改正向或重抽
- **但"调高 CFG 让负向生效"是陷阱**：ZIT 实测 CFG1.5 不开负向就已经崩色（白变黑、红变蓝）。
  退化来自 CFG 本身。**低 CFG 的蒸馏模型不要为了负向去抬 CFG**（§3.5 有完整数据）。

### 1.11 动态描述要写"瞬间的物理状态"，并给可核对的锚点

模型画的是静止的一帧，写"动感""很帅地跳起"没有意义。要写**这一帧里肉眼能验证的东西**：

- 头发朝哪个方向扬起：`发梢朝画面右侧扬起`（不是"头发飘动"）
- 脚是否离地：`双脚离地约二十厘米，膝盖弯曲`（不是"跳起来"）
- 液体的连续性：`水流从壶嘴连续落到杯口，中间不断开`
- 布料受什么力：`衣摆因为转身微微扬起`、`裤脚因为下坠感向上翻起`
- 补一句 `轻微运动模糊`，比让模型自己猜要好

**四模型实测：动态是分水岭。** 同一组提示词下，Krea2 把"跳跃"画成了**站在地上举双手**，
把"转身甩发"画成几乎静止；而 MOSS / ZIT / Qwen2.1 都能捕捉到腾空与甩发瞬间。
→ **要动作用 MOSS / ZIT / Qwen2.1，别用 Krea2。**

### 1.10 不要写"杰作 / 8K / 超高清 / 绝美 / 大师作品"

对现代 DiT 收益接近 0，反而把画面推向过度磨皮、过度锐化的塑料感。
部分模型（MOSS）训练时专门剔除 AI 图来压这种味道，写这些等于逆向操作。

### 1.12 全身像：画幅先行 + 服装编号 + 表情落到肌肉

四模型实测（832×1248 / 2:3 竖幅 / 同一段提示词 / seed 20261103，产物在 `output/fullbody-test/`）。

**① 全身像必须显式写"留白"，而且要写在第一句。**
`从头到脚完整入画，头顶与鞋尖各留出一拳空间` —— 不写这句，鞋被裁是常态。
实测 ZIT 仍然把**两只脚都裁掉了**（只剩一只鞋尖），其余三个模型都完整。

**② 全身像不要写"毛孔/绒毛/睫毛根根分明"。**
这些词会把镜头推到近景，与"全身"直接冲突。全身要写的是**质感**而不是**细节**：
`皮肤是真实的哑光质感，没有油光`。同时把光圈收到 f/5.6，别用 f/2。

**③ 服装部件要编号列出，位置要隔开。**
两个蝴蝶结（胸前 / 背后）挨着写会被合并成一个；中间插一句裙子描述就分开了。
区间描述（"1～3 条白线"）模型不会取中间值 → 必须写死成"两道"。

**④ 表情别堆近义词，落到具体肌肉。**
"微张嘴 + 半睁眼 + 皱眉 + 疲惫"四个近义词里，只有一个会被执行。
改成 `眉心中间微微收紧，上眼睑下垂遮住三分之一瞳孔，嘴唇自然分开一线`。

**四模型全身像表现（各 1 张）**

| 项 | MOSS | ZIT | Krea2 | Qwen2.1 |
|---|---|---|---|---|
| 耗时 | 22.7s | **19.6s** | 21.5s | 39.4s |
| 脚/鞋完整入画 | ✅ | ❌ **两只脚被裁** | ✅ | ✅ |
| 服装部件准确度 | 高（8/11，choker 漏） | 中（**上衣变露腰短款、蓬松腰封变成细腰头**） | 高（星形耳环最准） | **最高（11/11 全对）** |
| 姿态（半后仰贴墙） | 部分（站直贴墙） | ✅ 靠墙侧身 | ❌ **完全没贴墙，站走道中间** | ✅ **头后仰贴墙，最准** |
| 表情（疲惫半睁眼） | ❌ 睁眼直视镜头 | ✅ 低头闭眼 | ❌ 面无表情看镜头 | ✅ **半睁眼+眉头收紧，最准** |
| 车厢场景解析 | 好 | 好 | **最丰富**（吊环/座椅/广告全对） | 好 |
| 肤质 | 真实 | 偏磨皮，显年轻 | 真实 | 真实（两颊略有粉感） |

**结论：全身像 + 复杂服装 + 姿态表情，Qwen2.1 明显第一，MOSS 第二。**
Krea2 依然是"静物与材质之王、姿态表情之弱"——它能把你列的每一件配饰都画对，但**你让它靠墙它不靠，你让它疲惫它不疲惫**。ZIT 最快，但会自作主张改服装结构（把水手服变露腰短款），且会裁脚。

### 1.13 人像"变好看"的四条杠杆（同题实测，9:16）

上一轮那张四模型全身图"难看"的原因不是模型，是**提示词里两条自伤设定**：顶光 + 疲惫表情。
顶光把眼窝压黑（标准难看配方），"上眼睑下垂遮住三分之一瞳孔 + 眉心收紧"就是让人显得憔悴难受。

改这四处，同一段提示词立刻从"丑"变"好看"：

| 杠杆 | 改前（丑） | 改后（好看） |
|---|---|---|
| **光** | `车厢顶部的日光灯从正上方照下来` | `正面偏上四十五度一只一米二大柔光箱，眼下和鼻翼没有阴影；腰高一块银色反光板把下颌阴影提亮，脸两侧明暗差不超过一档` |
| **表情** | `眉心中间微微收紧，上眼睑下垂遮住三分之一瞳孔，嘴唇自然分开一线` | `放松地站着，唇角微微上扬，视线落在镜头上，眼神清亮，眼白干净，眼睑完全睁开` |
| **皮肤** | `哑光质感，没有油光` | `通透细腻，T 区哑光，鼻梁和颧骨一层很薄的高光，唇色是柔和的豆沙色` |
| **骨相** | 不写（模型套自己的模板脸） | `脸型偏鹅蛋，面颊饱满，下颌线柔和，内双，眼型细长，鼻头圆润` |

**① 顶光是毁脸第一位的原因。** 想要好看就必须有正面 fill——柔光箱在前上方，反光板在下颌。
"顶光 + 硬阴影"适合剧情片和压迫感，不适合人像。

**② "疲惫/憔悴/半睁眼"这类表情写多了必丑。** 人像要好看，表情必须往"放松 + 唇角微扬"写。
要故事感另说，别指望"疲惫"和"好看"兼得。

**③ 景别决定脸有多少像素，而脸像素决定好看上限。**
`七分身`这种词基本不生效（模型对站立人物默认画全身，实测四模型全部画成全身）；
**`半身`有效**（从头顶到腰/大腿）。实测半身的脸像素比全身多约 1.4–1.6 倍，
五官清晰度和"好看程度"提升比任何形容词都明显。
→ **要好看就拍半身；要全身就接受脸只有一百多像素，别指望五官细节。**

**④ 画幅 2:3 → 9:16（864×1536）解决了裁脚。**
同一段话在 832×1248 下 ZIT 把两只脚全裁掉；换 9:16 后 Qwen2.1 鞋下留出干净留白。
但 **ZIT 在 9:16 下仍然裁脚**——它的取景是坏的，不是画幅不够。

**改后四模型（9:16 / 半身 / 同 seed）**

| | MOSS | ZIT | Krea2 | Qwen2.1 |
|---|---|---|---|---|
| 脸的自然度 | 偏偶像/娃娃感，眼大脸小 | 偏娃娃，皮最滑 | **最像真人**（眼比例正常、有轻微不对称） | 自然与精致平衡最好 |
| 配饰完整度 | 全在（冠/星耳环/choker/腰封） | 冠丢失、**又露腰**、手臂多出红臂环 | **冠/choker/星耳环全丢** | **全在** |
| 服装结构 | 对 | **反复改结构**（短款露腰、腰封变细腰带） | 对（但少配饰） | 对 |
| 观感 | cosplay 偶像棚拍 | AI 娃娃 | 真实女生证件照，略僵 | 真实感 + 精致度最好 |

**选型：正片人像用 Qwen2.1（半身 / 9:16 / 柔光）；要"真人感"用 Krea2 但要逐件补配饰；要"偶像感"用 MOSS；ZIT 只适合抽卡。**

### 1.14 "点"的描述会被画成噪点，"面"的描述才会成为质感

写皮肤/材质时，**名词是点还是面，决定了出来是质感还是颗粒**：

| 你写的 | 模型的理解 | 结果 |
|---|---|---|
| `皮肤上布满细密的汗珠` | 无数个小圆点 | **密集亮点，像撒了盐** |
| `皮肤表面有一层薄薄的水光` | 一整片反光面 | 自然湿润光泽 |
| `布料上有细小绒毛` | 无数根细线 | 绒毛感（这一条是好的） |
| `脸上有雀斑` | 离散点 | 雀斑（也是点，但小幅面且稀疏时正常） |

判据：**同一个词重复的次数 + 点状物在画面里占的面积**。

### 1.15 参考图 / 场景锚的瑕疵会被"复刻放大"——喂图前先做卫生

**适用范围：所有"给参考图让模型编辑/派生"的任务（图生图、双图编辑、首尾帧、锚图链），
不只是 Qwen-Image-2.1。**

编辑类模型会把参考图（尤其是"场景锚/图2"这种底版角色）当**逐像素重绘的模板**。
模板上的微纹理、畸形解剖、凭空道具，会被搬进输出并**放大**。2026-11-04 在 2.1 上实测：

- 坏帧（整幅洒斑点）与**锚图自身高频纹理**空间相关 **0.950**，与人物参考图仅 0.051；
- 去掉锚上的畸形脚（inpaint）→ 同种子 493→669，**照样坏**（说明是整图纹理在拉，不是某个局部）；
- 把锚软化到 Lap 8（0.5× 往返）→ 同种子降到 262 干净，但**只救脸不救四肢**、畸形仍被复刻；
- 换成干净锚 → 同 pipeline 六帧**零重试**全干净（脏锚触发率 8/15）。

**喂图前卫生清单**

| 检查 | 为什么 |
|---|---|
| 手指/脚趾/四肢结构正常，边缘不被裁断 | 畸形肢体会被复刻得**比原图更恐怖**（脚趾糊成一团） |
| 没有凭空生成的脚、手、多余人体局部 | 桌沿/画面下缘是重灾区 |
| 没有蒸汽/烟雾/漂浮颗粒/光斑 | 这些是"点状纹理"，会被当纹理先验铺满皮肤 |
| 整图放大看无颗粒状脏斑 | 微纹理是复刻的主要载体 |

**验收方式：静态指标测不出来，只能实跑冒烟。** 用候选参考图当"图2"连跑 3 个种子
（脚本：`h3-long-video/scripts/pipeline.py anchor_probe`），每个种子量
`脸部 Lap<380` 且 `全图高频<15%`，然后看**坏的比例**：

| 坏的种子 | 结论 | 动作 |
|---|---|---|
| 0/3 | 优 | 直接用 |
| 1/3 | 可用 | 把 PASS 的种子锁进关键帧种子（`keyframe_seed`） |
| ≥2/3 | 该换 | 重出参考图 |

**关键认知：触发是「图 × 种子」的交互，不存在绝对免疫的参考图。**
实测同一段分镜、同一提示词：旧锚 100000 坏 / 100001 好；新锚 100000 好 / 100001 坏——
同一个种子换图会翻面。所以"换干净图"实质是把**默认种子那条路**修通
（旧锚触发率 8/15，换锚后默认种子连出六帧零重试），而不是永久免疫。
真正的兜底是"生成后量指标 → 换种子重出"这条闭环。

**别做的三件事**（都验证过无效）：① 用提示词去救（"皮肤干净通透"→ 678 更坏）；
② 提 CFG（1.0→2.5 仍 561）；③ 给参考图轻度降噪（NLM h=6，锚 Lap 73 仍坏 480）。
`薄汗`写一次 = 8‰ 斑点密度，写四处 = 8.7‰ 且肉眼立刻"花"掉（§5.10 实测）。

**要质感就写面**：`一层薄薄的水光`、`均匀的哑光`、`柔和的漫反射`。
**点状词只在你要的正是点时才用**（雀斑、雨滴、火星），且只写一次。
**要"很多"的时候，加的是面积，不是次数**——写"整片肩膀"比重复三次"汗珠"有效得多。

### 1.16 动作类提示词（视频/首尾帧）：一个 beat 只能属于一段

**适用范围：所有分段生成（首尾帧插值、分段续接、chain 串段），以及单段内的连续动作描述。**

分段时最容易犯的错：把同一个动作的"前后半"写在两段里。因为每段只知道自己那对首尾帧，
上一段没停准，下一段就会**从自己的起点重新演一遍**——观众看到的是"做了一次 → 又做了一次"。

2026-11-04 coffee 实测（同一份旧分镜，本地 vs 云端）：

| 段 | 设计 | 云端实际 | 本地 0.9MP 实际 |
|---|---|---|---|
| 段1 | 打字 → **只握住杯柄**（杯不离桌） | 停在握柄（末帧锚定 MAE 6.73）✓ | 过冲，直接端起来喝了一口（MAE 20+）✗ |
| 段2 | 桌面端起 → 送唇 → 啜饮 | 从桌面端起，只喝一次 ✓ | 接到的首帧已在唇边，只好**放下再端一次** ✗ |
| 观感 | — | 伸手→端起→喝，一条线 | 碰一下→放下→又拿起来喝 |

**三条写法规则**

1. **切分点必须落在"静止的、可命名的状态"上**：`手已握住杯柄，杯底仍在桌面`
   ——而不是 `手正在伸向杯子`。切在过程里，两段都要猜中间态。
2. **每段的收尾动作要写"停在哪"，并加硬约束"X 不离开 Y"**：
   `握住杯柄即停，杯子始终放在桌面，杯底不离开桌面，手臂不向上抬，绝不把杯子端起来`。
   只写"伸向杯子"不够——模型会把整条动作链补完。
3. **段末禁止写会"自动续下一段"的动词**：`端起 / 拿起 / 抬起` 结尾的一段，
   下一段若也从桌面起手，就必然重复。要么这段停在桌面，要么下段从"已在空中"开始。

**验收**：末帧锚定 MAE ≤ 10~14 只是初筛；**必须密集抽帧（每 0.6~1s）看动作是否重复/倒退**，
指标正常但动作重复是真实发生过的（MAE 9.8 的一段同样可能演错动作）。

### 1.17 动作动词要写到"生理细节"，否则模型只演动作的壳

写 `喝一口`，模型只能演"把杯子贴到嘴上"——因为"喝"在画面里没有可画的形状。
要拆成**能看见的物理变化**：

| ❌ 空壳写法 | ✅ 可执行写法 |
|---|---|
| `啜饮一口` / `双唇接触杯沿` | `头轻轻后仰，杯身倾斜，双唇含住杯沿停留约一秒，喉部有吞咽动作，随后杯身回正` |
| `走过去` | `右腿迈出，重心移到右脚，左臂自然摆动，衣摆向后带起` |
| `回头看` | `头部转向画面左侧约四十五度，下巴抬到与肩同高，视线落到身后` |
| `生气了` | `眉头压紧，下颌前收，鼻翼张开，双手握拳垂在体侧` |

**关键：`接触 / 碰到 / 贴着` 这类词描述的是"接触"不是"动作目的"。**
写"双唇接触杯沿"，出来的就是碰一下嘴；要喝，必须写后仰 + 倾斜 + 吞咽。

### 1.18 模板自带的"静态锁"会和动作打架——用段级字段覆盖

首尾帧/视频模板为了保稳定，会无条件追加"中性表情锁"（`双唇自然闭合、嘴角平直、不微笑、不张嘴`）
和"方向锁"（`全程朝脚尖方向移动`）。它们对静态人像有用，但**和动作描述直接冲突**时，模型会两头讨好：

- 动作写 `过渡到微笑` + 模板锁 `不微笑` → 表情在两种指令间抖，笑容出不来或忽大忽小；
- 动作写 `含住杯沿吞咽` + 模板锁 `双唇自然闭合、不张嘴` → 只贴嘴不真喝。

**处理方式：在段级写覆盖字段（`mouth` / `gaze` / `dir`），不要改模板**——
模板是全局的，改一次会影响所有段和所有项目。示例：

```json
{"mouth": "嘴部随喝咖啡动作自然变化：端杯时双唇轻含杯沿，吞咽自然，不夸张张嘴；表情放松"}
```

**判断规则**：动作里出现 `笑 / 嘴 / 唇 / 张嘴 / 咬 / 喝 / 说` 任一词 → 必须检查是否被默认嘴锁压制，
需要就覆盖。同理，坐姿段落被方向锁要求"朝脚尖走"时，用 `dir: {heading:"still", body:"still"}` 关掉。

### 1.19 首尾帧里的"静物朝向"必须逐项对齐——杯子把手、椅背、门缝都是锚

**适用范围：所有用首尾帧插值的视频（H3、2511、后续任何 first/last 工作流）。**

**机制**：视频模型把首尾帧当唯一真值。首帧把手朝左、尾帧朝右时，模型只能在两帧之间**自己编一个旋转过程**
（杯子瞬移、把手中途消失再出现、杯身悬空转 90°），或者两段各画各的、接缝处跳变。
2026-11-04 coffee 复查发现：S1_FIRST 与 S3_LAST 的杯柄虽然都朝画面右，但**杯身旋转角不同**
（S3_LAST 杯口和液面朝镜头露出、杯子更大更近）——这次没翻车是因为视频提示词写了"杯柄归位"，模型自己圆过去了；
**这是运气，不是设计**。同类风险还包括：椅子靠背朝向、门的开合方向、笔的本体朝向、屏幕内容、窗帘开合。

**关键帧生成时的规避写法（治本）**

静物不要只写名词，要写"朝向 + 相对位置 + 状态"三件套：

```text
❌ 桌上放一只白瓷咖啡杯
✅ 白瓷咖啡杯放在桌面右侧（笔记本右手边），杯柄朝向画面右方，杯口侧对镜头、看不见杯内液面，杯底与桌沿平行
```

同一段戏的所有关键帧（首帧、尾帧、人物参考）必须用**同一句静物描述**——复制粘贴，不要每次重写。

**视频段提示词里的规避写法（治标兜底）**

```text
杯柄始终朝向画面右侧，杯子只被拿起/放回，不在桌面旋转、不改变朝向和位置
```

**关键帧 QA 增加"静物清单"**：人物查完（指/四肢/烟雾/脏斑，见 §1.15）后，把画面里每件静物列成清单逐项核对——
朝向、位置、比例、状态（满/空、开/合、热气有无）、遮挡关系。**发现不一致不要试图用视频提示词纠正**
（两帧矛盾时模型只能编中间态），回去重出关键帧——和"锚图脏了就重出"是同一条原则。

**长期约定：新坑随发现随记录。** 以后每次跑片发现新的细节问题（画面瑕疵类），当天按四行格式
`现象 → 帧证据 → 根因 → 规避写法` 同时记入本手册（§7.6 坑清单或通用规律新增小节）和
`h3-long-video/SKILL.md` 对应章节。坑清单只增不删，已被修复验证的标"已规避"。

### 1.20 完整案例：coffee 三段（从"喝一口又喝一口"到定版）

一个把 §1.16 / §1.17 / §1.18 三条同时踩中的真实案例。**照这个流程走，任何分段动作戏都能自查。**

**素材**：1 张人物参考图 + 3 对首尾帧（5s / 5s / 6s，9:16；云端 704×1280，本地 832×1472），
Qwen-Image-2.1 编辑模式 + 首尾帧插值。

#### ① 症状

成片里女主"杯到嘴边碰一下 → 放下 → 又拿起来喝一次"。

#### ② 帧证据（本地 0.9MP 版，每 0.6~1s 密集抽帧）

| 时间 | 画面 | 说明 |
|---|---|---|
| 4.4~5.3s（段1末） | 已经端起杯子喝了一口 | **过冲**：设计只到"握住杯柄" |
| 5.8~7.6s（段2前段） | 杯子落到胸口，像放下（其实还在手里） | 段2 在"归位"以对齐自己的起点 |
| 8.2~9.6s（段2中段） | 又抬起来喝第二次 | 段2 的动作本来就是"端起 → 啜饮" |

→ 三段连起来看是"喝了两口"，单看每段都"合理"——这是分段动作戏最难查的一类错。

#### ③ 旧版分镜（模型真正看到的提示词）

| 字段 | 旧文本 | 为什么出问题 |
|---|---|---|
| 段1 `motion` | `只有双手和右臂移动，从键盘移到杯柄，上身其余部分保持稳定…` | 只说"移到杯柄"，没说**停在哪**；H3 把整条动作链补完（握 → 端 → 喝） |
| 段1 `end_action` | `…伸向右边的白瓷咖啡杯，手指明确握住杯柄…` | 没有"杯子不离开桌面"的硬约束 |
| 段2 `motion` | `只有右臂端杯和头部微微低下的动作…` | "端杯 + 低头"是全部，"喝"一个字都没有 |
| 模板嘴锁（自动追加） | `双唇自然闭合、嘴角平直、不微笑、不张嘴` | 与"喝"直接冲突 → 只贴嘴（§1.18） |

#### ④ 修复版（v2：模板一字没改，只改段级字段）

| 字段 | 新文本 |
|---|---|
| 段1 `motion` | `只有右手和右臂移动，从键盘移到杯柄并握住，上身其余部分保持稳定，人物与镜头距离不变。全程杯子不离开桌面：握住杯柄即停，不端起、不抬起、不倾斜` |
| 段1 `end_action` | `…手指明确握住杯柄，手肘抬起离开桌沿，上身微微向右前倾，视线从屏幕落到杯子上。杯子始终放在桌面，杯底不离开桌面，手臂不向上抬，绝不把杯子端起来` |
| 段2 `open_action` | `右手握着杯柄，咖啡杯静放在桌面上，杯口热气轻绕` ← 和段1 收尾是**同一个状态** |
| 段2 `motion` | `右臂把咖啡杯从桌面端起送到唇边，头部微微低下，然后头轻轻后仰、杯身倾斜，真的喝进一口：双唇含住杯沿停留约一秒，喉部有吞咽动作，随后杯身回正仍停在唇边。…全程杯子不落回桌面，喝完停在唇边等待下一段` |
| 段2 `end_action` | `右手端着咖啡杯停在唇边，刚咽下一口，双唇仍轻贴杯沿，眼睛因咖啡的香气微微眯起，神态放松满足。杯子不下落、不放回桌面` |
| 段2 `mouth` | `嘴部随喝咖啡动作自然变化：端杯时双唇轻含杯沿，吞咽自然，不夸张张嘴；表情放松` |
| 段3 | 不变：杯在唇边 → 放回桌面、杯柄归位 → 转头看屏幕、渐渐微笑 |

三段的关系变成：**握柄(杯在桌) → 端起真喝(杯在唇边) → 放下(杯回桌)**，每个切分点都是可命名的静止状态。

#### ⑤ 结果对照

| 指标 | 旧版（本地 0.9MP） | 旧分镜跑云端 | v2（本地 0.3MP + 20 步） |
|---|---|---|---|
| 动作执行 | 喝 → 放 → 再喝 ✗ | 偶然一条线 ✓ | 握柄 → 端起 → 真喝 → 放下 ✓ |
| 段1 末帧锚定 MAE | 20+ | 6.73 | 9.8 |
| 接缝 1→2 / 2→3 MAE | 10.49 / 11.45 | 3.81 / 4.37 | 5.20 / 5.21（SSIM 0.997） |
| 归因 | 提示词有坑 + 模型守不住 | **提示词同样有坑，被强模型掩住了** | 两条都修 |

**这张表最重要的读法**：云端没出问题 ≠ 提示词没问题。同一份旧分镜，云端靠 Larry 蒸馏 LoRA 的服从性硬扛过去，
换分辨率/换种子/换成本地权重就翻车。**"云端正常"不能作为提示词合格的证据。**

#### ⑥ 任何分段动作戏开工前的三步自查

1. **每段 `motion` 单独读**：这句话能被"画"出来吗？`端杯 / 低头` 能，`喝 / 生气` 不能（→ §1.17 拆生理细节）。
2. **相邻两段对状态**：段N 收尾 vs 段N+1 起点，是不是同一个状态？两段都从"桌面"起手就必然重复（→ §1.16）。
3. **三段文本连读**：`motion + end_action + 模板静态锁`，有没有互相否定的句子（笑 vs 不微笑、含杯沿 vs 不张嘴）→ §1.18 段级覆盖。

#### ⑦ 验收

末帧锚定 MAE 只做初筛（≤ 10~14）。**必须每 0.6~1s 抽帧目检动作是否重复/倒退**——
本案例旧版出现过"MAE 在阈值内、动作照样演错"的情况。文件留档：
`output/coffee/sb.json`（v2 分镜）、`video_prompts_v2.json`（渲染后提示词）、`diag/`（抽帧拼图）、`seam_metrics.py`。

### 1.21 人物 / 面部：两套段落，按景别选（2026-11-04 定稿）

同一张脸，写「毛孔」还是写「骨相」，取决于脸在画面里占多大。**用错了不如不写**：

- 脸占 1/10（全身）：毛孔会被压成噪点（§1.14），写「精致 / 8K」直接蜡质（§1.10）
- 脸占 1/3（近景 / 胸像）：只写骨相，出来还是模板脸，白瞎了那点像素

两套都验证过，按景别二选一，别混。

**A · 全身景别用这版**（脸只占 ~1/10，不写毛孔）
```text
人物：中国年轻女大学生，东亚骨相，脸型偏长，颧骨略高，下颌线清晰但不锐利，面中略微平坦；内双，眼型细长，眼尾平直；鼻梁挺直但鼻头圆润；眉毛自然未修；肤色偏暖黄。
面部：表情放松，嘴角自然闭合，面部肌肉有细微的不对称，不是精修照片那种左右对称的脸；皮肤是真实的哑光质感，没有油光。
```

**B · 近景 / 胸像用这版**（这套才吃毛孔词）
```text
人物：中国年轻女大学生，东亚骨相，脸型偏长，颧骨略高，面中略微平坦，下颌线柔和；内双，眼型细长；鼻梁挺直、鼻头圆润；眉毛自然未修，眉尾有零星杂毛。
面部：近景，脸部约占画面三分之一。皮肤保留真实的毛孔与细小绒毛，鼻翼两侧能看到极细的血管走向，左颊有三四颗浅褐色小雀斑，下唇有细微干纹，额头一层很薄的油光。
焦点落在眼睛上，睫毛根根分开，虹膜有细密的放射状纹理。
```

**C · 负向补这几个词**（接在现有负向后面）
```text
磨皮、磨皮感、塑料皮肤、蜡像、过度美颜、网红脸、五官过度对称、光滑无纹理、8K 锐化
```
⚠️ 只在 CFG > 1 的模型上有效。ZIT / Krea2 是 CFG=1 的蒸馏模型，负向完全无效（§1.9）。

**三条铁律**

1. **别写「精致无瑕 / 完美对称 / 光滑细腻 / 8K」**——这四个必出蜡质，
   而且会把构图推成远景时尚大片。**假的是措辞，不是构图，加近景也救不回来。**
2. **皮肤词别带「红」**——「血丝 / 泛红 / 微红」→ 两颊出粉斑（§1.3）。
   要写血管就写「极细的血管走向」。
3. **骨相 + 眼型 + 肤色能治网红脸**：脸型偏长 / 圆、颧骨略高、面中平坦、内双细长眼、眉毛未修
   ——这一串比堆「高级脸、气质、氛围感」有效得多。
   另外**必须显式写「中国女性 / 东亚」**，不写默认画成欧洲面孔（§2.6 实测过）。

**参数比提示词更能拖后腿**

| 动作 | 效果 | 本机核对 |
|---|---|---|
| 画布 1.0MP → **1.6~2.0MP** | 脸的像素直接涨 30~40%，最便宜的一档 | ✅ 与 §5.11 同结论 |
| bypass 蒸馏 LoRA，回官方 **20 步 / CFG 2.5** | 细节真正回来，慢但顶 | ⚠️ **不是 25 步 / CFG 3.0**（那是 MOSS 的参数，串了） |
| 把 Lightning 4 步加到 8 步 | ❌ **反而更差** | §5.8 实测：4 步 34.2 锐度最优，加步只有代价 |
| 全身出图后对脸**局部重绘** | 全身构图 + 近景脸两全 | 最推荐（impact-pack / inpaint-cropandstitch） |

**画布档位实测（2026-11-04，Qwen2.1 / 20 步 / CFG2.5 / 无 LoRA / 同一段近景提示词 / 同 seed）**

| 画布 | 像素 | 耗时 | 脸的表现 |
|---|---|---|---|
| 864×1152 | 1.00 MP | 34s | 皮肤偏光滑，毛孔成片状，眉毛是色块 |
| **1104×1472** | **1.63 MP** | **55s** | **额头出现细密颗粒，眉毛有发丝，性价比最高** |
| 1232×1648 | 2.03 MP | 72s | 纹理最实，皮沟与高光层次清楚，印刷级 |

要么老老实实 CFG 1.0 少写负向，要么 bypass LoRA 用官方 20 步。

### 1.22 关键帧转头：要几何描述，且收尾绝不回正（2026-11-05，shopping 10 段实测）

首尾帧头朝向几乎一样 → 视频里人脸全程一个方向（假），且 H3 差异量不够插值就"加戏"
（推镜/重绘脸，§7.6）。shopping 10 段里 8 段中招，两类根因：

**① 编辑模型对转头词执行打骨折**——写"头部向左转约45度"出来只有 ~20°。
要写**可验证的几何描述**，让"没转到"在画面里一眼可见：

```text
坏：头部向左转约45度，看向橱窗
好：头部明显向左转，转到鼻尖几乎指向左肩方向、能看到完整的右侧脸颊和右耳的程度
好：头部明显低下，下巴收向锁骨，视线垂直落在手中的杯子上
好：头部向右后方转动接近正对镜头，能看到完整的正脸而不是侧脸
```

角度数字可以保留，但必须配上"鼻尖指向 X / 能看到 Y 脸颊和 Z 耳"这种画面可查的描述。

**② 分镜设计错误：收尾"转回平视/回正"= 绕圈回原点**——s08/s09/s05 的尾帧写成
"转回平视前方""放下回正微笑"，首尾帧当然一样。**收尾必须停在转头的位置上**：
beats 是"平视 → 转头看 X"，尾帧姿态=转头到位停住，不做第三拍回正。

**嘴部联动**：尾帧含吸管/张嘴时，删掉提示词里的「双唇自然闭合」句，别让两条指令打架。

**转头幅度 20° 是最危险档**——看着有差异，实际不够 H3 插值 6 秒。要么大角度
（40°+ 或明确低头/仰头），要么换手臂大位移动作。

### 1.23 首尾帧装束一致性：给首帧当参考 + 把细节逐项点名（2026-11-05 用户要求）

**现象**：同一段的首尾帧，衣服袖子长短不一样（首帧袖口停在手腕，尾帧抬臂后荷叶边
滑到小臂）；偶发衣摆长度、配饰增减。

**帧证据**：shopping 段3 首帧（袖口在手腕）vs 尾帧（袖口滑到小臂中段）——同一套
"浅蓝雪纺长袖外搭 + 白色蕾丝吊带"，只有袖口位置变了。

**根因三条**：
1. **尾帧的图2 给的是"全片场景锚"（第 1 段首帧），不是本段首帧**。模型参考的是一张
   隔着好几个动作/角度的图，服装细节只能自己重新编一次；
2. 提示词只写"服装与图1完全一致"，**没有点名袖长、袖口结构、衣摆位置、配饰**——
   模型把这些当可自由发挥项；
3. **抬手臂时没有物理描述**，模型让袖子固定在躯干上，手臂一动袖口就滑。

**规避写法（已写进 pipeline 模板，2026-11-05）**：
1. 尾帧的图2 = **本段首帧**（`cmd_frames` 已改；本段首帧本身是在场景锚上生成的，
   场景连续性不丢）；
2. 分镜顶层写 `wardrobe_items`，**逐项点名**：
   ```text
   浅蓝色雪纺长袖外搭（肩部系带蝴蝶结、袖口喇叭状荷叶边、袖长到手腕）、
   白色蕾丝边吊带背心、胸前白色细系带、浅蓝色高腰牛仔短裤（裤脚毛边）、
   金色圆形小牌项链、白色厚底球鞋
   ```
3. 加**物理句**："抬手臂时袖口跟着手腕一起移动、始终停在手腕处，不许滑落到小臂或手肘"，
   比"袖长一致"有效；
4. 手写的 `prompt_first` / `prompt_last` 也会自动追加这段"逐项照抄"尾巴（`_consistency_tail`），
   自定义提示词不再绕过规则；
5. 视频阶段（H3）同样加一条"服装从第一帧到最后一帧不许变：{wardrobe_items}"。

**实测边界（2026-11-05，段3 两轮冒烟）**：
- ✅ 款式、袖型、蝴蝶结、项链、短裤腰头、背景店铺全部跨帧一致（改之前会重新编一套）；
- ❌ **"抬臂到胸前"这个动作下，长袖袖口必然上移**——首帧袖口在手腕，尾帧抬臂后
  荷叶边停在小臂中段。加"袖口跟着手腕走/停在手腕处"两轮都不能改；
- **结论：这是动作与服装的几何冲突，不是提示词问题**。给长袖（尤其泡泡袖/喇叭袖）
  设计动作时，不要用"双手抬到胸前/捧东西/整理胸前"这类，改成**指向橱窗、扶玻璃边框、
  整理耳侧头发、双手垂在身侧**；确实需要抬臂就认袖口会上移，别指望文字压住。

### 1.24 提示词必须属于本项目，不许照抄（2026-11-05 用户定）

**用户原话**：「你每个场景提示词要符合主参考图或者场景要求，不要照抄」。

**症状**：逛街分镜的下半截长出咖啡桌、傍晚的片子被写成白昼、人物的白色上衣在各段
描述不一。查下来全是同一个病：**模板/上一条分镜里的具体场景词被整句复制过来**。

**根因**：模板里写死了场景名词。历史残留四处（2026-11-05 已全清）：
`画面下方入画一部分桌面`、`浅灰色墙面 / 柔和的室内自然光`、`白色背心保持纯白`、
`保持白昼自然光`，以及扩图提示词里那句 `画面下方继续是原木色桌面和浅灰色墙面`——
最后这条最毒：每个项目扩 9:16 时都会补一张咖啡桌。

**写法规避**：
1. 模板里**零具体名词**；场景/服装一律走字段：`shot`（场景）、`scene_text`（无锚时的搭景）、
   `outpaint_scene`（扩图补什么）、`wardrobe` / `wardrobe_items`（服装逐项）；
2. 扩图默认只写「延续原有的地面、墙面和场景物件，光线方向/色温/时间感与原图一致」；
3. 光线句改成「白昼还是白昼、傍晚还是傍晚」，不要默认白昼；
4. `check` 新增 lint：提示词里出现分镜语料里没有的景物词（原木色桌面/浅灰色墙面/白色背心/
   室内自然光/白昼自然光/咖啡/水壶/沙发/床/键盘/橱窗/步行街）→ 直接报「疑似照抄了别的项目」；
5. 语料只统计 `prompt_*` 之外的字段——否则抄来的词会自我认证、永远查不出来（第一版就踩了）。

**新项目开工顺序**：主参考图 → 写 `shot` + `wardrobe_items`（+ `scene_text`/`outpaint_scene`）
→ `check` 过一遍 lint → 再出帧。

### 1.25 姿势稳定性：自由度守恒（2026-11-06，MOSS 四组×3 seed 实测）

**现象**：同一个提示词连着出图，换 seed 姿势就变——手一会儿在身前一会儿在身后、
身体一会儿纯侧一会儿 45°、人物在画面里的大小位置也飘。

**帧证据**：`output/moss-pose/cmp_pose.png`，四行各 3 个 seed（25步/CFG3.0/1.5MP，
同模型同负向，只改提示词结构与档位）。组内三张的**灰度结构相关**用来量化"姿势锁得死不死"：

| 组 | 姿势段 | 灰度相关 | 肉眼结果 |
|---|---|---|---|
| A 原结构 | 情绪/状态词 + 多处互斥约束 | **0.109** | 三张都仰头侧身，但手位、侧转角度、取景各不同 |
| B 只换姿势段 | 位置 + 支撑点 + 朝向 | 0.199 | 脸统一朝向镜头，仍有一张侧转 45°（开头还留着"侧面照"） |
| D 锚点 + 清掉景别/朝向矛盾 | 同上，一处矛盾不留 | **0.448** | 三张几乎一模一样：正面站、手垂身侧、人物大小位置一致 |
| C 原结构 + **8步提速档** | 同 A | 0.226 | 三张完全一致，但**全是歪脖仰头**，画质糊 |

**根因**：姿势不是一个词，是一组自由度——`站/坐/靠`、`重心在哪只脚`、`手放哪`、
`躯干朝向`、`头转向`、`景别`。**写清楚的自由度被锁住，没写或写矛盾的自由度交给 seed**。
25 步质量档表达力强，会把这些自由度全演出来；8 步蒸馏档看着"稳"，其实是
**模式塌缩**（LoRA 把输出锁到单一姿势，C 行三张都歪脖子就是证据），不是听话。

**规避写法**（四行）：
1. 现象 → 换 seed 手位/朝向/取景漂移
2. 帧证据 → 同提示词 3 seed 拼图，组内灰度相关 < 0.2 即判不稳
3. 根因 → 情绪词不能当姿势用；每留一处矛盾就多一个自由度；8 步档的"稳"是塌缩
4. 写法 → 姿势段只写**一个动作 + 一个支撑点 + 一个朝向**，例如
   `靠墙笔直站着，双脚并拢踩在地板上，重心落在左脚，后脑轻贴墙面；双手垂在身体两侧，
   掌心贴大腿外侧；身体正面朝向镜头`。
   同时把开头的景别/机位统一：写"全身照"就别再写"近景"，写"正面拍摄"就别再写"侧面照"，
   也别在后面补"眼神看向镜头"把头拧回去。

**具体自查清单**（对照 A 的原结构，六处自由度全空/全冲突）：
- [ ] `全身照` 和 `近景` 同段 → 取景自由度
- [ ] `侧面照` + `身体正面朝向镜头` + `眼神看向镜头` → 躯干与头的两个朝向自由度
- [ ] `半后仰` + `背靠墙` + `后脑贴墙` → 上身后仰角自由度
- [ ] `双手自然下垂` + `手掌向后贴墙` → 手位自由度（互斥，模型每次挑一个）
- [ ] `神情紧张 / 身体发软` 这类状态词 → **不是姿势**，模型每次自由解释
- [ ] 完全没写脚、重心、支撑点 → 下半身自由度

**验证口径**：姿势稳定性必须**至少 3 个 seed 一起看**，单张或两张都看不出来（§1.13 同源铁律）。
补完锚点要重跑 3 seed 再判，别用一张"这次对了"就收。

**补充修正（2026-11-06 下午）**：C 组那种"稳"更准确的说法是**输出被收窄到少数几个模式**，
不是完全锁死——收窄到的那个模式往往还是错的（歪脖仰头）。把提示词清干净之后，
收窄到的模式就是对的，见 §1.26 的 Q 组（8 步档 5/5 可用）。

### 1.26 物理可达性 + 数值角度：8 步抽卡的两个真凶（2026-11-06，13 张实测）

**现象**：姿势锚点都写了，8 步加速档还是得反复抽卡，手和脖子总有一个不对。

**帧证据**：`output/moss-pose-gacha/cmp_gacha.png`，三行：
P 原结构 8 步 × 5 seed / Q 清掉物理冲突 8 步 × 5 seed / R 原结构 25 步 × 3 seed。

| 组 | 手 | 头颈 | 可用 |
|---|---|---|---|
| P 8步 原结构 | **5/5 都没画出"手掌按墙"**：全跑身前，一张折中成胸前合十 | 5/5 歪脖仰头 45–60° | **0/5** |
| Q 8步 清干净 | 5/5 双手自然垂在大腿侧，无畸形 | 5/5 下巴水平 | **5/5** |
| R 25步 原结构 | 仍在身前 | 仍仰头歪脖 | **0/3** |

**根因（四行）**
1. 现象 → 8 步档手位与脖子反复出错，必须抽卡
2. 帧证据 → P 5/5 手跑身前、5/5 歪脖；换 25 步（R）照样 0/3，说明**不是步数问题**
3. 根因 → ①**物理不可能**：`背部和后脑靠在墙上` 之后，手没有任何空间"绕到背后按在同一面墙上"，
   模型只能折中，每次折中方式不同；②**数值角度算不准**：`下颚上扬 30 度` 被放大成 45–60°
   且带歪脖，蒸馏档尤其；③ `双手下垂，高度在大腿处` 与 `手掌按墙` 是互斥指令（见 §1.25）；
   ④ **CFG 1.0 下负向完全失效**，负向里 `missing fingers / badly drawn hands` 一个字都没生效，
   手部畸形没有任何纠偏手段（§5.7）
4. 规避写法 → 写**几何与朝向**，不写度数；先检查姿势真人做不做得到；手的位置只给一个终态

**自查：写姿势前先问"真人能不能做"**
- 身体某个面已经贴住支撑物 → 手/脚就不能再"绕到那个面后面按/撑"
- 带度数（`30 度`）、带精确距离（`1 拳距离`）、带绝对高度（`高度在大腿处`）→ 模型算不准，
  换成 `下巴保持水平` / `重心落在左脚` / `双手自然垂在身体两侧` 这种相对描述
- 一个部位只给一个终态，别写"下垂"又写"按墙"
- `全身照` 别搭 `近景`（§5.12 / §5.13）

**可直接替换的姿势段**（Q 组用的，8 步档 5/5 稳定）：
```
她侧身靠着车厢的墙壁站着，背部和后脑轻轻贴着墙面，双脚并拢踩在地板上，重心落在左脚；
双手自然垂在身体两侧，掌心贴着大腿外侧，手指放松；肩膀下沉，下巴保持水平，视线看向画面外侧。
```

**"8 步必须抽卡"这个判断要修正**：Q 组证明提示词清干净后 8 步档 5/5 可用。
抽卡的锅**主要在物理冲突 + 数值角度**，档位只负责把错误放大、且让负向失效。
要画质再上一档才需要 25 步（§2.2），要"能出图"不需要。

#### 想让双手按墙：三条可达路径（2026-11-06，11 张实测）

**铁律：身体哪个面贴住墙，手就按不到那面墙。** 背和后脑贴墙之后，手没有空间绕到
同一面墙上——这是 §1.26 P 组 0/5 的全部原因。想按墙，先把墙挪到手够得着的地方。

`output/moss-hands-wall/cmp_hands.png`，8 步档各 3 seed，另有 W1 的 25 步 2 seed：

| 方案 | 几何 | 机位 | 手按墙 | 结果 |
|---|---|---|---|---|
| **W1 面朝墙，双臂前伸** | 墙在人物正面，上身前倾臀部后坐 | 侧面 | 两只手同一面墙 | **3/3** |
| **W2 背贴墙，双臂两侧展开** | 手按身体左右两侧的墙面，不是背后 | **必须正面** | 两只手 | **3/3** |
| **W3 侧身，单手按墙** | 右肩靠墙，右手按墙，左手垂下 | 侧面 | 一只手 | **3/3** |
| 原写法（背贴墙 + 手向后按墙） | 手被身体和墙夹住 | 侧面 | — | 0/5（§1.26 P 组） |

**取舍**：W1 最有张力（侧脸 + 前伸双臂 + 后坐的身体），但只给侧脸；
W2 脸最清楚、双手都张开，代价是机位必须改成正面，且"墙"变成画面两侧的墙面/门框；
W3 最像随手拍、最不容易穿模，但只有一只手按墙。

### 2.3 提示词该长什么样

它的训练数据是用 VLM 按 `caption.long` 维度打标的长复述，所以**最有效的形态是"像在复述一张已经存在的照片"的自然语言段落**，不是 tag 堆叠，更不是下命令。

七段式（本质是复现 caption 维度）：
1. 主体 + 动作（有主语有谓语）
2. 构图（景别、机位、主体占比）
3. 环境（地点、时间、前中后景）
4. 光线（方向 + 色温 + 硬软）
5. 色彩（主色 / 对比色）
6. 材质（皮肤、布料、金属、水汽）
7. 风格（介质、镜头、颗粒）

150–300 字是甜点区，超过 500 字先检查是不是在重复。

### 2.4 文字与排版（该模型最强项）

实测三轮全部零错误：

### 2.8 JSON Layout（硬控构图）

自然语言写机位约 40% 命中，写 bbox 能到 80% 以上。

**格式**
- `bbox_format: "yxyx"` → `[y_min, x_min, y_max, x_max]`
- `bbox_coord_space: "abs_centralized"` → 以画布中心为原点的绝对像素，x 向右、y 向下；
  1024×1024 画布范围 −512…+512。宽 W 高 H 的画布：常规坐标 x、y 分别减 W/2、H/2
- `label` 取 `text` / `object`（ComfyUI 的 Layout Prompt 节点还可标 `character`）
- 要渲染的文字放 `text` 字段

```json
{
  "summary": { "meta": ["poster"], "canvas": "single", "caption": "整体场景、光线与风格" },
  "items": [
    { "label": "text",   "caption": "顶部居中的深蓝大标题", "text": "EXPLORE", "bbox": [-416, -384, -288, 384] },
    { "label": "object", "caption": "下方居中的蓝色山脉插画", "bbox": [-192, -288, 384, 288] }
  ],
  "bbox_coord_space": "abs_centralized",
  "bbox_format": "yxyx"
}
```

可直接把 JSON 当 prompt 粘进去；也可用 `Create Bounding Boxes` + `MOSS-Image Layout Prompt` 节点可视化框选。
**SFT 上 JSON 布局明显比 Base 准。**

### 2.10 坑清单

- [ ] 写了"刚…/正在…"这类过程词 → 改终态
- [ ] 皮肤描述里有"血丝/泛红/红晕" → 必出腮红
- [ ] 一条 prompt 里两个场景 → 会被平均/缝合
- [ ] 同义段落写了两遍 → 结构混乱
- [ ] 机位/视线/光源方向互相冲突 → 歪脸、多余肢体
- [ ] 多人画面没写人数与各自位置 → 漏人或加手
- [ ] 中英各写一遍同一件事 → 条件互相拉扯
- [ ] 没写族裔 → 默认西方脸
- [ ] 只写"浅景深"不写焦点 → 主体虚
- [ ] 换 seed 姿势就变 → 姿势自由度没锁住，见 **§1.25**（情绪词不是姿势、每处矛盾多一个自由度、8步档的"稳"是模式塌缩）
- [ ] 写"贴墙"又写"手绕到背后按墙" → 物理不可能，模型每次折中出不同手位，见 **§1.26**
- [ ] 写"上扬 30 度 / 离墙 1 拳 / 高度在大腿处" → 数值算不准，换相对描述，见 **§1.26**

**全身人物"经常变形"的四层原因（2026-11-05 三组×3 seed 实测，`output/moss-deform/`）**

按影响从大到小排，别一上来就改提示词：

| 层 | 症状 | 处理 |
|---|---|---|
| **① 步数**（最狠） | 腿粗且比例失调、手消失在身体里、鞋糊成一坨 | 8 步 → **25 步 / CFG 3.0**，一步到位 |
| **② 画布太窄** | 比例失控、脚被裁 | 512×1440（0.74MP）→ **864×1536（1.33MP）** |
| **③ 姿势复合** | 反弓 + 扭头 → 脖子错位、多手 | 一个支撑点 + 一个朝向（§5.13） |
| **④ 提示词自相矛盾** | 脚被裁、取景漂 | 删掉与景别冲突的词（下详） |

**同提示词骨架三组对照（A 现配置 / B 只换步数画布 / C 再简化姿势）**
- A（8 步 / 512×1440）：3 个 seed **全部变形**——腿粗、脚糊成一坨、有一张手臂消失
- B（25 步 / 864×1536，姿势不变）：3 张结构都完整，只剩脚型偏糊
- C（再简化姿势）：3 张**全部可交付**，姿势也自然了

**这段提示词里的四处自伤写法**
1. `全身照…从头到脚完整入画` 和结尾的 `近景` 打架 → 模型折中，脚被裁
2. `头顶和脚底离画面边缘还留有 100 像素的宽度` ——**绝对像素值**在 512 宽的画布上占 20%，
   模型算不来，反而挤压主体。改成 `各留出一拳空间`
3. `侧面拍摄` + `视线看向镜头` —— 侧身还要正脸看镜头等于扭头 120°，
   容易出脖子错位或双下巴。二选一
4. `头部和臀部贴在墙上，腰部略微弓起` —— 反弓 + 两点贴墙是**真人做不出的姿势**，
   模型只能瞎猜骨点。改成 `背部贴着墙壁，身体微微后仰`

**脚永远画不好是正常现象**：全身像里鞋只占几十像素，"鞋型""鞋带"这类细节不要写，
写了也只会变成一坨。要脚部细节只能近景裁切或局部重绘（§1.7）。


### 2.11 Krea2 二采实测（重要：方向是反的）

工作流里的「Krea2 二采」链路：MOSS 25 步 → 解码 → 放大 1.2× → **用 qwen_image_vae 重新编码**
→ Krea2 `8步 / CFG1 / er_sde / beta / start_at_step 6 / 不加噪` → 解码。

⚠️ **技术前提**：MOSS 的 latent 是 **FLUX.2 VAE 的 128 通道**，Krea2 只吃 **16 通道**，
直接接 latent 会报 `size of tensor a (128) must match tensor b (16)`。
必须先解码成像素、再用 qwen_image_vae 编码 —— 这正是原工作流用 `VAEEncode` 的原因。

**实测结果（同 seed，单采 vs 二采）**

| | 单采 25 步 | 二采（start6，约 2 步） | 二采（start7，仅 1 步） |
|---|---|---|---|
| 分辨率 | 912×1616 | 1088×1936 | 1088×1936 |
| 耗时 | 22–28s | 38s | 34s |
| 毛孔 / 绒毛 / 雀斑 | **全在** | **全部抹平** | 仍被抹平 |
| 织物织纹 | 清晰 | 变成光滑面 | 变光滑 |
| 木纹 / 米粒颗粒 | 清晰 | 糊成一片 | — |
| 次要道具（杯壁三道指痕） | 在 | **消失了** | — |
| 整体观感 | 真实照片 | 塑料 / 磨皮 | 蜡质 |

**结论：这个二采不是"修复细节"，而是"重绘 + 磨皮"。**
Krea2 自身的先验偏"干净、光滑、讨喜"，哪怕只跑最后 1 步，也会把高频纹理洗掉。
分辨率确实涨到 1.2×，但**信息量在下降** —— 属于"放大但不增细节"。

**建议**
- 要「放大 + 保细节」→ 别用 Krea2 二采，用传统放大（Lanczos / 4x-UltraSharp）+ 可选 SeedVR2
- 要「救崩坏的构图」→ 二采可用，但要接受质感损失（它擅长把错的拉回来，不擅长保住细节）
- 要「二采但保住皮肤」→ 本轮数据不支持任何步数设置，需另找更低的 denoise 或换 VAE 重绘方案

## 3. Z-Image-Turbo

### 3.1 配置（对应 `yyy-gen (1).json`）

| 项 | 值 |
|---|---|
| 主模型 | `z_image_turbo_bf16` |
| 文本编码器 | `qwen_3_4b`（`type: lumina2`） |

| 采样 | **6 步 / CFG 1.0 / res_multistep + beta** |
| 附加 | `DiversityBoostCoreV3`（strength 2.0 / clamp 0.5 / pink / linear）**建议关掉，见 §3.5** |
| 稳态耗时 | 约 18s（912×1616，本机 8GB）；关掉 DiversityBoost 后 **14s** |

工作流结构：19 个 `CR Text` 组成提示词库 + `Image Comparer` 双栏对比 + `ImageScaleBy 0.5` 预览 +
`SeedVR2` 高清放大整组旁路 + `NexBlend Asian Face 01 ZIT` LoRA 槽（当前强度 0）。
**定位是"批量试提示词的抽卡台"。**

### 3.2 特点

- 6 步出图，大显存卡上速度优势明显（本机 8GB 受权重换入换出拖累，只快 25%）
- 生态成熟，LoRA 多
- 默认审美更讨喜：五官、构图、bokeh 更"成品"

### 3.3 坑清单

- **CFG=1，负向提示词完全无效**——出问题只能改正向或重抽。
  ⚠️ 把 CFG 调高可以让负向生效，但 ≥1.5 就开始崩色（白变黑、红变蓝），详见 §3.5。
- **会自作主张加细节**：把"披在肩头的大衣"穿成"穿在身上"、皮衣多出拉链袋、在杯壁画一张脸
- 文字偶发重复行（实测黑板菜单多出一个孤立的「36」）
- 材质偏塑料（面料光滑、皮革无纹理），光线偏平，缺少真实的逆光/直闪物理感
- 皮肤偏黄、色块不匀（像底妆浮粉）

### 3.4 追"唯美"的写法（实测：这条路它能走通，但有三笔代价）

ZIT 的皮肤本来就偏光滑，所以**往唯美推是顺水推舟**（往真实推反而逆着它的先验）。
实测两句就到顶了：柔光 + 逆光轮廓。

**配方 A｜柔光梦幻**
> 一大片柔和的白光从正面偏上笼罩下来，皮肤被光透过，像有光从里面渗出来，
> 额头、鼻尖、下唇各有一点湿润的高光。
> 背后的光把她的发丝一根根照亮，发梢泛着淡淡的金色边缘。
> 整体色调浅而暖，像清晨薄雾里的光；背景是奶油般化开的光斑。

**配方 B｜金色逆光**
> 强烈的暖金色逆光从她身后照来，在发丝、肩线和手臂边缘勾出一圈发亮的光晕，
> 空气里有细小的尘埃在光柱中浮动。
> 脸处在柔和的阴影里，但没有变脏，皮肤洁净通透，透着血色。
> 边缘有柔和的光斑和轻微眩光，画面像被阳光轻轻包裹。

**三笔代价（实测都会发生）**
1. **场景会被唯美词吃掉**：我写的"电车车厢"被替换成户外金色虚化场地。
   想保住场景，必须把场景句放在唯美句**之前**，并在唯美句里加"背景仍是车窗"这种锚点。
2. **服装结构会被改**：两次都画成露脐短款、腰封变细腰带、手套变分体臂套。
   正向锁死写法：`上衣是完整长款的白色水手服，下摆一直盖住裙腰，腰上系一圈鼓起的白色蓬松腰封`。
3. **年龄会下探**：写"二十岁"仍画出十七八岁的幼态脸。唯美词本身就在往"嫩"推。
   要成年感就必须叠骨相：`下颌线清晰、颧骨有明确转折、成年女性的骨骼感`。

### 3.5 让它"听话"的三个开关（7 组对照实测）

同一段提示词、同 seed、864×1536，只改一个旋钮。判据是三条可核对的事实：
腰腹有没有露、场景是不是车厢、脚有没有入画。

| 组 | 设置 | 服装 | 场景 | 脚 | 颜色 | 耗时 |
|---|---|---|---|---|---|---|
| ZA | CFG1.0 + DiversityBoost | 上衣短、裙侧多出白块 | ✅ 车厢 | ❌ 裁到膝 | 正常 | 18.1s |
| **ZB** | **CFG1.0，关 Boost** | **✅ 上衣盖住腰、过肘手套、腰封正确** | ✅ 车厢 | ❌ 裁到膝 | **正常** | **14.1s** |
| ZH | ZB + 景别句挪到最后 | ✅ 全对 | ✅ 车厢 | **✅ 两只红高跟完整踩在地板上** | 正常 | 18.1s |
| ZG | CFG1.2 + 负向 | ✅ 基本对 | ✅ 车厢 | ❌ 裁到膝 | 略偏暗红 | 28.2s |
| ZC | CFG1.5 + 负向 | 手套变短、腰封塌 | ✅ 车厢 | ❌ 裁到膝 | 裙变褐 | 30.1s |
| ZF | CFG1.5，无负向 | 肩部渐变黑、手套变黑 | ✅ 车厢 | ❌ 裁到膝 | **崩（蓝白/黑渐变）** | 26.2s |
| ZD | CFG2.0 6步 + 负向 | — | ✅ 车厢 | ❌ 裁到膝 | **完全负片色，不可用** | 26.2s |
| ZE | CFG2.0 10步 + 负向 | 尚可 | ✅ 车厢 | ❌ 裁到膝 | 偏色（裙泛青） | 42.3s |

**结论一：最有效的"听话开关"是关掉 DiversityBoost。**
它是往 latent 里注入 pink 噪声来增加多样性的——**多样性本身就是不听话**。
关掉后服装立刻变正确、颜色变正常，而且**快了 22%**（14.1s vs 18.1s）。没有任何理由留着它。

**结论二：CFG 千万不要调高，调高是"崩色"不是"听话"。**
ZF 是关键对照：CFG1.5 **不开负向**照样崩（肩部黑渐变、裙变蓝白）。
所以退化来自 CFG 本身，不是负向的锅。CFG1.2 勉强能用，1.5 已经不能看，2.0 直接负片色。

**结论三：景别/构图类约束必须放在提示词最后，并给一个物理锚点。**
写"从头到脚完整入画"没用（ZA/ZB 都裁到膝盖）。改成放在末尾：

> 镜头退得更远，画面下三分之一是车厢地板，她的两只红色细跟高跟鞋完整踩在地板上，
> 鞋跟和鞋尖都在画面之内，画面底部还有一节空地板。

**这一句直接生效**（ZH 两只鞋完整入画）。给"地板"这种可见的参照物，比给"全身"这种抽象景别词有效得多。

**结论四：之前"唯美词吃掉场景"的锅不在 ZIT。**
同一条提示词去掉唯美词后，7 组全部守住了车厢。**是唯美句的权重压过了场景句**，
把场景写细 + 唯美句里锚定"背景仍是车窗"就能共存。

**ZIT 的最终推荐配置：CFG1.0 / 6 步 / 关 DiversityBoost / 无负向 / 景别句放末尾 + 地板锚点。**
约 18s，服装、场景、构图三项都能守住。

### 4.2 表现

- **真实感四模型最强**：毛孔、法令纹、额纹、皮肤厚薄差异全在，完全没有美颜痕迹。
  同一句"二十七八岁"，它给的是**四十岁上下的纪实人像**——质感极真，但年龄描述不敏感。
- 静物极佳：米饭颗粒、竹筷竹节、杯壁裂纹、水汽、木纹与水渍都对。
- 文字：**标题、价格、底部小字都正确，但生僻词会写成伪汉字**。

- 会漏掉次要细节：要求"杯沿下三道指痕"，它没画。
- 时装：**四模型里最像真照片**。写字楼玻璃的反射与环境镜像正确，皮夹克有真实磨痕，
  走路中段被抓拍的姿态自然（但人物显老，四十岁上下）。
- 动态：**四模型里最弱**。跳跃提示词画成"站在地上举手"（双脚着地，完全没腾空）；
  转身甩发几乎静止（头发只是微微抬起）。→ **静态静物/人像之王，动态别用它。**

### 4.3 坑清单

- **生僻/专有名词会变伪汉字**，菜单、品牌名、人名务必逐字核对
- 年龄/外貌强度不敏感（写"二十七八岁"可能给 40 岁）
- 忽略次要道具细节
- CFG=1 → 负向提示词无效
- int8 权重 12.5GB，8GB 卡靠换入换出，但 8 步只花 24s，仍比 Qwen2.1 快一倍

### 4.4 纯文本关键帧：Krea2 t2i + 全链连续（2026-11-07 用户定，已实跑）

- **现象**：没给参考图、只有文字的分镜，用双图编辑链路（`frames`）根本跑不了
  （要 `reference_images`），且 4 段各自独立出首帧会让首尾帧断开。
- **帧证据**：`output/card-duel/k2_probe_1.png` / `k2_probe_2.png`（同 seed 812345、
  只换动作句），双人长相 / 发型 / 服装 / 左右站位 / 石台 / 浮空城 / 星空全部一致；
  `k2card_frames_sheet.png` 五格同样稳定，链式 md5 三处全相等。
- **根因**：`image_krea2_turbo_t2i_int8.json` 是纯 t2i（子图里 `EmptyLatentImage`，
  **没有任何图像输入**），做不了「拿本段首帧当参考去改尾帧」；身份一致性只能靠
  **所有帧共用一段静态锁 `t2i_base_prompt` + 同一个 seed**。段间若再各自生首帧，
  人物必然一段一个样。
- **规避写法**：① 静态锁写死人物 / 服装 / 场地 / 机位 / 画风 / 场景正面清单，
  每张都拼在动作句前面；`prompt_first` / `prompt_last` 只写这一帧的动作差异。
  ② 全片同 seed（禁 100000）。③ 段 2+ 默认 `chain:true`，首帧
  byte-for-byte 复制上段尾帧，把身份漂移压到「每条尾帧一次 t2i」。
  ④ 原生 9:16 出图，不要做 16:9→9:16 的模糊铺底适配。

**与「Krea2 动态最弱」不矛盾**：关键帧本来就是静态姿势，动作由 H3 插值；
实测 5 张帧的动作 / 光效差异清楚，且比 MOSS 宽幅图更统一。
用户工作流真实档位是 `krea2_aingmix_kroma_v10_int8_convrot`（Aingmix Kroma v1.0，
**不是**官方 turbo），`prompt_enhance=false`、`enable_lora=false`、8 步 CFG1；
`pipeline.py` 用等价精简 API 图复刻（不导入子图），832×1472 实测 18–24s/张。

**端到端实跑**（任务 `20261107_191155_08f6f0f7`，4×15s）：`t2i` 出 5 张帧约 90s，
`push/resume` 出片 12m38s，成片 `星界卡牌对决_纯文本链式_60s.mp4`
（832×1472 / 1440 帧 / 60.0s / 38.6MB）。QA **零 flagged**，4 段首尾 SSIM
0.949–0.968、static_ratio 全 0；`transition_mode=none` 硬切后，
t=15/30/45s 三个链式接缝相邻帧 MAE 仅 0.4~6.5，全片中位 3.93
（对照：4 段独立切镜版同位置峰值 65.0、段 1 还报 `last_frame_drift`）。
**结论：纯文本任务用 Krea2 t2i + 全链硬切，身份稳定性和接缝都明显优于独立切镜版。**

### 5.4 追"真实"的写法（实测：四模型里唯一能真的骗过眼睛）

Qwen 的默认脸偏"干净完美"，反而假。**往真实推要三件事：加不完美、给硬光、禁磨皮。**

**① 皮肤要写出"脏"的细节**（正面清单，任选 4–6 条）：
`能看清毛孔和细小的绒毛` / `鼻翼有一点油脂反光` / `左颊有三四颗浅褐色小雀斑` /
`唇部有清晰唇纹，唇色偏淡` / `眼下有一层很淡的青影` / `额头有细微的横向纹理` / `妆很轻`。
⚠️ 仍然不许出现带"红"字的词（§1.3）。

**② 必须明写"没有磨皮"，并且给不完美**：
`画面没有经过磨皮和锐化` / `两侧脸颊不是完全对称的，笑起来一侧比另一侧略高`。
Qwen 会真的照做——实测出现左右眼大小略有差异、笑纹只在一侧。

**③ 光要硬、要有落差，别补反光板**：
`午后的日光从车窗斜进来，落在她脸的左侧，右侧靠车厢顶灯补一点亮度，两边有真实落差，没有人给她补反光板`。
或者更狠：`侧光从四十五度打来，光线是硬的，鼻梁在脸颊上投下一道清楚的影子`。

**④ 介质词往"随手拍"靠**：
`35mm 定焦` / `高感光带来轻微噪点` / `像随手拍下的一张照片`。比"4K、锐利对焦"有效得多。

**代价：真实化的同时会牺牲"漂亮"。** 实测两张 Qwen 真实版都更像真人，但笑容偏憨、
眼下有青影、脸显 25–28 岁而非 20 岁。**"真实"和"精致好看"是对冲的，不能都要。**

**分工建议**
| 想要 | 用 | 关键句 |
|---|---|---|
| 像真人随手拍的照片 | **Qwen + §5.4** | 毛孔/雀斑/青影 + 硬侧光 + 轻微噪点 |
| 漂亮到不真实的头像 | **ZIT + §3.4** | 柔光透视 + 发丝金边 + 奶油光斑 |
| 又要真实又要好看 | Qwen 真实版打底 + 后期轻度润饰 | 别靠重绘，会洗掉纹理（见 §2.11）|

### 5.5 加速 LoRA 实测（⚠️ 两个 8 步 LoRA 已于 2026-11-03 删除，此处留档）

> **本机的 `qwen-image-2.1-turbo8-8step` 和 `p_qwen_image_2.1_8step_v0.1` 都被删除了**（进回收站）。
> 用户实际使用后判断"8 步出来的东西没法用"，不要再去找这两个文件。
> 下面的数据是当时的同 seed 对照，留着是为了说明**加速 LoRA 的取舍规律**，不是让你照着重装。
> 现在 Qwen2.1 的主力路线只有一条：**官方权重 + 20 步 / CFG 2.5**。

**当时的推荐配置**
```
LoRA : qwen-image-2.1-turbo8-8step.safetensors   强度 1.0
采样 : 8 步 / CFG 1.0 / euler + simple
补丁 : ModelSamplingFlux  max_shift 0.6935  base_shift 0.5  width/height 跟随画布
```
约 14.1s（864×1536，本机 8GB），画质与 20 步基准肉眼无差。作者明确写：**不要提高 CFG 和步数**。

**为什么必须加 ModelSamplingFlux**
不加这个补丁，8 步下画出来的上衣会变短、露出腰腹（实测）。加了之后下摆恢复正常。
它的作用是按画布尺寸复现训练时的分辨率相关噪声调度——**这是 Turbo8 最容易被忽略的一步**。

**实测对比（同 seed / 864×1536 / 同一个复杂服装提示词）**

| 方案 | 步数 / CFG | 稳态耗时 | 服装结构 | 皮肤细节 |
|---|---|---|---|---|
| 基准（无 LoRA） | 20 / 2.5 | 48.3s | ✅ | 基准 |
| **Turbo8 + MSF** | **8 / 1.0** | **14.1s** | ✅ | **≈ 基准** |
| p_qwen 8step | 8 / 1.0 | 14.1s | ✅ | ≈ 基准 |
| Viggle turbo 6step | 6 / 1.0 | 12.1s | ✅ | 略暖，接近 |
| LightX2V Lightning | 4 / 1.0 | **8.1s** | ❌ **露腰** | **偏软、有磨皮感** |

**Lightning 的取舍**：它是下载量最高的（43 万），速度最快（8.1s，比 Turbo8 快 1.7 倍），
但**皮肤纹理明显变软、上衣会被画成短款露腰**。适合抽卡试构图，不适合出成片。
（本机保留 `qwen-image-2.1-lightning-4step.safetensors`，67MB。）

**命名与来源**
- Turbo8：`chriswritescode/Turbo8-LoRA-Qwen-Image-2.1`，DMD2 v2 / step 2500，1.27GB，
  官方给了 ComfyUI 工作流，明确"227 层全部映射"，还支持编辑、RGBA 透明、原生 2K —— **已删除**
- Lightning：`lightx2v/Qwen-Image-2.1-Lightning`，DMD 4 步蒸馏，64MB，
  训练用动态指数 shift（base 0.5 / max 0.9），原始建议 sigmas `[1.0, 0.75, 0.5, 0.25]`
- 现存位置：`models/loras/Qwen-功能2.1/`（8 步的两个已移入回收站）

**⚠️ 为什么删：8 步这条路在本机的实际表现不如手册数据**
同 seed 对照时 Turbo8 确实能做到"8 步≈20 步基准"，但那是**单张静态对照**。
实际连续出图时，8 步的失败率明显更高（结构漂移、衣物改款、皮肤颗粒），
加上还要额外挂 ModelSamplingFlux 补丁、CFG 必须锁 1.0、负向失效——
**省下来的 34 秒不值得反复抽卡**。Qwen2.1 的时间应该花在 20 步上。

Viggle 的 LoRA **直接挂 `LoraLoaderModelOnly` 是能出图的**（实测 12.1s，服装结构也正常），
但官方明确说这样不对，差别是能看出来的。

**正确的连线（`custom_nodes/viggle_turbo.py` 已装好，节点名带 `Qwen-Image-2.1 Viggle Turbo` 前缀）**

```
UNETLoader ─→ Viggle Turbo LoRA (unmerged)  strength 1.0
                    ├─→ BasicGuider ← CLIPTextEncode(正向)
EmptyLatentImage ─→ Viggle Turbo Sigmas   nodes="1.0, 0.9375, 0.875, 0.75, 0.5, 0.25"
KSamplerSelect(euler) ─→ SAMPLER
RandomNoise(seed) + BasicGuider + SAMPLER + SIGMAS + 空latent
                    └─→ SamplerCustomAdvanced ─→ VAEDecode
```

三个关键点：
1. **LoRA 用 `(unmerged)` 版本，不要用 `LoraLoaderModelOnly`。**
   普通加载器会把 LoRA 合并进权重：bf16 下只保留约 70% 的更新量，**int8 下会引入约 4 倍于更新量级的噪声**
   ——本机用的正是 `qwen_image_2.1_int8_convrot`，所以这条对这里特别要紧。
2. **sigma 用 `Viggle Turbo Sigmas`，不要用 KSampler 的 simple/beta。**
   它按 latent 尺寸算分辨率相关的 shift（mu 从 0.5 到 0.9），和训练一致。
   `nodes` 那串就是 6 步的噪声节点，**只在高端增删步数**，`0.875, 0.75, 0.5, 0.25` 这四个必须保留。
3. **无 CFG、无负向**：用 `BasicGuider` + `SamplerCustomAdvanced`，走的是 CFG=1 的路径。

**实测（同 seed / 864×1536 / r128）**

| 接法 | 耗时 | 脸部颗粒噪点 |
|---|---|---|
| 基准 20 步 | 48.3s | 基准 |
| 朴素：合并 + KSampler/euler+simple | 12.1s | **脸上明显颗粒感** |
| 合并 + Viggle Sigmas + Guider | 10.1s | 好一些，仍有轻微噪点 |
| **r128 不合并 + Sigmas + Guider** | **12.1s** | **最干净，≈ 基准** |
| r256 不合并 + Sigmas + Guider | **32.2s** | 同样干净 |

**r256 在 8GB 上不能要**：每层旁路权重都要换入换出，32.2s 比 r128 慢 2.7 倍，画质没有可见提升。
官方说"r256 是完整版、建议用这个"，但那是给大显存说的；**8GB 用 r128**。

### 5.7 CFG 到底能不能抬？—— 不能，实测代价很大

**结论：所有步数蒸馏的加速模型都必须在 CFG 1.0 工作**（Turbo8 / Lightning / Viggle，以及 ZIT 的 6 步、Krea2 的 8 步）。
原因很简单：**它们训练时就没有无分类器引导**，抬 CFG 等于喂给模型一个它没见过的引导强度。

**代价一：时间接近翻倍。** CFG>1 时每步要跑两遍前向。

| | CFG 1.0 | CFG 1.5 | CFG 2.0 |
|---|---|---|---|
| Turbo8（8步） | **14.1s** | 28.1s | 26.2s |
| Lightning（4步） | **8.1s** | 12.1s | 10.4s |
| Viggle（6步） | **12.1s** | — | 20.1s |

**代价二：画面被"催熟"。** 脸部区域实测（864×1536 同 seed）：

| | 亮度 | 饱和度 | 过曝像素 | 反差 |
|---|---|---|---|---|
| 基准 20 步 CFG2.5 | 114.9 | 47.2% | 0.04% | 62.1 |
| Turbo8 CFG1.0 | 105.3 | 38.3% | 0.02% | 58.2 |
| Turbo8 CFG1.5 | 107.8 | 44.5% | 0.04% | 62.8 |
| Turbo8 CFG2.0 | 108.0 | **48.2%** | 0.05% | 64.0 |
| Lightning CFG1.0 | 140.3 | 27.3% | 0.00% | 57.4 |
| Lightning CFG2.0 | 132.8 | 38.3% | 0.05% | 60.4 |
| Viggle 无 CFG | 113.4 | 36.3% | 0.01% | 59.3 |
| Viggle CFG2.0 | 124.4 | 41.2% | 0.03% | 63.0 |

规律一致：**饱和度 +10 个点、反差 +4~6、过曝像素约 2.5 倍**。画面变浓、变硬、白衣服更容易发飘。

**代价三：负向换不回来。** 我试过在 Turbo8 CFG2.0 下用针对性负向
（`short crop top, exposed midriff, bare belly`）去纠正结构，**看不到可见改善**。
所以"抬 CFG 把负向提示词换回来"这条路，在蒸馏模型上不成立。

**唯一值得用 CFG>1 的场景**：嫌加速版偏灰、想要 20 步基准那种浓郁度。
Turbo8 CFG2.0 的饱和度 48.2% 和基准的 47.2% 基本持平——但那要多花一倍时间，
还不如直接用 20 步基准。

**要负向、要强遵循，就去用非蒸馏的 20 步 base；加速档就老老实实 CFG 1。**

#### 反向陷阱：摘掉加速 LoRA 之后，CFG 必须改回 2.5

**这是最容易犯的错**：同一条工作流里，4 步 LoRA 用 `CFG 1` 是对的，
但你把 LoRA 旁路、步数改成 20，**却忘了把 CFG 从 1 改回 2.5** —— 结果就是"官方模型 20 步反而更差"。

原因：`CFG = 1` 意味着 **无分类器引导，负向提示词完全没参与计算**。
你负向里写的 `artifacts, low quality, blurry, bad anatomy` 在 CFG 1 下一个字都没生效；
模型只是安安静静地把条件分支推完，画面偏平、偏灰、细节发软、指令遵循变弱。

**实测（同 seed / 928×1664 / euler + simple / 20 步 / 无 LoRA，只改 CFG）**

| CFG | 耗时 | 亮度 | 饱和度 | 锐度 | 噪点 | 反差 | 观感 |
|---|---|---|---|---|---|---|---|
| **1.0** | 54s | 114.8 | 13.7 | 31.8 | 0.67 | 63.0 | 偏亮偏平，负向全失效 |
| **2.5（官方）** | 102s | 96.0 | 14.2 | 17.8 | 0.50 | 62.0 | **最自然，层次最好** |
| 3.5 | 114s | 74.3 | 18.8 | 9.0 | 0.32 | 58.8 | 变暗变硬，脸开始发愣 |
| 4.5 | 114s | 67.7 | 21.5 | 8.3 | 0.35 | **35.6** | **画面崩**：边缘出现橙红色噪点污染 |

**要点**

- **2.5 是甜点**，官方默认档就在这
- **3.5 以上开始劣化**，4.5 直接崩溃（反差从 60 掉到 35.6，橙红噪斑）
- **时间**：CFG>1 每步跑两遍，20 步 CFG2.5 在 8GB 卡上约 **100s**（CFG1 只要 54s）——
  省下的时间换来的是"负向失效 + 画面发平"，不划算

**两档参数必须整套换，不能只改一半：**

| 档位 | LoRA | 步数 | CFG | 采样器 | 耗时 |
|---|---|---|---|---|---|
| 极速 | `lightning-4step` 1.0（建议 0.85） | **4** | **1.0** | euler + simple | 8–14s |
| 质量 | **旁路（不挂）** | **20** | **2.5** | euler + simple | ~100s |

**口诀：挂 LoRA → CFG 1；摘 LoRA → CFG 2.5。中间地带（比如挂 LoRA 却给 CFG 2.0）两头不讨好。**

### 5.8 步数超过训练点，会不会更好？—— 不会，只有代价

常见想法：4 步蒸馏模型给 8 步，是不是等于"多跑几步更精细"？**实测不会。**
同 seed / 同提示词 / 同画布 / CFG1 / euler+simple，只改步数：

| 配置 | 步数 | 耗时 | 全图亮度 | 锐度 | 噪点 | 反差 |
|---|---|---|---|---|---|---|
| 基准（无 LoRA） | 20 | 48.3s | 150.6 | 25.6 | 0.30 | 63.7 |
| **Lightning** | **4（训练点）** | **8.1s** | **115.8** | 34.2 | **0.44** | **61.1** |
| Lightning | 6 | 10.1s | 111.6 | 35.4 | 0.47 | 59.2 |
| Lightning | 8 | 12.1s | 107.0 | 37.6 | 0.50 | 57.3 |
| Lightning | 10 | 14.2s | 105.4 | 38.3 | 0.52 | 56.6 |
| Lightning | 12 | 16.1s | **103.1** | 38.1 | **0.54** | **55.6** |
| **Turbo8** | **8（训练点）** | **14.1s** | 120.8 | 41.7 | **0.57** | 54.8 |
| Turbo8 | 12 | 18.1s | 118.6 | 53.7 | 0.62 | 55.2 |
| Turbo8 | 16 | 22.1s | 117.6 | **60.1** | **0.62** | 56.7 |

**Lightning 4→12 步：亮度 -12.7、反差 -5.5、噪点 +23%，饱和几乎不变。**
画面一路变暗、变平、变粗，**没有任何一项指标变好**。多花 8 秒纯粹是浪费。

**Turbo8 8→16 步：锐度 +44%，但噪点也 +9%、亮度 -3。**
这不是"细节变多"，是**对比度和颗粒一起被推高**——100% 裁切下发丝更"硬"、皮肤斑点更明显，
属于过锐化，不是分辨率或结构上的增益。而且时间从 14.1s 涨到 22.1s。

**为什么不会更好。**
蒸馏 LoRA 学的是"在训练时那 N 个 sigma 点上，做一次大幅度的去噪跳跃"。
KSampler 的 `simple` 调度是**按步数在 sigma 空间等间隔切片**：

- 4 步的切片点 = 8 步切片点里的第 0/2/4/6 个
- 也就是说 **8 步有半数 sigma 点是模型训练时从没见过的**

模型被要求在陌生的中间状态上做小步更新，它只能把画面往均值方向收敛 ——
表现就是**变暗、变平、颗粒增多**，正是上表的数据。

**结论（可直接照做）**

| 想更快 | 想更清晰 |
|---|---|
| 就用训练点步数，别加 | 换更强的模型，别给同一个小 LoRA 加步数 |

具体到这次的四个选择，**同样 12~14 秒**：

| 方案 | 耗时 | 锐度 | 结论 |
|---|---|---|---|
| Lightning 8 步 | 12.1s | 37.6 | 加步不加质，不如换 |
| **Turbo8 8 步** | **14.1s** | **41.7** | **多 2 秒，全面更好，选它** |

**这是本节最实用的一条：需要"再多一点质量"时，不要给 Lightning 加步数，直接换 Turbo8。**

### 5.9 bf16 值不值得下？—— 8GB 能跑，但没有理由跑

> **该权重已于 2026-11-03 移入回收站（可还原）。以下实测数据保留备查，
> 也适用于判断其它模型的 bf16 vs int8_convrot 取舍。**

官方 fp16/bf16 单文件 `qwen_image_2.1_bf16.safetensors` = **13.25 GB**（int8_convrot 只有 6.76 GB）。
2026-11-03 实下实跑（同 seed / 同提示词 / 20 步 / CFG2.5 / 864×1536 / 文本编码器沿用 int8）：

| | 体积 | 耗时 | 峰值内存 | 系统总占用 |
|---|---|---|---|---|
| `int8_convrot` | 6.76 GB | **48.3s** | — | — |
| `bf16` | 13.25 GB | **90.5s** | ComfyUI 10.05 GB | 19.8 / 23.7 GB |

**结论一：8 GB 显存能跑，靠的是分块换入换出。**
ComfyUI 进程峰值 10.05 GB（不是 13.25 GB，说明是分块加载），系统总占用 19.8 GB，
**跑完只剩 4.3 GB 余量**——能跑，但同一时间别开别的吃内存的东西，否则会掉进页面文件。

**结论二：慢 1.87 倍（48.3s → 90.5s），画质几乎没有变化。**

| | 亮度 | 饱和度 | 锐度 | 噪点 | 反差 |
|---|---|---|---|---|---|
| int8_convrot | 150.6 | 28.1 | 25.6 | 0.30 | 63.7 |
| bf16 | 150.8 | 27.9 | **27.1** | 0.31 | 63.7 |

**整张图平均像素差异只有 3.9/255（1.5%）**，而且几乎全部来自构图微移，不是细节差异。
100% 裁切对比：毛孔、睫毛、发丝、金冠的金属边缘，两张分不出来。

不是"bf16 不行"，而是 **`int8_convrot` 这个量化做得太好**（convrot = 旋转量化，
对权重分布做了旋转再量化，精度损失极小）。这条同样适用于 Krea2 的 int8_convrot 版本。

**什么时候才需要 bf16：**
- 要**训练 LoRA**（int8 不能反传，必须 bf16 或 fp8 基座）
- 要接 ControlNet / 需要全精度权重合并的工具链
- 显存 ≥ 24 GB，bf16 能整块常驻、速度不被换页拖慢

**日常出图：留在 int8_convrot，快一倍，看不出差别。**

### 5.10 4 步 LoRA 出图"皮肤很多纹路/颗粒"—— 是提示词写的汗，不是采样器坏了

**现象**：接 `lightning-4step` 跑 4 步，皮肤（肩、颈、手臂、腿）上密布细碎亮点，
像撒了一层盐粒、或者砂纸一样的颗粒感，100% 放大尤其明显。

**归因实测（同 seed / 同提示词 / LoRA 1.0 / CFG1 / 928×1664）**

| 变量 | 斑点密度‰（全图局部锐利亮点占比） | 结论 |
|---|---|---|
| 提示词不写汗 | **4.91** | 基准，皮肤干净 |
| 只写一次"薄汗" | 8.32 | 已翻倍 |
| 汗/湿/湿发写 4 处 | **8.11 ~ 8.69** | 皮肤变成密布小水珠 |

**① 主因是提示词里"汗"的密度，不是模型坏了。**
实测把「薄汗」「出汗的脖颈」「湿发」「发丝被汗浸湿」这类词堆到 3~4 处，
模型会**逐一执行**，皮肤上就真的画满细密水珠；这些水珠在 4 步下没有被平滑掉，
就变成了密集的亮点颗粒。**只写一次"薄汗"时斑点密度已经翻倍，写四处最重。**

**② `res_multistep` 比 `euler` 更"硬"。** Lightning 官方给的是 euler：

| 采样器 | 斑点密度‰ |
|---|---|
| res_multistep（多数工作流默认） | 8.11 |
| **euler** | **7.05** |

差约 13%，肉眼可见。**4 步蒸馏 LoRA 就用 euler + simple，别留 res_multistep。**

**③ 加步数不能解决。** 4 步 → 8 步：res_multistep 8.11→8.69、euler 7.05→7.18，
**颗粒反而略增**。所以别指望"多跑几步就干净了"（与 §5.8 的结论一致）。

**④ 画布越大，颗粒越明显。** 同比例 9:16，同提示词、euler 4 步：

| 画布 | 像素 | 耗时 | 皮肤 |
|---|---|---|---|
| 704×1264 | 0.89 MP | 4.2s | 相对平滑，水光连贯 |
| 928×1664 | 1.54 MP | 8.0s | 开始出现细密颗粒 |
| 1152×2064 | 2.38 MP | 12.0s | 颗粒最密，细节开始糊 |

**4 步给不了大画布需要的收敛量**，像素越多越撑不住。

**⑤ 降 LoRA 强度有效。** euler 4 步下：

| LoRA 强度 | 皮肤 |
|---|---|
| 1.0 | 颗粒明显 |
| **0.85** | **明显减少，水光变连贯** |
| 0.70 | 更少，但画面开始发软、风格偏移 |

**怎么改（按优先级）**

1. **汗只写一次，而且换写法**：
   - 别写：`布满细密的汗珠`、`皮肤表面泛着汗水的油亮光泽`、`湿发黏在出汗的脖颈`
   - 改成：`皮肤表面有一层薄薄的水光`（一个"面"，不是无数"点"）
   - 这是最关键的一条，改完颗粒直接少一半
2. **采样器换 euler**，scheduler 保持 simple
3. **LoRA 强度降到 0.85**
4. **画布压到 1.5 MP 以内**（9:16 用 864×1536 或 928×1664 就到顶）
5. 定稿要更大尺寸时，先小图出好，再用放大工具（不要靠 4 步直接跑 2 MP 以上）

**一句话：4 步 LoRA 把"描述"执行得非常字面，你写多少汗，它就画多少水珠。
写"水光"是面，写"汗珠"是点——点会被画成噪点。**

#### 编辑模式（双参考出帧）的斑点渲染——种子二值触发，五个常规嫌疑全部排除（2026-11-04 取证）

h3-long-video 帧生成（TextEncodeQwenImage21 双参考，768×1376）出现的"锐度异常"实为
**斑点渲染模式**：整幅画面布满中频深色斑（皮肤、头发、墙面全有），强梯度像素占比 37.7%
（干净帧 8.5%），亮度 +5、饱和度 +5.5。与 §5.10 的"汗"颗粒无关（提示词无汗词）。

**取证结论（同分镜同提示词，存档 15 张逐一测量）**
- **种子二值触发**：同种子逐像素复现（两份存档一致），seed+1 干净；本段触发率约 8/15。
- **斑点分布由条件决定、不由种子决定**：不同种子的两张坏帧，斑点空间相关 **0.973**；
  坏帧 vs 好帧仅 0.035。即"画不画"看种子，"画在哪"看条件。
- **已逐一排除**：热气/内容（带热气的场景锚脸部 Lap 152 干净）、CFG（1.0→493 / 2.5→561 都坏）、
  提示词措辞（"自然的皮肤纹理"改成"干净通透"→678）、参考图像素噪声（降噪参考→683）、
  int8 量化（§5.9 bf16 对照仅 1.5% 差）、步数与 LoRA（4/6/20 步、base/L4/V6 都能中招）。
- 频谱无 8/16px 周期峰 → 不是 latent 网格编解码伪影。

**实操**：不要试图用提示词/CFG/步数救——全被实验否掉。
唯一可靠修法是**脸部 Laplacian 闸门（>380 判坏）+ 种子 +1 重出**，
h3-long-video 的 pipeline 已内置，实测重试一次必干净。

**【后续修正（同日更晚）——第六个嫌疑人才是真凶：场景锚（图2）的细节强度】**
用户指出"这张图当第二参考图会有问题"，追查证实：
- **斑点分布与场景锚自身的高频纹理空间相关 0.950-0.956**（与人物参考图仅 0.051）——
  坏帧的斑点就是**锚图的微纹理被逐像素复刻放大**。
- **去局部缺陷无效**：inpaint 掉锚上的畸形脚（同坏种子 493→669）、再去热气（→685），
  照样坏——脚不是开关，但坏帧会把畸形脚**放大复刻**（脚趾结构更恐怖）。
- **剂量关系（同坏种子 100000，只改锚图）**：

  | 锚图处理 | 锚自身 Lap | 生成帧脸部 Lap | 结果 |
  |---|---|---|---|
  | 原锚 | 132 | 493 | 坏 |
  | 轻降噪 NLM(h=6) | 73 | 480 | 坏 |
  | 0.7× 往返 | 28 | 473 | 坏 |
  | **0.5× 往返+Gauss0.8** | **8** | **262** | **干净** |

  阈值效应明显：锚图细节压到极低才脱离复刻模式，但**软化只救脸不救全身**
  （软锚版脸干净、四肢仍斑驳、畸形脚仍被复刻）。
- **治本 = 换干净的场景锚**：锚是 AI 生成的，自带微纹理 + 畸形（脚、热气）。
  重出段1首帧并在提示词里加约束（"桌板在画面下缘完整收尾，桌下不可见，
  不出现脚或腿；杯口无热气"），3 个种子全中。换锚后**同一 pipeline 六张帧
  首次全部一次过**（脸 Lap 157-312，全图高频 6.9-7.3%），零重试。

**最终修法（三层）**：
1. 场景锚必须干净：生成锚的提示词带"桌下不可见/无热气"类约束，人工确认无畸形解剖；
2. 闸门升级：脸部 Lap>380 **加** 全图强梯度像素占比>20%（Sobel 模长>60），
   后者专抓"脸达标但四肢斑驳"的漏网帧（坏 37.7% vs 好 8.5%，4 倍区分度）；
3. 命中闸门 → 种子 +1 重出（已有）。
教训：**给 2.1 当第二参考图的图，质量要求比"好看"更高——它的一切像素瑕疵都会被复刻放大。**

### 5.11 分辨率越高是否越需要加步数？—— 需要，且"加分辨率"比"加步数"更划算

**先给结论：2.38 MP 这个量级不会崩（无重复纹理、无肢体错误），但画布越大确实越"吃"步数。**
而不是"分辨率高了就不行"——真正不行的是**大画布配 4 步**（见 §5.10）。

**实测（无 LoRA / CFG 2.5 / euler + simple / 同 seed；锐度为统一缩到 928×1664 后的值，可横向比较）**

| 画布 | 像素 | 步数 | 耗时 | 锐度 | 噪点 | 相对基准 |
|---|---|---|---|---|---|---|
| 928×1664 | 1.54 MP | 20 | 55s | 20.6 | 0.50 | 基准 |
| 928×1664 | 1.54 MP | 30 | 72s | **26.3** | 0.57 | +28% |
| 1152×2064 | 2.38 MP | 20 | 94s | **28.6** | 0.61 | **+39%** |
| 1152×2064 | 2.38 MP | 30 | 142s | **36.7** | 0.70 | +78% |
| 1152×2064 | 2.38 MP | 40 | 179s | 40.9 | 0.74 | +99% |

**三条读数**

**① 加分辨率比加步数更划算。**
「1152 + 20 步」（94s，锐度 28.6）**已经超过**「928 + 30 步」（72s，26.3）。
多花 22 秒换来比加 10 步更多的真实细节（下采样到同尺寸后仍然更锐，说明是真信息，不是单纯放大）。

**② 高分辨率下加步数，收益也更大。**
1152 从 20→30 步：28.6→36.7（+28%）；928 从 20→30 步：20.6→26.3（+28%）。
比例相同，但**绝对增益更大**——像素越多，越有机会把细节画出来，前提是给够步数。

**③ 30 步是甜点，40 步开始过头。**
40 步比 30 步只多 +11% 锐度，却多花 37 秒；100% 裁切下**额头皮肤开始出现颗粒、眉毛边缘变硬**，
属于过锐化。**不建议为了"更清楚"一路加到 40+。**

**④ 2.38 MP 仍然安全。** 五张都没有出现高分 DiT 常见的高分辨率失败
（重复纹理、双头、肢体增生、结构崩）。Qwen-Image-2.1 对画布的容忍度相当高，
**真正会出问题的组合是"大画布 + 4 步"**，那是步数不足，不是分辨率过高。

**推荐配置（8 GB 卡实测）**

| 用途 | 画布 | 步数 | CFG | 耗时 | 说明 |
|---|---|---|---|---|---|
| 快速看构图 | 928×1664 | 20 | 2.5 | 55s | 够用 |
| **日常正片** | **1152×2064** | **20** | **2.5** | **94s** | **性价比最高** |
| 要印刷/大幅面 | 1152×2064 | 30 | 2.5 | 142s | 细节最足 |
| 抽卡试提示词 | 864×1536 | 4 + 4步LoRA | 1.0 | 10s | 只判构图 |

**口诀：想更清楚，先加画布，再加步数；两条都加是 2.6 倍时间，收益只有 +78%。**

### 5.12 提示词写长了就"漂"——不是长度，是清单膨胀（六组对照）

**结论：Qwen2.1 不会因为写长而降低画质，它会让画面"漂"。**
文案越长，越容易把"裤子 / 腰带 / 鞋 / 地面 / 全身动作"这些**画幅装不下的东西**写进清单，
模型为了把它们都画进去只能拉远镜头，人像就从"好看的脸"变成"小人站在房间里"。

**实验设计（864×1536 / seed 20261103 / 20 步 CFG2.5 / 官方权重，产物在 `output/prompt-len/`）**
四档提示词是**严格包含关系**（L1 ⊂ L2 ⊂ L3 ⊂ L4，只往末尾追加，前面一字不改），
所以差异只可能来自"新加了什么"，不可能来自"字数变多"。

| 档 | 字数 | 耗时 | 追加的内容 | 实际景别 |
|---|---|---|---|---|
| L1 | 53 | 48.2s | 核心：人 + 米色墙 + 白亚麻衬衫 + 左前光 | **半身到腰上 ✅ 最好** |
| L2 | 172 | 50.3s | 只加五官/皮肤/85mm | **拉近成胸像特写**（清单里全是脸） |
| L3 | 372 | 46.0s | 墙面/踢脚线/左侧龟背竹/耳钉/留白 | **仍是半身 ✅**，环境全对 |
| L4 | 664 | 44.2s | 加西裤/皮带/水磨石地面/窗户/头发/指甲 | **变全身，脸只剩画面 1/6** |
| R 纯重复 | 318 | 45.1s | 把 L1 原句重复 6 遍，零新信息 | **与 53 字几乎一模一样** |
| L4 删下装+地面 | 607 | 46.3s | 只删两处：西裤皮带、水磨石 | **回到大半身**，裤子和地面消失 |
| L4 末尾加"只到腰部" | 686 | 44.6s | 末尾补"这是半身人像，不要画全身" | **仍然全身，补话完全无效** |

**五条读数**

**① 长度本身零成本。** 318 字纯重复和 53 字出图基本一致，耗时也一样（45.1 vs 48.2s）。
所以"写长了就糊""token 超了被截断"这两个说法都不成立——ComfyUI 里 `max_length` 是 9.99e7，不截断。

**② 变丑的机制是"取景被迫扩大"，不是画质下降。**
L4 的 100% 裁切拿出来看，皮肤的颗粒、睫毛的分层、衬衫的织法都比 L1 更细；
问题是脸只占画面 1/6，人像的"好看"直接掉档。**它画得更好，但你不想看小脸。**

**③ 决定景别的是"清单里有没有下半身和地面"，不是字数。**
把 L4 里的"西裤 + 皮带"和"水磨石地面"两句删掉（664→607 字），景别立刻从全身回到大半身，
而其余 600 字（窗户、纱帘、头发、指甲、色彩参考）全部保留。**删两句比加一句管用。**

**④ 末尾补一句否定救不回来。**
在 664 字后面加"这是半身人像，画面只到腰部，不要画全身"（686 字），结果还是全身。
它读的是清单，清单里有西裤就必须画；而"不要画全身"是一句指令，两种语言不在一层——
这也是为什么**"别写什么"永远不如"删掉什么"**。

**⑤ 只堆脸也会漂，方向相反。**
L2 只加了五官和皮肤（172 字），镜头立刻推成胸像特写。
清单里全是脸 → 模型把画面全给脸。**所以"漂"是可预测的：你写的内容重心在哪，镜头就跟到哪。**

**操作规则（Qwen2.1 专用）**

| 想要 | 就写 | 千万别写 |
|---|---|---|
| 半身人像（最稳） | 墙面、背景植物上半部、窗光、衬衫织法、耳饰、表情 | 裤子、腰带、鞋、地面、脚、走的动作 |
| 全身人像 | 下装 + 鞋 + 地面 + `从头到脚完整入画`（放第一句） | 毛孔、睫毛根根分明（会把镜头推回近景） |
| 要让画面丰富又不掉脸 | 环境只写**这个景别里能看见的部分**：墙、背景家具上半、窗外虚焦 | 想同时写清全屋陈设，那只能接受取景变宽 |

**字数区间：150–350 字（约 8–15 条独立信息）最稳。**
超过 400 字先自查一遍——**是不是写了画面里本来就不该出现的东西**，而不是急着删形容词。
如果删完还剩很多，说明这条 prompt 其实想说的是两张图，拆成两条跑。

### 5.13 "矛盾"和"留空"分别会怎样（四组对照，720×1800 / 20 步 CFG2.5）

写完长提示词后，画面"不对劲"通常是三种病之一，表现完全不同，别混着治。

| 组 | 提示词做法 | 结果 |
|---|---|---|
| C1 基准 | 半身 + 坐在床边 + 双手撑在身后 | **完全照做**，构图姿态都对 |
| C2 留空 | 只写"半身人像"，**不写姿势** | 退成**胸像**，手不见了，姿态由模型自由发挥 |
| C3 景别冲突 | 要"半身"，同时又写身高/长腿/高跟鞋 | **拉成全身**；鞋还画成了一双（原句是"一只斜落在床脚"） |
| C4 姿态矛盾 | 同时写"站在床边"和"斜坐在床沿" | 模型**自己折中**：坐在地上，姿态含糊，腿的位置乱 |

**三条读数**

**① 矛盾不会把画面画畸形，它会让模型"折中"。**
C4 没有多手多脚，也没有崩脸——它只是把两个姿势各取一半，出来一个"既没站也没坐"的含糊姿态，
并且构图从半身漂到七分身。**矛盾伤的是"可控性"，不是"画质"。**

**② 留空比矛盾更糟。**
C2 只写了景别，结果手被裁出画外、身体位置不明，等于把构图交给模型掷骰子。
**一帧是静止的，姿势必须写死：一个动作 + 一个支撑点**（`坐在床边，双手撑在身后的床沿`）。

**③ 景别冲突只损失构图，不损失画质。**
C3 的脸和皮肤都很干净，问题只是"我要半身它给了全身"。
这和 §5.12 的清单膨胀是同一个病，治法也一样：**删掉画面外的身体部位**。

**④ 步数会把矛盾藏起来。**
4 步的出图整体发糊，C3/C4 这种构图漂移在糊图里根本看不出来，容易被当成"模型就这水平"。
**把步数补到 20 之后，提示词里的矛盾才第一次显形**——所以先修配置，再看提示词，顺序别反。

**姿势段的写法模板**

1. **位置**：她在哪（`站在窗边`、`坐在床沿`、`靠在墙上`）
2. **支撑点**：身体重量压在什么上（`右手撑在床沿`、`后背贴着墙面`）
3. **朝向**：身体相对镜头（`身体微侧，脸转向镜头`）
4. **一条**情绪，不要四条近义词（§1.12 ④）

| 本地 0.9MP + 6 步 | 8.2~8.5 | 19.7~85.9 | 1~2s 后换房间/站起来 |
| 本地 0.9MP + 20 步 | 8.4 | 92.9（两次都漂） | 变窗景、杯子不落桌 |
| 云端 416×736 + 8 步（`runninghub.megapixels=0.3`） | 3.7 | 8.7 | 稳，**1.9 分钟/6s 段**，锐度 43.3（放大 832 后） |
| 云端 704×1280 + 8 步 | 3.1~3.6 | 5.9~7.3 | 稳，锐度 80 |

> 0.2 / 0.3 / 0.4 三档是同种子（500531）、同首尾帧、同提示词的严格 A/B（2026-11-04，段3）。
> **0.3MP 是本地权重的甜点，不是"越低越锚得稳"**——0.2 锚定和锐度同时变差（原生 336×592 放大到 832×1472 是 2.5×），
> 0.4 锐度最高但动作多演了一口。锚定与分辨率的真实关系是一个峰，不是单调线。

**结论：本地升分辨率会换来"重绘背景"的倾向，锚定反而变差。** 要稳就 0.3MP+20 步；
要清晰就得接受漂移风险，或改走云端。云端稳的根因是 Larry 蒸馏 LoRA 强化了指令服从，不是分辨率。

### 7.5 段间接缝：末帧继承 + 0.25s 叠化

- 下一段首帧 = 上一段**实际末帧**（`adopt`），不是原关键帧；跨段硬切 MAE 从 10.49 降到 2.5~3.8；
- 接缝仍允许 0.25s 叠化（`join_dissolve_seconds: 0.25`）；**0.4s 在姿势差大时会出双影**；
- `adopt` 必须 `--no-normalize`：`normalize_916` 会把 704×1280 裁掉顶部 28px，接缝 MAE 反升到 12。

### 7.9 加速 LoRA 摘除对照（2026-11-05，段2 橱窗俯身 5s）

> ⚠️ **2026-11-05 08:50 追加**：本节所有数据都是在**身份锚接错人**的状态下测的（§7.11），
> 结论「脸漂与加速 LoRA 无关」方向仍成立，但**具体数值要打折**，等修正后重测再定稿。

**现象**：加速档（TaoMate-H3-3step，4 步一采 + 2 步二采）出的段视频 identity 相似度 0.109~0.305 全不过闸（0.45），怀疑加速 LoRA 拉低保真。

**对照实验**：`config.json` 里 `lora_strength: 1.0 → 0.0`（图结构不动），段 2 改 20 步单采、0.3MP，同首尾帧跑 3 个种子。

| 配置 | identity（3 seed） | 单次耗时 | 判定 |
|---|---|---|---|
| 加速 LoRA，4+2 步二采 | 0.109 / 0.220 / **0.305** | ~2.3 min | FAIL 但最好 0.305 |
| **无 LoRA，20 步单采** | 0.258 / 0.215 / 0.120 | ~3.7 min | FAIL，三 seed 均值更差 |

**根因**：脸漂不是采样步数/加速 LoRA 的锅——本地 H3 插值阶段本来就会重绘脸，去不去 LoRA 都在漂；去掉 LoRA 反而少了蒸馏档对构图的服从性，脸漂得更随机。

**结论（已入档）**：
- **本地出视频保持加速档 4+2**，摘 LoRA 是负收益（更慢 + 更差）；
- identity 闸门（0.45）在本地 0.3MP 下本来就过不了，别再往采样参数上使劲，出路只有云端（权重服从强，0.3MP 锐度 80 vs 本地 30~36）或事后换脸；
- 复现开关：repo `config.json` 的 `lora_strength`（0 = 摘加速，Director 每次执行都热读，不用重启）。

### 7.10 单段 15 秒实测（2026-11-05，本地 4+2 步 / 0.3MP）

用户要求：能否直接出一段 15 秒连续动作，不走多段拼接（脸的问题先不管，等以后更好的在线模型）。

**做法**：`output/shopping/sb15.json`，单段 `seconds: 15`，首帧 `shopping_s01_first.png`、尾帧 `shopping_s03_last.png`（两张都是中景、同一机位、同一个人），动作写成连续四拍：转头看橱窗 → 回正看镜头 → 抬手掖头发 → 双手抬到胸前比划，全程双脚不动。

**结果**：15.00s / 832×1472 / 24fps / 带音轨，**本地出片约 4 分钟**（大幅短于 4 段 5s 拼出来的总耗时）。

| 项目 | 实测 |
|---|---|
| 动作连续性 | ✅ 四拍真的按顺序演完了，收尾姿态基本落在尾帧（SSIM 0.831） |
| 首帧贴合 | 0.876 |
| **人脸尺度漂移** | ❌ **3.0×**（face_ratio 0.0202 → 0.0613）：t=0~3 中景，t=4~8 自己推成半身，t=12 又拉回中景 |
| 往返比 | ❌ 3.55（人物在画面里横向漂移后回来，净位移 113.6px） |
| 动作分布 | ⚠️ 前 50% 完成 123%：动作全挤在前半段，后半段基本静止 |
| identity | ❌ 0.073（按用户要求本次不作为结论） |

**结论**：
- **15 秒单段技术上是通的**：帧数/显存/时间都没问题，脚不动的小幅度连续动作能演完，适合"一个长镜头里连着几个小动作"的需求；
- **但构图会自己呼吸**：模型在中段擅自推镜到半身、再拉回，`face_zoom` 是这条链路里 15 秒档的头号问题，写"绝不推近"也压不住（同 5 秒档没这么严重，说明是时长拉长后累积漂移）；
- 要长镜头就先接受"景别会变"，或者把 15 秒拆成 8+7 两段（拼接点用 0.25s 叠化），构图稳定性明显更好；
- 复现：`pipeline.py video --storyboard sb15.json --seg 1 --backend local`。

### 7.11 身份锚接错人（2026-11-05 用户发现，最贵的一个 bug）

**现象**：用户问「为什么你每次跑任何工作流都会出现这个参考图」——截图是一张穿棕色校服的女生。
查下去发现：`ComfyUI-Shared/input/image.png`（早年留在输入目录的旧图）被写进了三个 H3 工作流的
LoadImage 默认值，而它挂在**节点 110 = reference_1** 上。

**为什么致命**：视频提示词模板写的是「`<Picture3>` 起是<女主角>的身份参考」，而 Picture3 就是
reference_1。`pipeline.py gen_local` 当年只覆写了 `111`（reference_2），**110 从来没被改过**。
于是每次出片，模型收到的身份锚是那位校服女生，我们真正的参考图只是第二顺位。
job 目录可直接验证：旧任务 `reference_1.png` 的 md5 ≠ 项目参考图。

**影响面**：所有本地 H3 视频（含 15 秒单镜、咖啡、逛街全部）都在这条错锚下生成；
identity 长期卡在 0.1~0.35、中途变脸、「凭空多一个人」都被它放大。

**修法（三处，已落地）**：
1. `pipeline.py gen_local`：`110` 和 `111` **一起**覆写成 `<sb 的 reference_images[0]>`；
2. `_new_director_job`：复制参考图到 `job/reference_1.png` 后**把 `cfg["reference_images"]` 指过去**
   （以前只复制文件、config 仍继承模板任务的旧路径，等于换了个坑继续踩）；
3. 三个 H3 工作流的 LoadImage 默认值统一改成 `placeholder.png`（中性占位图，
   `.bak-20261105` 备份），`write_director_workflow` 生成工作流时再把真实参考图/首帧烤进去——
   打开工作流不会再看到别人的脸，误点 Queue 也不会静默用错人。

**修正后实测（段2，加速档 4+2）**：identity 0.346 / 0.267 / 0.292（修正前最好 0.305），
最好值提升、backtrack 由 FAIL 降为 WARN，但 0.45 闸门本地仍未达成。

### 7.12 关键帧比例守卫：非 9:16 会被纵向拉伸（2026-11-05）

**现象**：15 秒测试片的第一帧，人明显被拉长（腿特别长、脸变窄）。

**帧证据**：`shopping_s01_first.png` 是 **896×1184（3:4，比例 0.757）**，而 H3 按
832×1472（0.562）采样 —— 宽高比差 35%，节点不做等比适配，直接拉伸填充。
其余 18 张关键帧都是 768×1376，所以只有段 1 拉长。

**为什么会留 3:4**：关键帧先按原图比例干净生成（3:4/4:5），最后统一用扩图 LoRA 扩成
9:16。那天 8 段重出跑到一半被打断，段 1 的两帧停在扩图之前。

**修法（已落地）**：`cmd_video` 出片前逐帧查比例（`_ensure_ratio_916`）：
非 9:16 → 自动扩图（中性"延续原场景"提示词）→ 仍不合格就**拒绝出片**并说清楚。
以后不会再出现"帧没扩完就直接喂给 H3"的带病出片。

**验证动作**：出片前 `python -c "from PIL import Image; ..."` 把 20 张帧的宽高比列一遍，
或直接看 `frames` 阶段有没有打印「扩图 9:16 …」。

### 7.13 英文提示词 vs 中文：5 秒段 A/B（2026-11-05）

**背景**：用户给了一份英文的视频提示词格式（`integrated_multimodal_description` +
`[Shot 1]` + `overall_soundscape` + `non_diegetic_music`），问英文是不是效果更好。

**做法**：同一段（段2 橱窗俯身）、同一对首尾帧、同种子序列，把我们的中文模板换成
按该格式写的英文提示词，各跑 3 个种子。

| 指标 | 中文模板 | 英文结构化 |
|---|---|---|
| identity（3 seed） | 0.346 / 0.267 / 0.292（均 0.302） | **0.314 / 0.347 / 0.278（均 0.313）** |
| 首帧到位 SSIM | 0.886 / 0.887 / 0.891 | 0.889 / 0.890 / 0.888 |
| 尾帧到位 SSIM | 0.855 / 0.857 / 0.856 | 0.855 / 0.856 / 0.845 |
| backtrack | WARN 1.76~1.83 | FAIL 2.13~2.28（更差） |

**结论：语言不是变量，持平（差值在种子噪声内）**。H3 的文本编码器是 Qwen3-VL 32B，
本身双语；MiniMax 的训练语料以中文为主，中文在"转头几何描述"这类可控性上反而更有抓手。
**不要为了"效果更好"去翻英文**——翻过去只是多一层转译误差。

**但那份格式有两点必须吸收**（已落地）：

1. **音效 / 配乐两段**：H3 是带音轨生成的，我们以前一个字都没写声音，等于把音频交给模型乱编。
   现在 `VIDEO_TMPL` 末尾固定两行：`环境音：…` / `配乐：…`，分镜可用 `soundscape` /
   `music` 字段覆盖；不写就只给"与场景一致的稳定环境音 + 不加配乐"。
2. **首尾帧时间锚定**：`At 0.00 s <Picture 1> is the exact opening frame, at the end
   <Picture 2> is the exact closing frame`——中文模板第一句本来就是同义，保留即可。

### 7.14 参考图的背景会被整套复刻（2026-11-05，找了一整天才定位）

**症状**：每一帧底部都长出一块木台面/桌面，改扩图提示词、重出帧都去不掉，
用户连问两次「尾帧怎么还是有桌子」。

**根因**：主参考图 `ref_girl.jpg` 是**室内照**——她坐在地板上，旁边是床头柜和床，
地面是暖棕色软木/木地板。2.1 编辑模式把参考图当底版，木地板与床头柜被一并复刻。

**决定性证据**（同段、同提示词、同种子，只换参考图）：

| 参考图 | 底部"暖棕高饱和"像素占比 | 画面 |
|---|---|---|
| 整张室内照 | 0.48 ~ 0.94 | 底部一条木台面 |
| 只裁头部+肩胸（422×367） | **0.03 ~ 0.04** | 干净石板路 |

**规则**：
1. 主参考图**只保留人物**（头到胸/头到腰），背景裁掉；它只负责身份，
   场景交给 `shot` / 场景锚 / `scene_text`；
2. 裁图时把木色地面、桌面、柜子这类**暖色大块**去掉——它们是最容易被复刻的元素；
3. `frames` 阶段新增后验：底部 12% 暖棕占比 > 32% 直接打印警告（`warm_bottom_ratio`），
   干净帧实测 0.03~0.19、带台面 0.48~0.94，区分很清楚；
4. 这条和「锚图卫生」合起来是同一句话：**参考图脏，每帧都脏；锚图脏，全片都脏**。

### 7.15 从外部案例库反哺模板：时间锚 + 场景正面清单（2026-11-05）

翻 beatapi.io 的 H3 提示词画廊（整理件见同目录 `H3提示词案例库.md`）后，
把两条直接落进 `pipeline.py` 的 `VIDEO_TMPL`：

**① 单镜时间锚**（来自案例「雨夜站台」的 `Shot 1 continues — 5.5s:`）

- 做法：`beats` 按数量等分时长（末尾留 10% 收尾），渲染成
  「0.0s 保持首帧姿态；2.2s …完成；4.5s …完成；5s 才停在尾帧姿态」+
  「不许提前把后面的动作做完」「最后一个节拍后不要定格」。
- 治的病：§7.10 里 15 秒单镜「三个动作全挤在前 50% 演完、后半段定格」
  （`motion_front` 123%）。根因不是幅度，是**一个时间点都没写**。
- 副作用要盯：时间锚会和 `motion` 里的顺序描述叠加，如果两者说法不一致
  （motion 说"先转头"、beats 顺序反过来），模型会二选一。写分镜时两边顺序必须一致。

**② 场景正面清单**（来自案例「沙发动画」的 `The room contains only A, B and C.`）

- 做法：新增分镜字段 `scene_items`，视频提示词渲染成「场景里只有 <Picture1> 里已经存在的
  这些东西：{scene_items}；除此之外不加入任何家具、长椅、桌子、台面、栏杆…」。
- 治的病：§7.14 那类"画面下方自己长出台面"。负向串模型会漏且不报警，
  正面点名让画面每一块地方都有归属。
- 写法要求：`scene_items` 与 `shot` 必须互相覆盖——`shot` 提到的物件都要列进去，
  列进去的物件 `shot` 里也必须有。**"描述里出现的物件，模型一定会画出来"**
  （案例「书店精灵」里 `a ceramic coffee cup` 就是它自己项目的桌面来源）。

| J1 | **MeanShift + 12 色量化锚** | **16.0%** | ✅ 采用 |
| J2 | Canny 线稿锚 | 17.3% | 略差，出镜像感 |

**根因**：2.1 的 `image_2` 不是"参考它的空间布局"，而是"照着这张照片重渲染"。锚里任何
高频纹理都会被逐像素复刻，并按景别放大——全身景下地面占比从 40% 涨到 60%，等于把锚的
地面纹理放大 4 倍画，于是从"石砖缝"变成"碎石噪点"，再顺着手臂／腿部皮肤蔓延。

所以 §7.14 的"参考图脏→每帧脏"只讲了一半：**锚即使不脏，只要"太像照片"，一样炸**。

**解法**（已落 `pipeline.py::quant_anchor()`）：
1. `pyrMeanShiftFiltering(24, 32)` + `kmeans(k=12)`，`setRNGSeed(0)` 固定初始化；
2. 首帧图2 用 12 色（去纹理优先），尾帧图2（本段首帧）用 24 色保袖长/蕾丝边；
3. 结果缓存成 `<锚>_q.png` / `<锚>_q24.png`，按 mtime 失效。

**全片验证**（shopping 10 段重跑）：段5/7/9 = 17.4% / 16.0% / 16.9%；最差段 58%→17%，
脸 Lap 152→75。干净段会升 3~5 点（11%→16%），最差段降 42 点，**方差从 11~58% 收敛到 12~17%**。

**边界**：量化锚只治"纹理复刻"，不治畸形/多脚/凭空道具——那些是布局问题，仍要重出锚。

**同一实跑的两条正向结论**：① 三段人物占比 ~55% / ~80% / ~70%、街景角度与光影

不必量化/抠图/合成；② 成片 832×1472 / 24fps / 317 帧 / 13.21s，3/3 段，
首/尾帧 SSIM 0.976~0.986、static_ratio 0、零 flags。
**附带边界**：Director 内部合并是硬切 + 剪静止帧（15s → 13.21s，剪约 1.8s），
不读分镜的 `join_dissolve_seconds`；三机位切镜硬切无双影，
若要 0.25s 叠化得走 pipeline 的 `merge --join-dissolve 0.25`。

#### 7.16.6 chain 段首尾帧没连到一起：manual 覆盖 + 2.1 不复制（2026-11-05 20:00）

**现象**：19:44 的三机位 3 段成片观感正常，但 Director 关键帧面板里段 1 尾帧与
段 2 首帧是两张独立生成的图（且机位不同），段 2 尾 ↔ 段 3 首同理。
用户指出「昨天 skill 不都弄好了吗」——文档里 chain 的语义本来就是同一张图。
**帧证据**：`s3_frames/s3_sheet.png` 六格，段 1 尾是平视全身远景、段 2 首是侧 45°
中近景，完全不是同一张；修复后 `s3c_chain_final.png` 四格，接缝两对 md5 严格相等。
**根因**：两处叠加。① `cmd_frames` 的 2.1 分支 `chain` 只打印不复制
（只有 2511 `shutil.copy` 上段尾帧）；② `cmd_director_push` 给每段都写
`segNN_start_manual.png`，而 `repo/docs/工作流关系.md` §3.2 的首帧优先级是
「manual start → 上一段尾帧（链式）」，manual 把继承顶掉了。
连带后果：`Q21_LAST_TMPL` 声称「图2 是本段首帧，是同一个镜头」失去前提，
尾帧机位 / 服装没有同一镜头的硬基准。
**规避写法**：① `cmd_frames` 两个后端 `chain` 段一律复制上段尾帧作首帧；
② `cmd_director_push` 在 `chain:true && i>1` 时把 `first_src` 指向上一段 `last`，
`continue_from_previous` 按分镜写（不再写死 True）；
③ 分镜语义分开：**连续动作** `chain:true`（全链同一机位、首帧 = 上段尾帧），
**切镜** `chain:false + transition:cut`（独立首帧，可换景别 / 角度 / 光影）。
验收口径是 **md5 严格相等**，不是「看起来相似」，也不是「加 0.25s 叠化糊过去」——
叠化只用于姿势差大的切镜接缝。

**实跑**：任务 `20261105_203221_2f6a3df9`，3/3 段 completed，成片 832×1472 /
24fps / 296 帧 / 12.33s，QA 全绿（首尾 SSIM 0.983~0.986、static_ratio 0、零 flags），
相邻帧灰度 MAE 中位 1.35、段间峰 5.9（三机位硬切版是整张换构图），
抽帧无跳变 / 换人 / 双影。

**同源闸门**：`bg_ref` + 段级 `light` 时过曝阈值 `ao+0.015`（≈1.7%）会把白天街景
玻璃反光 / 天空的 2.0% 误判成「墙面或高光死白」；放宽到 `max(0.030, ao+0.020)`，
真过曝仍拦得住。与 §7.16.5 的曝光门一样，改完用 `frames --seg N` 秒级重算。

### 7.17 尾帧"一动不动"：模板里「不变」的量压过了「变」（2026-11-05）

**症状**：shopping 分镜 10 段里 9 段首尾帧质检 FAIL，全部是
`首尾帧几乎同姿态（关键点位移 0.02，阈值 0.12）`。`end_action` 写得很具体
（"右手抬到肩膀高度、手掌平贴橱窗玻璃"），出图手臂完全没抬。

**根因**：`Q21_LAST_TMPL` 旧版是全片共用模板，为了锁死服装/身份/场景，累计写了
「保持…完全一致」「以图2为唯一标准」「保持原状」「不许…」「不新增也不删除」共 10 处，
只有 1 处 `{end_action}` 在描述"要变"。更要命的是结尾那句
「人物在画面中的大小**和位置**与图2保持一致，不靠近也不远离镜头」——
模型的解读是"整个人的姿态也别动"。

**实证**：同 seed、同 end_action，只改模板措辞 → 位移 0.02 → **0.14**，
`主要变化：右腕 0.88`，质检 FAIL → PASS。

**规则**（所有编辑模式的提示词都适用）：

1. 动作句放**第一句**，前面先声明"这一张画的是动作做完之后的样子"；
2. 用「姿势必须与图2 明显不同」并要求**至少四项可见变化**：手臂位置、手的落点、头部朝向、上身倾角；
3. 「不变」**必须点名范围**，只允许：身份 / 服装配饰 / 场景三样；
4. 描述人物大小时只能用「**尺度**一致」，并补一句「只约束大小，不约束姿势」——
   写成「大小和位置一致」等于锁死姿势；
5. 头发锁只写发长/分缝/不飘散，别写"垂落位置不变"（抬手时头发必然动）。

> 通用规律：**模型对"不许改"的服从度远高于"要改"**。一段提示词里负向锁一旦超过两三条，
> 正向动作就会被稀释成"原样复制"。

### 7.7 验收清单（每次出片必做）
1. **末帧锚定 MAE**（脚本 `output/coffee/seam_metrics.py`）：> 14 就要换种子重出；
2. **密集抽帧**（每 0.6~1s）：看动作是否重复/倒退、场景是否漂移、有没有第二个人；
3. **接缝 MAE**：> 8 就补叠化；
4. **首帧锚定**：确认段首没有跳帧（adopt 后应 ≈0）；
5. **静物核对**（§1.19）：抽帧里逐秒看每件静物的朝向/位置/状态有没有中途变化（杯子把手、椅背、门、屏幕内容）；
6. **新坑记录**：发现上面没覆盖的新问题，当天按 `现象→帧证据→根因→规避写法` 记入 §7.6 和 skill。

### 7.8 出视频后端：本地 / 云端（2026-11-04 加进 Director 节点）

ComfyUI 的 Director 节点新增 `video_backend`（`本地 ComfyUI（默认）` / `RunningHub 云端`）。
**只管视频阶段**——关键帧永远在本机出（云端没有 Qwen 关键帧链，也拿不到参考图扩图），
所以还是「本机出帧 → 人工确认 → 再出视频」。

| 差异 | 本地 | 云端 |
|---|---|---|
| 采样 | 可一采 / 二采 | **只有单采**（段里的 `two_pass` 被忽略，日志会提示） |
| 渲染尺寸 | `megapixels`（0.3 甜点） | `runninghub.megapixels`（0.3 → 416×736），留空才用成片尺寸 |
| 末帧 | 节点直接吐图 | `ffmpeg -sseof -1` 抽最后一帧，链式继承不变 |
| 帧数 | `h3_frame_count` 向上取到 17n+5 | 同一套规则（5s→124、6s→158），避免段段变短 |
| 缓存 | 各自独立 | 签名含 `video_backend`，切换后端会重渲，不会拿旧片冒充 |
| 重试 | 失败自动重试 | **不自动重试**（每次真扣额度），失败单段 `--force` 重跑 |

顺带删掉了 `keyframe_steps`：关键帧与正片共用 `steps`。两个旋钮并存时最容易出
「关键帧糊、正片清」——改了 `steps` 忘了改它。旧工作流打开时前端会自动摆正
`widgets_values`（`migrateLegacyKeyframeSteps`）。

坑（第一次接云端时踩的）：
- 平台 conditioning 节点的 `length` 必须落在 `17n+5`，否则被拒或被拉回；
- 宽高必须被 **32** 整除（720 直接报 ValueError，会吸附到 704/736）；
- 只有首尾两张图时，提示词里引用 `<Picture 3>` 会被 `strict_prompt_tags` 拒单（code 805），
  要改写成"以 `<Picture 1>` 首帧为身份基准"。

## 11. 杂志感 / 电影感 配方（2026-11-03 实测）

### 11.0 一句话结论

**「杂志大片」「电影感」「高级感」「8K」这些词，模型只会翻译成"通用好看"，不会给你那种风格。**
风格是可以被复现的构成要素：**布光器具 + 光源动机 + 介质 + 构图 + 色彩设计**。
实测同模型同 seed，只换措辞，差距大到像两个模型出的。

### 11.1 杂志图：六个必写项

| # | 要素 | 写法（可直接用） |
|---|---|---|
| 1 | 布光器具 + 角度 | `主光是头顶偏前四十五度的美人碟，光斑落在额头到鼻梁这一段`；`右下方银卡把下颌阴影提亮一档` |
| 2 | 背景与明度关系 | `浅灰色无缝背景纸，没有其他道具`；`背景纸比人脸暗两档` |
| 3 | 服装结构与材质 | `黑色皮质衬衫，领口立起，能看到皮革细纹和肩线的硬挺结构` |
| 4 | 妆容的具体质感 | `哑光底妆，鼻梁与颧骨一层很薄的珠光，眼线细而平直，唇色低饱和豆沙，唇纹清晰` |
| 5 | 姿态与重心 | `正脸朝镜头，下巴略收，肩膀一高一低形成重心，右手抬起搭在锁骨上` |
| 6 | 镜头与光圈 | `85mm 定焦，f/5.6，全脸清楚，背景干净无渐变` |

**反例（A1）**：只写「时尚大片，高级感，杂志封面，超模气质，8K」
→ 出的是**网红脸 + 婚纱影楼感**，皮肤蜡质，背景还自己冒出几块几何色块。

**正例（A2）**：上表六项全写 → 皮革有颗粒、皮肤有毛孔、妆容哑光、
高光沿额头到鼻梁形成一条明确的光带、肩线硬挺 —— 像真的杂志内页。

> **要点：杂志感 = 控制光。** 光越具体（器具、角度、补光位置、背景差几档），越像专业棚拍。

### 11.2 电影图：七个必写项

| # | 要素 | 写法（可直接用） |
|---|---|---|
| 1 | 动机光源（谁在发光） | `主光是便利店灯箱的冷白光，从她右前方斜打过来` |
| 2 | 双色温对撞 | `街对面招牌的洋红作为副光，从她左后方勾出轮廓` |
| 3 | 暗部留细节 | `其余部分沉进阴影，最暗处保留细节不死黑` |
| 4 | 前景遮挡 | `前景有雨渍的玻璃边缘遮挡，虚化` |
| 5 | 反射与现实感 | `雨后的地面反光把冷白和洋红重新反射进画面下半部分` |
| 6 | 构图与"不看镜头" | `人物在画面左侧三分之一，低头看手里的塑料袋，没看镜头`；`上方三分之一是黑暗的屋檐` |
| 7 | 介质与画幅 | `35mm 变形宽银幕镜头，anamorphic 横向拉丝 flares`；`2.39:1`；`Kodak Vision3 500T 的颗粒与偏青阴影` |

**反例（B1）**：只写「电影感的夜晚街头，电影级光影，大片氛围，故事感，cinematic lighting」
→ 出一张**空荡荡的路灯街景**，主体缩在远处几乎看不见，没有任何色温设计。

**正例（B2）**：上表七项全写 → 冷白主光 + 洋红副光两块色温对撞、
湿地反光、前景雨渍玻璃、主体在左三分之一低头、暗部不死黑 —— 直接是电影剧照。

> **要点：电影感 = 光源有出处 + 两种色温打架 + 画面里有遮挡。**
> 光说"电影感"，模型只会调暗画面加几盏路灯。

### 11.3 画幅比必须直接改分辨率，不能只写在提示词里

| 用途 | 分辨率 | 比例 |
|---|---|---|
| 杂志竖幅 | 912×1216 | 3:4 |
| 杂志封面 | 912×1216 或 1024×1280 | 3:4 / 4:5 |
| 电影宽银幕 | **1600×672** | 2.38:1 |
| 宽银幕（更高） | 1936×816 | 2.37:1 |

只写「2.39:1」但画布还是 9:16，模型会把内容硬塞进去，出不来宽银幕的横向叙事感。
宽高都要是 16 的倍数。

### 11.4 跨模型验证

同一段具体提示词，MOSS 与 Qwen-Image-2.1 都吃这一套：

| | 杂志版 | 电影版 |
|---|---|---|

## 12. 画幅硬锁与长任务进度（2026-11-07，卡牌战斗 60s 实跑）

### 12.1 skill 链路硬锁 9:16，宽幅只能另搭 API 图

- **现象**：想用 16:9（1344×768）跑 Director，改 job `config.json` 的 `final_width/final_height` 也不生效。
- **帧证据**：任务 `20261107_182638_17a464bc`，4×15s = 60.0s / 832×1472 / 1440 帧，成片 `星界卡牌对决_60s.mp4`。
- **根因**：两道校验。`director.py` 建任务时 `final_width >= final_height` 直接 raise；`run_h3_long_video.py` controller 还有 `if "9:16" not in aspect_ratio: raise RuntimeError`。`resume` 只传 config 路径，但拉起的是独立 controller 进程、照样校验。H3 节点本身支持 1344×768（自建 API 图提交成功、`node_errors` 空）。
- **规避写法**：走 skill 就先适配成 9:16；坚持宽幅就别用 Director，自己搭 `MiniMaxH3ReferenceToVideo` + `SamplerCustomAdvanced` API 图。

### 12.2 16:9 → 9:16 适配：reflect pad 会复制倒立人物

- **现象**：`np.pad(mode="reflect")` 出来的竖版，上下各出现一个倒立的人，像镜面倒影；渐暗也压不掉。
- **帧证据**：`card16_sheet.png` 第一版（4 张横排），上下倒立人物清晰可辨。
- **根因**：reflect 是按边界逐行回弹复制，人物本来就在画面中部偏下，回弹后必然被完整复制成倒影。
- **规避写法**：原图 cover 缩放 + 中心裁切 → `GaussianBlur(34)` + 亮度 0.62 做铺底；清晰主画面按宽缩放居中，上下各 120px alpha 羽化。第二版拼图无倒影、无硬边。实跑发现 H3 会把这种帧**重演绎成原生竖构图**（星空占满上方、人物中近景、圆台在下），成片里完全没有「横屏嵌竖屏」痕迹。

### 12.3 「卡住了」多数是静默等待，不是死锁

- **现象**：用户报卡住；查 ComfyUI 队列 `running=1`、日志显示 TE/UNET 已 staged，其实在渲染。
- **帧证据**：自建 `run_card_video.py` 的 `wait()` 最长 1800s、每 5s 轮询且零输出；`/prompt` 本身 0.0s 返回 `prompt_id`。
- **根因**：等待循环没有进度心跳，人看不到任何反馈。
- **规避写法**：每 15–30s 打印「已耗时 + ComfyUI running/pending」；提交后立即打印 `prompt_id` 并支持 `attach <seg> <prompt_id>` 接管，避免重复提交。Director 链路用 `/h3-long-video/status/<job>` 轮询，同样带心跳。

### 12.4 「镜头全程固定」锁不住 H3 的推近 / 特写

- **现象**：提示词明写「不推近、不拉远、不切特写」，段 1 仍被 QA 判 `last_frame_drift`（尾帧 SSIM 0.329，其余三段 0.92–0.98）。
- **帧证据**：成片 `card_final_video_sheet.png`，t=0.5s 双人全身远景 → t=6s 女子半身 → t=10/14s 女子持卡特写，t=17s 才回到双人中景。
- **根因**：H3 按 15s 长段自己调度景别，静态锁句压不过长时长下的运动先验。
- **规避写法**：观感上像剪辑过的电影片段、可接受；但**尾帧不再等于关键帧**，别拿 SSIM 当唯一验收口径。要严格锁机位，把 15s 拆成更短的段或改用首尾帧约束更强的模式。
