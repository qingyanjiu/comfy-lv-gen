# H3 约束层提示词规范（head / tail）

> **这份文档只给维护者看。** 写分镜、写 `body` 请看 [`segment编写规范.md`](./segment编写规范.md)。
>
> `head` / `tail` 是**全片唯一一份**的公用约束，存在 `assets/selflift.global.json` 里，
> 所有片共用、由维护者统一优化。分镜作者不需要看、不需要改、也不需要在 `body` 里重复任何一条。

---

## 一、分工

| 层 | 文件 | 谁写 | 写什么 |
|---|---|---|---|
| 约束层 | `assets/selflift.global.json` 的 `head` / `tail` | 维护者 | 身份锚、画风、眼神统一句、承接规则、静息、禁止项 |
| 内容层 | 上传的分镜 JSON | 分镜作者 | `title` / `story` / 参考图 / `segments[].body` |
| 运行产物 | 片目录 `segments.json` | 工具生成 | 约束层快照 + 内容层，别手改 |

判断标准只有一条：**所有片都成立的话 → 写进 head/tail；只有这一部片成立 → 写进 story / body。**

---

## 二、head 现有的块

改之前先认块。每块之间用空行分隔，块内不要再空行（块级占位符按空行识别段落边界）。

| 块 | 管什么 | 改的时候注意 |
|---|---|---|
| 【人物身份与参考图绑定】 | `<Picture {pic:1}>` 是人物、按参考图锁脸 | 编号只用占位符，别写死数字 |
| 【场景与环境参考】 | 结构以空镜板为准、不许改建筑与光源方向 | 没接空镜板时整块要能自然成立 |
| `{picblk?:first}` … `{/picblk}` | 真实首帧继承（链式段才出现） | **必须**块级包住多行，行级 `{pic?:first}` 会留孤立标题 |
| 【全片空间关系与摄影机连续性】 | 不跨轴、只改摄影机不改人物 | 通用规则，不写具体机位 |
| 【人物眼神与面部表情】 | 眨眼频率 + catchlight + 不空洞 | 全片只此一份，段级 head 若存在要逐字复制 |
| 【人物身体动态与生理真实感】 | 呼吸、重心、动作缓 | 别写具体动作 |
| 【头发、服装与材质动态】 | 发丝、衣料随动作的次级运动 | 同上 |
| 【空间关系、物体完整性与物理接触】 | 不穿模、不残留肢体 | 只保留通用禁止，不做手指级描述 |
| 【背景人物与群体行为自然度】 | 群演各自自然、不抢焦点 | 只在有背景人物时才有意义，保留通用描述即可 |
| 【全片统一执行原则】 | 收口：人物运动是主线 | 别在这里加新规则 |
| 【本片设定】`{story}` | 由分镜的 `story` 字段注入 | 分镜没写就整块删；不要在这里写死某一部片 |

## 三、tail 现有的块

| 块 | 管什么 |
|---|---|
| 【统一画风与摄影质感】 | 写实电影、35mm、浅景深、胶片颗粒、低饱和调色；反向禁止塑料皮肤/过锐/异常 HDR |
| 【段尾稳定与真实交接】 | 段尾 0.5 秒自然收束、保留可继承的最后一帧 |
| 【全片统一禁止项】 | 换人融脸、跨轴环绕、穿模、文字水印…… |

**tail 不要重复 head 已经写过的规则。** 同一句约束出现两次不会加强，只会互相稀释。

---

## 四、占位符

`head` 里所有涉及图片编号、可选媒体、本片设定的地方都必须用占位符，由 `seg_prompt()` 按本段实际接线换算。

| 语法 | 展开 |
|---|---|
| `{pic:1}` … `{pic:8}` | 第 N 个人物参考 |
| `{pic:plate}` | 空镜板（永远排最后） |
| `{pic:first}` / `{pic:last}` | 本段首帧 / 锁定的尾帧 |
| `{pic?:key}` | **行级可选**：本段没接该媒体 → 整行删掉 |
| `{picblk?:key}` … `{/picblk}` | **块级可选**：本段没接该媒体 → 整块删掉（多行段落必须用这个） |
| `{story}` | 分镜的 `story` 字段，一行的形式注入；没写则整块删 |

规则：

- 编号 1-based，`{pic:1}` 是**人物**，不是首帧；接了 first_frame 之后人物会整体后移一位，这正是不能用死数字的原因。
- 引用本段没接的序号 → `strict_prompt_tags` 直接报错并列出本段实际接线。
- 写多行、且只在链式段成立的段落（比如首帧继承），一律 `{picblk?:first}` 包住。
- 花括号只允许上述几种；裸的 `{` 会在网页保存时被拦下。

---

## 五、段级 head（内部能力，不对外）

`segments[].head` 会**整段覆盖**全局 `head`，不是追加。一旦某段写了段级 head：

- 该段就失去了全局 head 的所有统一约束；
- 必须把眼神统一句、身份锚、禁止项**逐字复制**过去，否则这段等于没有约束；
- 只在「本段接线特殊、需要完全不同的说明」时才用，正常分镜不要用。

## 六、改约束的流程

1. 改 `.workbuddy/skills/h3-long-video/assets/selflift.global.json`（仓库里的 `skill/assets/…` 同步）。
2. **新建的片**：建片时读文件，自动带上新约束。
3. **已有的片**：不用手动套用。下次跑 `run` / `runall` 前会自动比对并合并；
   有差异才写入并打 `head/res/quality_updated_at`（全片标需重出），完全一致时一个字节都不写。
4. 维护者强制刷新口仍在：`POST /h3-long-video/selflift/apply-global`（`force=True`），网页已不暴露。
5. 改完 `head` 要检查自己的改动有没有和 `tail` 重复、有没有写死图片编号、有没有漏掉块级占位符。

改了 `selflift.global.json` 不需要重启；改了 `selflift_panel.py` / `schema` / 网页才需要重启服务（内嵌 8188 需重启桌面版）。

## 七、head / tail 自查

- [ ] 每条规则都是「所有片都成立」的，没有混进某一部片的剧情或人物
- [ ] 图片编号全部用占位符，没有写死 `<Picture 1>`
- [ ] 多行的条件段落用 `{picblk?:key}` 包住，行级可选句用 `{pic?:key}`
- [ ] 眼神三件套只出现一次，且全片统一
- [ ] tail 没有重复 head 的规则
- [ ] 没有裸的 `{` 符号
- [ ] `{story}` 块只在【本片设定】里，没写死具体设定
