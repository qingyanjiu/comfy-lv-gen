> **2026-11-01 起这条链路已自动化**：Director 的 `keyframe_backend` 选 2511 / 2.1 时，
> `run_h3_long_video.py` 会按本文的方法（空 latent 首帧 + 上一帧当画布派生尾帧、固定 608×1056）
> 代码建图自动出全部首尾帧，不用再手动开下面的工作流。它们保留为调参 / 试提示词用。

> 2511 出一张目标角度的底图，再让 2.1 拿它当糊画布 + 正面参考照换回原人物的脸
> （`Qwen改图.md`「先出角度图、再换回原人脸」）。

## 结论

用生图模型生成首尾帧**比凑图更好**，但前提是**串行派生**，不是两张图各写一个 prompt 独立生成。
独立生成的两帧，场景、光向、机位、人物尺度一定对不齐，视频模型插值时就会硬切、飘、地面滑动。

正确顺序：

```
① 生成原生 9:16 首帧 F0
② F0 当 image 1（构图锚）+ 身份图当 image 2，改动作 → 尾帧 F1
③ F0 / F1 接进 H3 的 first_frame / last_frame
```

## 五个实测出来的坑

### 1. 不要事后把 1:2 裁成 9:16

H3 **在生成时会把人往近处推**。输入构图只要没有富余空间，推近后头顶就出画。

实测三种处理（同一对首尾帧，同一 seed）：

| 处理方式 | 输出头顶 | 备注 |
| --- | --- | --- |
| 镜像补边到 1080×1920 | 完整 | 能用，但两侧是镜像，不自然 |
| 纯裁切到 960×1707 | 发顶被切 | 构图拉紧，推近后直接出画 |
| 裁切 + 缩 90% + 模糊底 | 仍被切 | 四周模糊带被模型无视，照样往中间顶 |

**正解：首帧在生成时就按 9:16 出。**

### 2. 让编辑模型"修镜像"会变成三联画

把补边图喂回 Qwen 让它"把两侧镜像换成真实背景"，4 步蒸馏版会理解成"这是一张三联画"，
直接画出三个半人 + 一条竖直分界线。这条路别走。

### 3. 原生 9:16 的正确做法：空 latent

`Qwen2511-FirstFrame916.json` 的做法：

- 把 KSampler 的 `latent_image` 从 `VAEEncode(image1)` 换成 `EmptySD3LatentImage(720, 1280)`；
- 参考图照旧接 `TextEncodeQwenImageEditPlus` 的 image1/2/3。

效果相当于"以参考图为条件的重新构图"：人物身份、服装、场景、光影都带过来，
但构图按 720×1280 重新排，头顶和脚下由模型补齐，不存在硬边和裁切。

### 4. 派生尾帧时，别写"位置不变"

第一版尾帧几乎没动，原因就是提示词里写了：

- 「双腿保持原来的坐姿和**位置**不变」
- 「人物在画面中的**位置和大小不变**」

这两句在保护构图，也把动作锁死了。要改动作，就只锁「场景、机位、光向、服装」，
不要锁「人物位置和大小」。

另外，**动作幅度必须够大**。实测同一张图：

| 尾帧动作 | 视频表现 |
| --- | --- |
| 右手从床面移到膝盖 | 前 2.5 秒就走完，后 2.5 秒定格 |
| 上身后仰 35°、双手移到身后撑床、肩线打开 | 5 秒内均匀完成，全程有运动 |

### 5. 输出比例必须是精确 9:16

H3 会直接报错：`final resolution must remain a 9:16 portrait preset`。
`720×1456` 这种"接近 9:16"的尺寸不接受，只能 720×1280（或其它 9:16 预设）。

Qwen 那边 `FluxKontextImageScale` 会把图缩到约 1 MP，输出未必是精确 9:16
（实测 720×1280 的输入出的是 752×1392，比例 0.540）。所以尾帧出图后要再裁一次到精确 9:16
（752×1337，切顶部 55 px）。

## 关键帧对齐成片分辨率（2026-11-02）

### 为什么改

关键帧一直是固定 `608×1056`（比例 0.5758），成片是 `832×1472`（0.5652），差 1.86%。
以前靠 `normalize_video_resolution` 里的 `scale=W:H` 硬拉伸过去——**整片被横向压扁 1.86%**，
脸会显窄、圆形的东西变椭圆。这个偏差在 720p 上看不出来，上到 1080p 会很明显。

### 现在的做法

```
Qwen 出图（608×1056）
  → aspect_gap 算和目标的差
      ├─ 差 ≤ 0.5%：直接 resize 到 832×1472
      ├─ keyframe_align=crop（默认）：等比放大到 848×1472 再中心裁成 832×1472
      └─ keyframe_align=outpaint：铺目标比例的灰底画布 → 扩图 LoRA 补真实场景 → 裁+resize
  → 关键帧 = 832×1472（和成片同尺寸）
```

H3 拿到的首尾帧和输出尺寸完全一致，`normalize_video_resolution` 里那段
`scale=W:H` 也一起改成了 `scale=...:force_original_aspect_ratio=increase,crop=W:H`，
两处用同一套几何，谁都不会再拉扁。

### 扩图那一档在哪

`outpaint_canvas_geometry()` 会在预算附近搜一遍 32 对齐的宽高组合，挑**比例误差最小**的那组：

| 目标 | 源 | 画布 | 比例误差 |
|---|---|---|---|
| 832×1472 | 608×1056 | 672×1184 | 0.42% |
| 720×1280 | 608×1056 | 576×1024 | 0.00% |
| 1080×1920 | 608×1056 | 576×1024 | 0.00% |

比例误差权重故意压得比像素预算高 40 倍——为了凑像素数把比例搞歪 1%，
后面还得再裁一刀，等于白扩。

扩图走的是 `build_qwen_keyframe_graph(..., preset=OUTPAINT_PRESET, size=画布尺寸)`：
复用 2.1 那条编码器路径，只把 UNET 换成官方 int8、挂上扩图 LoRA、步数提到 20。
底模别换回 ray 微调版，它在扩图上会乱造角度。

### 手动换帧

面板「替换」上传的图、以及你直接覆盖磁盘上的 `segNN_{start,end}_manual.png`，
都会在入口处做一次「等比 cover 裁切 → resize 到任务分辨率」：

- `director.py` 的 replace 路由里叫 `_normalize_keyframe_to_job()`；
- runner 读取手动帧时叫 `manual_keyframe(..., config)`。

所以随便丢一张 4:5 截图、PS 过的图、别处生成的图进去都行，不用自己先裁。
已经对齐过的会原地跳过（比对尺寸，不重复裁）。

## 提示词模板

**首帧**（空 latent 版）：

```text
9:16 竖构图全身照片：<人物与动作描述>。
<光线与背景描述>。
人物身份、脸型、五官、发型和服装与图1、图2保持一致（同一个人）。
真实摄影，自然皮肤纹理，全身完整入镜，头顶和鞋底不被裁切，画面中只有一个人，无文字水印。
```

**尾帧**（以首帧为 image 1 派生）：

```text
保持图1中同一个人物、同一场景、同一机位、同一光照方向和同一镜头焦段，改变人物的肢体姿态：
<具体动作，写清角度和手的位置>。
双腿保持原来的盘坐姿势，膝盖位置不发生移动。
头部仍然朝向镜头，脸与图2一致，双唇自然闭合、嘴角平直，不微笑、不露牙、不张嘴。
人物完整入镜，头顶上方保留空间，鞋底不被裁切。保持真实的皮肤纹理和原有光线。
不改变服装款式和颜色，画面中只有一个人，无文字水印。
```

**视频**：

```text
<Picture1>、<Picture2> 分别定义本段首帧和尾帧构图。<Picture3> 定义<女主角>的身份、脸型、五官、发型和服装。
<女主角>从首帧姿态缓慢过渡到尾帧姿态：<动作分解描述>。
动作在整个 5 秒内匀速、连续地完成，最后一帧才达到尾帧姿态，中途不停顿、不静止。
9:16 竖屏完整全身构图，固定全身机位，摄影机不推进、不后退、不缩放、不摇晃，头顶、身体和鞋底始终完整入镜。
面部稳定，双唇自然闭合，嘴角平直；不微笑、不露牙、不张嘴、不咧嘴，嘴巴绝不突然放大。
只有上半身和手臂在动，下半身与床单保持稳定，不穿模、不跳帧、不切镜，无文字、字幕和水印。
```

## 5 秒能装多少动作

| 幅度 | 例子 |
| --- | --- |
| ✅ 稳 | 迈 2–3 步、上身前后倾、抬手、重心左右移、坐姿转向 30° |
| ⚠️ 勉强 | 完整转身 180°、站起、蹲下 |
| ❌ 必崩 | 站到躺、跨房间位移、换场景、脱外套 |

动作再大就分两跳：F0 → F0.5 → F1，每段 5 秒。

## 其它注意

- `LoadImage` **只读 ComfyUI 的 input 目录**（现为 `D:\Comfy-Desktop\ComfyUI-Shared\input`），
  Qwen 出图在 output，必须先复制过去才能接进 H3；
- 视频任务由 `H3SingleClipDirector` 起独立进程跑，**ComfyUI 重启会导致任务连接失败**，需要重新提交；
- 视频产物按 `config.json` 的 `comfy_output_dir` 落盘（现为 `ComfyUI-Shared/output/h3_single_clip`）。
  注意个别节点（VHS 一类）会用 ComfyUI 服务端自己的 output 目录，所以安装目录 `output/` 下
  偶尔会有残留文件——清理时两边都看一眼；
- 中间过渡帧偶尔会出现张嘴，属于 H3 的老问题，提示词里加「嘴巴绝不突然放大」可以压制一部分。

## 人工接管：首尾帧不一定非要模型生成

上面讲的是「模型出首尾帧」。实际做长视频时更常用的是**人工/外部图覆盖**：
Qwen 出图只是起点，你可以随时用自己的图替换，Director 不会再拿 H3 去重画它们。

覆盖机制在任务目录的 `.state.json` 里：

```json
"keyframe_overrides": {
  "2": { "start": ".../keyframes/seg02_start_manual.png",
         "end":   ".../keyframes/seg02_end_manual.png" }
}
```

命中的那一侧 `*_source` 记为 `manual`、`*_sha1` 记为 `manual:<路径>`，出视频时直接用文件，
不跑生成。写入方式有三种：

| 方式 | 怎么用 | 会不会覆盖你手动放的图 |
|---|---|---|
| `pipeline.py push` | 把 `state` 里的首尾帧批量灌成 `segNN_{start,end}_manual.png` | ——（它就是写手动帧的） |
| 面板「替换」 | 上传一张图顶掉那一侧，**旧图存进 `*_original`** | 会，且可还原 |
| 面板「重画」 | 清 `sha1` + 加 `attempt`，下次关键帧阶段用 AI 重出这一张 | 不会 |

**「还原」只还「替换」留下的那份原图**（`*_original`），不跑 GPU、不排队重画。
`push` 灌进来的帧没有原图，所以那一侧「还原」是灰的——要按提示词重出就点「重画」，
要换图就点「替换」。

**改提示词不会自动重画已有帧**：面板里「保存并重画关键帧」只清掉该段**非 manual** 的帧；
两侧都是 manual 时会拒绝并提示原因。想让某段回到 AI 版本，先「还原」再「重画」。
