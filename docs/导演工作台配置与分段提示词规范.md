# SelfLift 导演工作台 · 配置与分段提示词规范

> **这份文档是给「其他大模型」看的。** 目标：让模型按本规范产出可直接导入工作台的**视频分段**。
> 一句话原则：**你只负责「内容层」（片名 / 故事梗概 / 分段正文），不要碰「约束层」（head / tail / 秒数 / 画幅 / 画质 / 工作流）。**

---

## 0. 先理解分层（最重要）

工作台的配置分成两层，职责严格分开：

| 层 | 存什么 | 谁维护 | 你要不要写 |
|---|---|---|---|
| **约束层** | 全局 `head` / `tail`：人物身份绑定、场景空镜锚定、真实首帧继承、空间关系与轴线、表情/姿态/眼神、身体动态、发衣材质、物体完整性与接触、背景人物、画风与禁止项 | 工作台统一一份，所有片共用，跑片时**自动注入** | **不要写**，写了也会被忽略 |
| **内容层** | 片名 `title`、故事梗概 `story`、参考图 `ref_images`、空镜板 `bg_plate`、分段 `segments[]` | 每部片不同 | **这才是你要产出的** |
| **本片参数** | 每段秒数 `seconds`、画幅 `aspect_ratio`、分辨率 `megapixels`、画质 `quality`、声音 `audio`、接缝方式 `join` | 网页上按片设置 | 不用写，网页里选 |

**推论：** body 里**不要重复** head/tail 已经覆盖的东西（不换人 / 不融脸 / 严格继承上段尾帧 / 段尾收住 / 眨眼频率 / catchlight / 画风质感 / 禁止项）。重复只会稀释权重。

## 1. 你要产出的内容层 JSON

### 1.1 字段表

```jsonc
{
  "title": "片名",                 // 必填，会进文件夹名与成片名
  "story": "本片设定",             // 强烈建议：1–3 句，人物外形 / 场景 / 色调 / 当前情境与关系
  "ref_images": ["人物参考图路径"], // 一人一张；顺序 = {pic:1}, {pic:2} …
  "bg_plate_path": "空镜板路径",   // 全片唯一的场景参考（可选但强烈建议）
  "segments": [
    {
      "title": "段标题",           // 可选，卡片上显示
      "body": "分段正文（核心）",   // 必填，见第 3、4 节
      "link": {                    // 可选，默认 chain
        "mode": "chain",           // chain=像素承接上段尾帧 / transition=独立生成+转场
        "transition": "dissolve"   // 仅 transition 用：dissolve / black / cut
      }
    }
  ]
}
```

### 1.2 不要写这些字段

`head` / `tail` / `seconds` / `fps` / `megapixels` / `aspect_ratio` / `quality` / `workflow` / `clip_name` / `length` / `join_mode` —— 全部由工作台/全局配置接管，上传时**静默忽略**。

`id` / `seed` / 首尾帧路径也不用写，系统自动分配。

### 1.3 最小示例

```json
{
  "title": "雨夜相逢",
  "story": "短发女生，白外套，雨夜街道，冷蓝调。她刚从便利店出来，在等一个没来的人。",
  "ref_images": ["refs/heroin.png"],
  "bg_plate_path": "refs/street_plate.png",
  "segments": [
    { "title": "走出便利店", "body": "第一镜\n动作：…\n[机位]：…\n[光线]：…\n[场景]：…" },
    { "title": "雨中等候", "body": "第一镜\n动作：…\n[机位]：…\n[光线]：…\n[场景]：…", "link": { "mode": "chain" } }
  ]
}
```

> 也支持「只给一整段长文本」：工作台会按 空行 → 分隔线 → 句号 自动切段（约 130 字/段）。想精确控制请自己分好 `segments`。

## 2. 分段长度与拆镜

- **每段秒数全片统一**（默认 8 秒），在网页建片时定；分镜里不用写。
- 一镜 ≈ 3–6 秒；镜头数 ≈ `round(秒数 / 5)`（8s ≈ 2 镜，12s ≈ 2–3 镜，4s ≈ 1 镜）。
- 长度**按内容自然发挥**：8 秒段常见 600–1000 字，软上限约 1200 字（再长会超模型上下文）。
- 一段只推进**一条动作线**；不要在一段里塞多场戏。

---

## 3. body 的结构：镜 × 四块

一段 body = 一个**镜头故事板**。按顺序编号 `第一镜 / 第二镜 / 第三镜 …`，**每一镜**都写下面四块（块之间空一行）：

```
第一镜
动作：…

[机位]：…

[光线]：…

[场景]：…

At 00:04.5, …

第二镜
动作：…
[机位]：…
[光线]：…
[场景]：…
```

| 块 | 写什么 |
|---|---|
| **动作** | 谁、从哪到哪、身体哪个部位在动、怎么启动又怎么收住。**逐步扩写**（见 3.1） |
| **[机位]** | 位置 / 高度 / 侧别 / 景别 + 运动（**1 个主运镜**，见 3.4） |
| **[光线]** | 方向 + 质量 + 色温 + 光源（不要只写「氛围感」） |
| **[场景]** | 本镜用得到的物件与方位，只写人与物件的接触关系；多人必写左右/朝向/遮挡 |

> `At 00:SS.mmm, …` 只用来标**一镜内部**的细微节拍（起幅→动作→收住），严格递增、落在段时长内。**跨镜切换用新的「第N镜」标签，不要用 At。**

---

### 3.1 动作：必须逐步扩写（不要一句话带过）

把一条动作线拆成 **3–6 个有序步骤**：`起势 → 过渡 → 发力/位移 → 缓冲 → 收住`。
每一步都写清 **「哪个部位 + 朝哪 + 多大幅度 + 落到哪」**，用「先…然后…接着…再…最后」串成一段自然的连续动作。

- ⚠️ H3 只吃「**持续、缓慢、可见**」的位移。**快动作 / 猛地转身 / 快速奔跑**出不来，只会卡顿。
- 一镜只推进一条动作线，但这条线要写满。

正例：

> 先，右手手指抵住玻璃门把手，手腕发力缓慢向外推开约 45°；然后左脚脚尖先探出，踩进湿滑的积水路面，重心前移；接着右腿跟进跨出门槛，膝盖微屈缓冲落地；再，颈部带动头部缓缓抬起，视线由地面雨渍上移；最后下巴收住，目光定格在雨幕中，身体静止，只有衣角轻颤。

---

### 3.2 表情与姿态：每镜必写（防「木头人」）

H3 最容易把角色拍成雕塑。**每一镜**都必须写「当前主人公」的：

- **表情**：视线落点、眼睑/瞳孔状态、眉头眉间、唇角/唇线、下颌/吞咽/呼吸。给出情绪支撑（期待 / 紧张 / 克制 / 失落 / 警觉…），但用**克制的微表情**，不夸张、不舞台化。
- **姿态**：重心落在哪只脚、脊柱/肩/颈的松紧、手的位置与手指状态、腿脚站位。写清身体怎么承重、哪里发力、哪里放松。
- **要随动作变化**：起势时什么表情 → 结束时什么表情，不是一句静态标签。

❌ 禁止：面无表情 / 木然 / 呆滞 / 空洞凝视 / 像木头或雕塑般静止。主角不能只是「站着 / 走着 / 转身」却不带任何表情与身体状态。

正例：

> 她的表情是克制后的失落：眉头轻蹙但不过分紧锁，唇角抿成一条平直的线，呼吸稍显急促，眼睑低垂又抬起，目光始终没有游移。重心落在右脚，左肩微微前扣，右手手指无意识地抠着外套下摆。

---

### 3.3 眨眼：硬规则（实测）

- **≥5 秒**的段：**整段合计 1 次**眨眼（≤10 秒；>10 秒最多 2 次；**不要每镜都眨**）。
- 固定写法：`很快地眨了一下眼，眼睑迅速合拢又立刻睁开（约 0.5 秒）`，放在视线转移或停顿的间隙里。
- **必须**写一句：`眼睛正常睁开、看着前方`（防 H3 默认越眯越垂）。
- ❌ 禁写「缓慢闭上双眼」（会被拉成约 2 秒的表演级闭眼，不是眨眼）。
- ❌ 禁写「每隔 N 秒眨一次」这种频率句（H3 不响应，实测 5 秒内 0 次）。
- **<5 秒**：可省略眨眼，但仍写「眼睛正常睁开」。

> 眨眼必须写成 body 里的**具体动作**，写在全局 head 里的频率句是无效的。

---

### 3.4 机位：专业运镜词库（一镜一主运镜）

优先用专业术语，而不是「镜头动一下」。**一组镜头只选 1 个主运镜**，最多再加 1 个轻微修饰。

| 类别 | 可用词 |
|---|---|
| 景别 | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写 / 过肩 / 主观 POV |
| 角度 | 平视 / 俯拍(高机位) / 仰拍(低机位) / 顶拍 / 荷兰角(倾斜) / 背拍 / 越肩 |
| 运动 | 推(dolly in) / 拉(dolly out) / 摇(pan) / 移(truck) / 升降(crane·pedestal) / 跟拍(follow) / 环绕(arc) / 滑轨(slider) / 手持(handheld) / 斯坦尼康(steadicam) / 变焦推拉(dolly zoom) / 航拍(aerial) |
| 修饰 | 缓推 / 急推 / 匀速 / 加速 / 减速 / 推进半程停在… |
| 焦点 | 浅景深 / 深景深 / 移焦(rack focus) / 跟焦 |

**H3 可用性红线**：只吃得下「持续、缓慢、平稳」的运动。甩镜 / 急推 / 快速环绕会卡顿，别写它做不出的。

**禁自相矛盾/堆叠**：

- 反例（错）：「固定滑轨跟拍（follow），持续向前缓推（dolly in）」——固定和跟拍、推进互相打架。
- 正例（对）：「固定机位，近景特写，仅极轻微手持呼吸感」 / 「滑轨跟拍（follow），沿人物斜后方缓慢前移」 / 「缓推（dolly in）从中景过渡到近景」。

---

### 3.5 具体压过空泛

把「电影级 / 氛围感 / 绝美 / cinematic / atmospheric」换成可执行的：**光的方向与质感、材质、精确颜色、机位运动（类型+幅度+速度）、具体物理声**（布料摩擦、脚步、呼吸、金属轻响、水滴）。

---

## 4. 占位符 `{pic:N}`（必须一字不差）

- 人物用 `{pic:1}` / `{pic:2}` … 指代，工作台会按本段实际接线自动换算成真实编号。
- 只引用**已经给了**的图；**不要新造**编号。
- `{pic:plate}` = 空镜板，body 里一般不用；`{pic:first}` = 本段首帧。
- **绝不写 `<Picture N>` / `<Video N>` / `<Audio N>` / `<Subject N>`** —— 工作台只认 `{pic:N}`。
- 链式段的首帧会占掉编号、人物整体后移一位，所以**不要写死** `<Picture 1>`，写 `{pic:1}` 就对了。

---

## 5. 连续性与接缝

- **chain（默认，像素承接）**：段首约 0.5 秒沿上段真实尾帧的轨迹**自然继续**（不重新起步、不重置姿势）；段尾约 0.5 秒动作自然收住，形成可继承的最后一帧。
- **transition（独立+转场）**：本段独立生成，靠 `transition`（dissolve/black/cut）拼接，不强制接上段像素。
- **同一片方向锁定**：人物朝哪、摄影机在哪个侧别、不跨 180° 轴线、不无故换边——全片一致。
- 可选「段级 head」：写了会**整段覆盖**全局 head，所以必须把全片统一约束逐字复制进去；一般不建议写。

---

## 6. 多人镜头

- 参考图只给「这个人长什么样」，**不给「他们怎么站」**。
- 关系必须写进 body：谁在画面左/右、各自朝向、有没有接触与遮挡，一个都不能省。
- 服色/发色要明显区分，否则链式多段越跑越同化。
- 人多脸小：0.5MP 下用中近景，或把分辨率提到 0.8–1.0MP。
- ⚠️ 不要把多人拼在一张参考图里（每张脸都会糊，还会把「并排」当模板）。

示例：

> `{pic:1}` 的女生站在画面左侧、面朝右；`{pic:2}` 的男生在右侧、半侧身面向她，右手搭在她左肩上，女生左肩被遮住一部分。

---

## 7. 动作参考视频（可选）

- 软参考：只接管**动作节奏 / 朝向 / 景别 / 机位**，不接管场景（被空镜锁）和画风（被提示词控）。
- 时长 2–15 秒。**比段短** → 只压住开头，后段自由生成，容易「动作做完就停住」。
- 8 秒段建议给 **6–8 秒**的参考最稳；只有 3 秒就考虑把这一段缩到 3–4 秒。
- 挂参考视频会拖慢约 **80%**；参考音轨不参与生成。

---

## 8. 分辨率 / 画质 / 声音（网页上按片设置）

| 项 | 建议 |
|---|---|
| 画幅 `aspect_ratio` | 9:16 竖屏优先竖构图、中近景/特写、留好头顶空间；16:9 可做更宽的横移与环境 |
| 分辨率 `megapixels` | 8GB 显存建议 0.5MP；多人或要脸清晰度提到 0.8–1.0MP（更慢） |
| 画质 `quality` | fast（省时）/ standard / high（细节最好，换档位等于换采样轨迹，同 seed 也会变） |
| 声音 `audio` | `off`（默认，产物**无音轨**）/ `native`（保留 H3 原声，音质一般） |

⚠️ 改画幅 / 分辨率 / 画质 / 声音 → **全片标记需重出**。

---

## 9. 工作台内置「提示词优化器」（了解即可）

- 每段卡片有「优化」按钮：把**原提示词**发给本地 LM Studio（Qwen3.5），结果写进独立的 `optimized_body`，跑片时**优先使用优化后内容**，原文保留。
- 优化器会自动带上：本片故事梗概、画幅/分辨率、段时长与镜头数。
- 优化器输出仍是本文第 3 节的「镜 × 四块」；并且后端会**兜底补**「眼睛正常睁开、看着前方」和 ≥5s 的一次快速眨眼。

## 10. 交付前自检清单

- [ ] 只输出**内容层**（没有 head / tail / 秒数 / 画幅 / 画质）？
- [ ] 每段都有 `title` + `body`；`body` 是「第N镜 + 动作/[机位]/[光线]/[场景]」？
- [ ] 每镜都写了**表情 + 姿态**，且随动作变化？（没有木然/呆滞/空洞凝视）
- [ ] 一段只推进一条动作线？没有快动作/猛转身/快速奔跑？
- [ ] ≥5s 的段有 **1 次**快速眨眼 + 「眼睛正常睁开、看着前方」？没有频率句/「缓慢闭上」？
- [ ] [机位] 只有 **1 个主运镜**，无「固定+推进」这类矛盾，且 H3 做得动（缓慢平稳）？
- [ ] 多人镜写了左右/朝向/接触/遮挡？
- [ ] `{pic:N}` 只引用了已给的图，没有 `<Picture N>`？
- [ ] 没有「电影级 / 氛围感 / 绝美」这类空泛词？

## 11. 可直接粘贴的系统提示（给其他大模型）

```
你是 MiniMax H3 视频模型的资深分镜师。请把用户的想法写成「可导入 SelfLift 导演工作台」的视频分段，只输出内容层 JSON（title / story / ref_images / bg_plate_path / segments[]），不要输出 head/tail/秒数/画幅/画质。

硬规则：
1) 每段 body 必须是「镜 × 四块」：按 第一镜/第二镜… 编号；每镜依次写 动作、[机位]、[光线]、[场景]，块间空一行；必要时用 At 00:SS.mmm 标一镜内节拍。
2) 动作逐步扩写：起势→过渡→发力/位移→缓冲→收住，3–6 步，每步写「部位+方向+幅度+落点」，用「先…然后…接着…再…最后」串起来。只写持续、缓慢、可见的动作；禁快动作/猛转身/快速奔跑。
3) 每镜必写当前主人公的表情（视线/眼睑瞳孔/眉/唇角/下颌/呼吸）与姿态（重心/脊柱肩颈/手指/腿脚），并随动作变化；禁面无表情、木然、呆滞、空洞凝视、雕塑静止。
4) 眨眼：整段≥5s 只写 1 次「很快地眨了一下眼，眼睑迅速合拢又立刻睁开（约0.5秒）」，并写「眼睛正常睁开、看着前方」；禁「缓慢闭上」和「每隔N秒眨一次」。<5s 只写眼睛正常睁开。
5) [机位] 用专业运镜术语（dolly in/out、pan、truck、crane、follow、arc、slider、handheld），1 镜只 1 个主运镜，禁矛盾堆叠，只写 H3 做得出的缓慢平稳运动。
6) [光线] 写方向+质量+色温+光源；[场景] 只写本镜用到的物件与接触关系；多人必写左右/朝向/接触/遮挡。
7) 具体压过空泛：不要「电影级/氛围感/绝美」，要写光的方向质感、材质、颜色、机位类型+幅度+速度、具体物理声。
8) 人物用 {pic:1}/{pic:2}… 指代，只能引用已给的图；绝不写 <Picture N>。
9) 不重复全局约束（不换人/不融脸/继承上段尾帧/段尾收住/画风禁止项），那些工作台会自动注入。
10) 输出纯 JSON，不要 Markdown 代码块外的解释。
```

## 12. 完整示例（2 段 × 8 秒，9:16 竖屏）

```json
{
  "title": "雨夜相逢",
  "story": "短发女生，白外套，雨夜街道，冷蓝调。她刚从便利店出来，在等一个没来的人。",
  "ref_images": ["refs/heroin.png"],
  "bg_plate_path": "refs/street_plate.png",
  "segments": [
```
