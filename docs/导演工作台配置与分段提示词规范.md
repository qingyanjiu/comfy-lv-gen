# SelfLift 导演工作台 · 配置与分段提示词规范

> **这份文档是给「其他大模型」看的。** 目标：让模型按本规范产出可直接导入工作台的**视频分段**。
> 一句话原则：**你只负责「内容层」（片名 / 故事梗概 / 分段正文），不要碰「约束层」（head / tail / 秒数 / 画幅 / 画质 / 工作流）。**

---

## 前置：规范体系与规则优先级（先读这一节）

这套体系由四份文件组成，**职责不同、不可互相替代**。改任何一份前先确认它管的是哪一层：

| 文件 | 管什么 | 谁读它 |
|---|---|---|
| **本文档**（配置与分段提示词规范） | JSON 字段契约、内容层/约束层分层、body 四块结构、占位符写法；§11 是**给外部大模型生成分镜用的 S-1 V2 系统提示** | 人 + 生成分镜的大模型 |
| **segment编写规范.md** | body 怎么写才出片：动作/机位/景别像素账、实测能力清单、蒙太奇 §十三、后半衰减等**实测规则** | 人（写分镜/调片时查） |
| **视频生成提示词规范.md** | 全局 head/tail 的约束措辞（身份/场景/首帧/表情等） | 人（改共用约束模板时查） |
| **prompt_optimizer_system.txt** | 优化器把粗糙 body 改写成 H3-ready body 时遵循的规则 | 本机的 Qwen3.5 优化器 |

**S-1 是哪份？** 就是本文档 §11 的「可直接粘贴的系统提示」。它是给外部大模型（GPT/Claude 等）一次性生成整部分镜用的；优化器则是逐段精修。两者是「先规划、后精修」的关系，规则必须一致。

### 规则冲突时的优先级（从高到低）

当两条规则打架，**按这个顺序取舍**，不要两条都照做：

1. **不矛盾 / 可执行优先**：任何动作、机位、场景、光线描述若互相冲突（如「固定机位」又「推进」、动作写「原地不动」而 `[场景]` 写「相向行走」），优先改成自洽的一条。见 segment 规范 §13.10。
2. **H3 实测能力边界优先**：专业电影术语如果 H3 做不出（rack focus / 甩镜 / 急推 / 段内切镜），改用实测生效的写法（缓推 / 横移 / 前景遮挡 / 纵深走位）。见 segment 规范 §13.8。**理论正确但本机做不出 = 错。**
3. **人物与空间连续性优先**：左右位置、朝向、身份、服装、关键道具、180° 轴线，宁可牺牲运镜花样也要保持连续。
4. **景别决定细节优先**：远景写微表情、给 3px 的马腿写「四蹄交替」都是无效字数。先算子，再决定写什么。见 segment 规范 §4.1 / §13.9。
5. **导演表达优先于格式凑数**：为凑字数重复人物外观/全局约束、为显专业堆运镜术语，都会稀释真正重要的动作与镜头。
6. **格式规范兜底**：字段、占位符、JSON 合法性是硬底线，但它是容器，不是目的——满足前五条之后再校验格式。

一句话：**先不自相矛盾 → 再做得到 → 再保连续 → 再算像素 → 最后才谈好看和格式。**

### 关于篇幅与节拍

- 正文长度由动作、构图和接触关系决定，没有统一的最低字数。
- 时间点只用来描述已经存在的动作阶段；不要按时长公式补镜头、补动作或补字数。
- 超过约 1200 字仍可能挤占模型上下文。优先删重复约束和无关形容词，保留动作、机位、光线和关系。

## 0. 先理解分层（最重要）

工作台的配置分成两层，职责严格分开：

| 层 | 存什么 | 谁维护 | 你要不要写 |
|---|---|---|---|
| **约束层** | 全局 `head` / `tail`：人物身份绑定、场景空镜锚定、真实首帧继承、空间关系与轴线、表情/姿态/眼神、身体动态、发衣材质、物体完整性与接触、背景人物、画风与禁止项 | 工作台统一一份，所有片共用，跑片时**自动注入** | **不要写进 body**。要改就在网页「提示词约束」里改：「更新模板（所有片）」改共用；「更新本篇（只这一片，不动模板）」只改当前部片 |
| **内容层** | 片名 `title`、故事梗概 `story`、参考图 `ref_images`、空镜板 `bg_plate`、分段 `segments[]` | 每部片不同 | **这才是你要产出的** |
| **本片参数** | 每段秒数 `seconds`、画幅 `aspect_ratio`、分辨率 `megapixels`、画质 `quality`、声音 `audio`、接缝方式 `join` | 网页上按片设置 | 不用写，网页里选 |

**推论：** body 里**不要重复** head/tail 已经覆盖的东西（不换人 / 不融脸 / 严格继承上段尾帧 / 段尾收住 / 眨眼频率 / catchlight / 画风质感 / 禁止项）。重复只会稀释权重。

**人物名字的写法：** 名字直接写，**不要加尖括号**。`<...>` 在 H3 里是结构化标签（只认 `<Picture N>` / `<Video N>` / `<Audio N>` / `<Subject N>`），写成 `<某某>` 不是合法标签，名字不会生效，还可能触发严格标签校验报错。正确例：`<Picture {pic:1}> 为第一位人物参考，人物是某某，严格绑定其脸型…`

## 1. 你要产出的内容层 JSON

### 1.1 字段表

```jsonc
{
  "title": "片名",                 // 必填，会进文件夹名与成片名
  "story": "本片设定",             // 强烈建议：1–3 句，人物外形 / 场景 / 色调 / 当前情境与关系
  "ref_images": ["人物参考图路径"], // 一人一张；顺序对应 <Picture {pic:1}>, <Picture {pic:2}> …
  "bg_plate_path": "空镜板路径",   // 全片唯一的场景参考（可选但强烈建议）
  "segments": [
    {
      "title": "段标题",           // 可选，卡片上显示
      "cast": "本段出场人物（可选）", // 逐段不同的「谁在场 + 是几号图 + 本段外观状态」，见 3.6
      "body": "分段正文（核心）",   // 必填，见第 3、4 节
      "link": {                    // 可选，默认 chain
        "mode": "chain",           // chain=像素承接上段尾帧 / transition=独立生成+转场
        "transition": "dissolve"   // 仅 transition 用：dissolve / black / cut
      }
    }
  ]
}
```

### 1.2 不要写这些字段

`head` / `tail` / `seconds` / `fps` / `megapixels` / `aspect_ratio` / `quality` / `workflow` / `clip_name` / `length` / `join_mode` —— 全部由工作台/全局配置接管，上传时**静默忽略**。

`id` / `seed` / 首尾帧路径也不用写，系统自动分配。

### 1.3 最小示例

```json
{
  "title": "雨夜相逢",
  "story": "短发女生，白外套，雨夜街道，冷蓝调。她刚从便利店出来，在等一个没来的人。",
  "ref_images": ["refs/heroin.png"],
  "bg_plate_path": "refs/street_plate.png",
  "segments": [
    { "title": "走出便利店", "body": "第一镜\n动作：…\n[机位]：…\n[光线]：…\n[场景]：…" },
    { "title": "雨中等候", "body": "第一镜\n动作：…\n[机位]：…\n[光线]：…\n[场景]：…", "link": { "mode": "chain" } }
  ]
}
```

> 也支持「只给一整段长文本」：工作台会按 空行 → 分隔线 → 句号 自动切段（约 130 字/段）。想精确控制请自己分好 `segments`。

## 2. 分段长度与拆镜

- **每段秒数全片统一**，在网页建片时定；分镜里不用写。
- 一段对应一次连续生成，默认只做一个镜头。段内切换景别或机位会降低身份、道具与空间稳定性。
- 想要 10 秒左右的电影式组接，使用 3 段 × 3–4 秒，以 `transition: cut` 硬切拼成一支片；每段独立锁定演员、空间方向和关键道具。
- 一段只推进**一条动作线**；镜头数由导演明确指定，不按秒数自动推导。

---

## 3. body 的结构：镜 × 四块

一段 body = 一个**镜头故事板**。按顺序编号 `第一镜 / 第二镜 / 第三镜 …`，**每一镜**都写下面四块（块之间空一行）：

> ⚠ **body 里不写人物长相、服装、画风、禁止项。** 人物是谁、本段穿什么 → 每段的 `cast` 字段（见 3.6）；全片通用的身份绑定 → 共用 `head`；画风与禁止项 → `tail`。都写进 body 只会互相打架。
> 判断标准：**这一段发生了什么** → body；**这一段有谁在场、是什么状态** → `cast`；**这部片是什么样** → `story`；**所有片都要遵守什么** → 共用 `head` / `tail`。

```
第一镜
动作：…

[机位]：…

[光线]：…

[场景]：…

At 00:04.5, …

第二镜
动作：…
[机位]：…
[光线]：…
[场景]：…
```

| 块 | 写什么 |
|---|---|
| **动作** | 谁、从哪到哪、身体哪个部位在动、怎么启动又怎么收住。**逐步扩写**（见 3.1） |
| **[机位]** | 位置 / 高度 / 侧别 / 景别 + 运动（**1 个主运镜**，见 3.4） |
| **[光线]** | 方向 + 质量 + 色温 + 光源（不要只写「氛围感」） |
| **[场景]** | 本镜用得到的物件与方位，只写人与物件的接触关系；多人必写左右/朝向/遮挡 |

> `At 00:SS.mmm, …` 只用来标**一镜内部**的细微节拍（起幅→动作→收住），严格递增、落在段时长内。**跨镜切换用新的「第N镜」标签，不要用 At。**

---

### 3.1 动作：按复杂度说明（不要一句话带过，也不要机械拆解）

简单动作写 1–2 个自然阶段，普通动作写 2–4 个，复杂交互才写 3–6 个阶段。写清方向、幅度、接触和结束状态即可；一个自然手势不需要拆成连续的“手指 / 手腕 / 小臂”清单。

- ⚠️ H3 只吃「**持续、缓慢、可见**」的位移。**快动作 / 猛地转身 / 快速奔跑**出不来，只会卡顿。
- 一镜只推进一条动作线，但这条线要写满。

正例：

> 先，右手手指抵住玻璃门把手，手腕发力缓慢向外推开约 45°；然后左脚脚尖先探出，踩进湿滑的积水路面，重心前移；接着右腿跟进跨出门槛，膝盖微屈缓冲落地；再，颈部带动头部缓缓抬起，视线由地面雨渍上移；最后下巴收住，目光定格在雨幕中，身体静止，只有衣角轻颤。

---

### 3.2 表情与姿态：在景别可见时写

H3 容易把角色拍成雕塑。脸部或身体细节在当前景别可见、且剧情需要时，写「当前主人公」的：

- **表情**：视线落点、眼睑/瞳孔状态、眉头眉间、唇角/唇线、下颌/吞咽/呼吸。给出情绪支撑（期待 / 紧张 / 克制 / 失落 / 警觉…），但用**克制的微表情**，不夸张、不舞台化。
- **姿态**：重心落在哪只脚、脊柱/肩/颈的松紧、手的位置与手指状态、腿脚站位。写清身体怎么承重、哪里发力、哪里放松。
- **要随动作变化**：起势时什么表情 → 结束时什么表情，不是一句静态标签。

❌ 禁止：面无表情 / 木然 / 呆滞 / 空洞凝视 / 像木头或雕塑般静止。主角不能只是「站着 / 走着 / 转身」却不带任何表情与身体状态。

正例：

> 她的表情是克制后的失落：眉头轻蹙但不过分紧锁，唇角抿成一条平直的线，呼吸稍显急促，眼睑低垂又抬起，目光始终没有游移。重心落在右脚，左肩微微前扣，右手手指无意识地抠着外套下摆。

#### 例外：远景不写脸（像素账，必须遵守）

表情写多细，取决于**这一镜里脸占多少像素**——远景写微表情是无效的，只会得到一张白板脸：

| 景别 | 人物占画面高 | 脸高（1344×768 下） | 该怎么写 |
|---|---|---|---|
| 大远景 / 远景 | < 40% | **10–20 px** | 只写体态、朝向、剪影、动作、兵器反光；表情最多一句「神情沉毅」。**不写五官、不写微表情、不写眨眼** |
| 全景（完整全身） | 60–85% | 40–60 px | 轮廓可见但**锁不住身份**；表情只写大方向（沉毅 / 警觉 / 疲惫） |
| 中景 / 中近景 | 脸占 1/4 以上 | 80–150 px | 微表情、视线落点、眨眼都写 |
| 近景 / 特写 | 脸占 1/2 以上 | 200 px+ | 唯一能可靠锁住这张脸的景别 |

- **要观众记住这张脸**：必须给中近景或近景。远景负责气势、近景负责身份，分开写。
- **远景里区分人物靠外形**（盔甲颜色、兵器、马匹、披风），不靠脸。
- **不要靠调高分辨率解决远景的脸**：像素翻倍只把 10 px 变 20 px，仍是白块；要到 40 px 以上需线性放大 5–6 倍（几十 MP），消费级显存做不到。
- 这是**正常现象**，不是 bug：同帧里近处的人脸清楚、远处的人脸糊白，正是模型按像素预算分配细节的结果。

---

### 3.3 眨眼：按表演需要选用

- 仅在中景以上、脸部清晰可见、又不会打断凝视或紧张动作时，才在 body 中写一次快速眨眼。
- 可用写法：`很快地眨了一下眼，眼睑迅速合拢又立刻睁开`；不要写周期频率或缓慢闭眼。
- 远景、背影、持续凝视和紧张动作镜省略眨眼与眼睛状态指令。

---

### 3.4 机位：专业运镜词库（一镜一主运镜）

优先用专业术语，而不是「镜头动一下」。**一组镜头只选 1 个主运镜**，最多再加 1 个轻微修饰。

| 类别 | 可用词 |
|---|---|
| 景别 | 大远景 / 远景 / 全景 / 中景 / 中近景 / 近景 / 特写 / 大特写 / 过肩 / 主观 POV |
| 角度 | 平视 / 俯拍(高机位) / 仰拍(低机位) / 顶拍 / 荷兰角(倾斜) / 背拍 / 越肩 |
| 运动 | 推(dolly in) / 拉(dolly out) / 摇(pan) / 移(truck) / 升降(crane·pedestal) / 跟拍(follow) / 环绕(arc) / 滑轨(slider) / 手持(handheld) / 斯坦尼康(steadicam) / 变焦推拉(dolly zoom) / 航拍(aerial) |
| 修饰 | 缓推 / 急推 / 匀速 / 加速 / 减速 / 推进半程停在… |
| 焦点 | 浅景深 / 深景深 / 移焦(rack focus) / 跟焦 |

**H3 可用性红线**：只吃得下「持续、缓慢、平稳」的运动。甩镜 / 急推 / 快速环绕会卡顿，别写它做不出的。

**禁自相矛盾/堆叠**：

- 反例（错）：「固定滑轨跟拍（follow），持续向前缓推（dolly in）」——固定和跟拍、推进互相打架。
- 正例（对）：「固定机位，近景特写，仅极轻微手持呼吸感」 / 「滑轨跟拍（follow），沿人物斜后方缓慢前移」 / 「缓推（dolly in）从中景过渡到近景」。

---

### 3.5 具体压过空泛

把「电影级 / 氛围感 / 绝美 / cinematic / atmospheric」换成可执行的：**光的方向与质感、材质、精确颜色、机位运动（类型+幅度+速度）、具体物理声**（布料摩擦、脚步、呼吸、金属轻响、水滴）。

### 3.6 本段人物 `cast`：逐段不同，单独一个字段

**每段出现谁、谁对应哪张参考图、本段什么外观状态，逐段都可能不同**，所以它不能写进全片共用的 `head`，也不建议混进 body，而是每段自己的 `cast` 字段。跑片时拼装顺序是：

```
head → cast → body → tail
```

写法：

```json
"cast": "本段出场：<Picture {pic:1}> 是吕布，紫金冠、紫金战甲、持方天画戟，位于画面右侧；<Picture {pic:2}> 是张飞，黑甲、持丈八蛇矛，位于画面左侧。本段只有这两人，关羽不出场。"
```

规则：

- **谁在场写谁**，没接线的角色一个字都别提，否则模型会硬加人。
- **本段的外观变化**（换装 / 淋湿 / 受伤 / 摘头盔）写在这里，不要去改全片 `head`。
- 只写「是谁 + 在画面哪一侧 + 本段状态」，**不写动作**——动作归 body。
- 留空 = 这一段只靠 `head` 的通用绑定（第几号图 = 第几位人物），单人戏可以不写。
- `<Picture {pic:N}>` 在这里同样有效；引用本段没接的序号会直接报错并列出实际接线。

> 为什么不能放 `head`：`head` 是全片共用的一份，在里头写「第一位是吕布」等于宣布每一段都是吕布的戏，换一部片还是那两个人。

## 4. 占位符：必须写成 `<Picture {pic:N}>`

**正确写法是 `<Picture {pic:1}>`（外层尖括号 + 内层占位符），不是裸 `{pic:1}`。**

工作台的 `{pic:N}` 只会被替换成**编号数字**：

| 你写的 | 展开后 | 结果 |
|---|---|---|
| `她看着 {pic:1}` | `她看着 2` | ❌ 变成裸数字，H3 认不出是参考图 |
| `她看着 <Picture {pic:1}>` | `她看着 <Picture 2>` | ✅ 正确绑定参考图 |

规则：

- 人物一律写 `<Picture {pic:1}>` / `<Picture {pic:2}>` …，工作台按本段实际接线自动换算编号。
- 只引用**已经给了**的图；**不要新造**编号。
- `<Picture {pic:plate}>` = 空镜板（body 里一般不用）；`<Picture {pic:first}>` = 本段首帧。
- **不要写死字面编号** `<Picture 1>`——链式段接了首帧后编号会整体后移，必须用占位符。
- 绝不写 `<Video N>` / `<Audio N>` / `<Subject N>`；视频/音频参考走单独接线。

---

## 5. 连续性与接缝

- **chain（默认，像素承接）**：段首约 0.5 秒沿上段真实尾帧的轨迹**自然继续**（不重新起步、不重置姿势）；段尾约 0.5 秒动作自然收住，形成可继承的最后一帧。
- **transition（独立+转场）**：本段独立生成，靠 `transition`（dissolve/black/cut）拼接，不强制接上段像素。
- **同一片方向锁定**：人物朝哪、摄影机在哪个侧别、不跨 180° 轴线、不无故换边——全片一致。
- 可选「段级 head」：写了会**整段覆盖**全局 head，所以必须把全片统一约束逐字复制进去；一般不建议写。

---

## 6. 多人镜头

- 参考图只给「这个人长什么样」，**不给「他们怎么站」**。
- 关系必须写进 body：谁在画面左/右、各自朝向、有没有接触与遮挡，一个都不能省。
- 服色/发色要明显区分，否则链式多段越跑越同化。
- 人多脸小：0.5MP 下用中近景，或把分辨率提到 0.8–1.0MP。
- ⚠️ 不要把多人拼在一张参考图里（每张脸都会糊，还会把「并排」当模板）。

示例：

> `<Picture {pic:1}>` 的女生站在画面左侧、面朝右；`<Picture {pic:2}>` 的男生在右侧、半侧身面向她，右手搭在她左肩上，女生左肩被遮住一部分。

## 7. 动作参考视频（可选）

- 软参考：只接管**动作节奏 / 朝向 / 景别 / 机位**，不接管场景（被空镜锁）和画风（被提示词控）。
- 时长 2–15 秒。**比段短** → 只压住开头，后段自由生成，容易「动作做完就停住」。
- 8 秒段建议给 **6–8 秒**的参考最稳；只有 3 秒就考虑把这一段缩到 3–4 秒。
- 挂参考视频会拖慢约 **80%**；参考音轨不参与生成。

## 8. 分辨率 / 画质 / 声音（网页上按片设置）

| 项 | 建议 |
|---|---|
| 画幅 `aspect_ratio` | 9:16 竖屏优先竖构图、中近景/特写、留好头顶空间；16:9 可做更宽的横移与环境 |
| 分辨率 `megapixels` | 8GB 显存建议 0.5MP；多人或要脸清晰度提到 0.8–1.0MP（更慢） |
| 画质 `quality` | fast（省时）/ standard / high（细节最好，换档位等于换采样轨迹，同 seed 也会变） |
| 声音 `audio` | `off`（默认，产物**无音轨**）/ `native`（保留 H3 原声，音质一般） |

⚠️ 改画幅 / 分辨率 / 画质 / 声音 → **全片标记需重出**。

## 9. 工作台内置「提示词优化器」（了解即可）

- 每段卡片有「优化」按钮：把**原提示词**发给本地 LM Studio（Qwen3.5），结果写进独立的 `optimized_body`，跑片时**优先使用优化后内容**，原文保留。
- 优化器会自动带上：本片故事梗概、画幅/分辨率、段时长与镜头数。
- 优化器输出仍是本文第 3 节的「镜 × 四块」；并且后端会**兜底补**「眼睛正常睁开、看着前方」和 ≥5s 的一次快速眨眼。

## 11. S-1 V2：可直接粘贴的系统提示（给其他大模型）

> 版本 V3（2026-11-18）。升级点：按 MiniMax H3 **官方提示词优化器规范**（见 `docs/官方参考/` 两份原文）对齐——新增输入边界与资产编号、保守补全策略、对白/说话人/画面文字的官方写法、官方运镜术语对照、提交前静默自检。**JSON 字段契约与 `<Picture {pic:N}>` 写法不变**——这是工作台接口，不得改。
>
> 官方六段式（Ref2VA）/三段式（FL2VA·I2VA·L2VA）整段结构由工作台的提示词优化器在 `kind=full` 时负责；本系统提示产出的是**内容层分镜 JSON**，只吸收官方的写作规则内核，不输出区段名。

```

② H3 可执行（动作/机位/景别符合它真实做得到的事）；③ 工程规范（JSON 字段正确、不与全局 head/tail 冲突）。

① 自洽可执行（动作/机位/场景/光线不得互相矛盾）→ ② H3 实测做得到（理论正确但本机做不出=错）

1) 每段 body 是「镜 × 四块」：按 第一镜/第二镜… 编号；每镜依次写 动作、[机位]、
   [光线]、[场景]，块间空一行；一镜内节拍用 At 00:SS.mmm 标。
```
