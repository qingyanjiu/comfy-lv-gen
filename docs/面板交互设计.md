# Director 节点交互改造方案（草案 v2）

> 目标：先定交互，再改代码。本文只讨论"用户怎么用这个节点"，不涉及实现细节。
> 现状问题 / 决策点 / 推荐默认值，逐条列出待确认。

---

## 一、现状交互面

### 长视频节点 `H3LongVideoDirector`
- `storyboard`：一大段手写 JSON（段数 × 每段 5~6 个字段）
- `reference_notes`：自由文本，描述 Picture 1/2 怎么用
- 数字控件：`steps` / `two_pass_steps` / `megapixels` / `final_width` / `final_height` / `keyframe_steps`
- `two_pass_mode`：跟随每段 JSON / 全部一采 / 全部二采
- `force`：全量重渲
- `reference_1..N`：参考图
- 可选：`advanced_overrides` JSON、`seed`、`randomize_seed`、`first_frame`

### 单段节点 `H3LongVideoDirectorSingle`（暂称）
- 必填：`first_frame` **+ `last_frame`** + `reference_1` + `prompt` + `seconds`
- `two_pass` 布尔、其余与长视频节点相同

---

## 二、当前交互的 7 个问题

| # | 问题 | 后果 |
|---|---|---|
| 1 | 分镜表是手写 JSON，字段多且无校验 | 拼错 key 静默失效；写作负担重 |
| 2 | 尾帧锚定隐式且**每段都发生** | ① 模型为命中尾帧姿势而"走过头再退回" ② 每段多一次 2 秒、0.6MP 草案渲染（约 9 段 = 9 次额外渲染） |
| 3 | 链式/切点用 `continue_from_previous` 表达，转场参数分散 | 用户心智模型（"这两段连不连"）与字段名不一致 |
| 4 | 执行前无预览 | 跑几小时才发现第 3 段姿势不对 |
| 5 | 质量靠手动调 3 个数字 | 每次都要重新决定 megapixels/steps/two_pass |
| 6 | UI 只能全量重渲 | 坏一段要重跑全部 |
| 7 | 单段节点 `last_frame` 必填 | 单段模式同样被强制锚定，一样会倒退 |

---

## 三、改造决策点（逐条拍板）

### D1 分镜表的输入方式
- **方案 A（推荐）**：保留 JSON，但新增「**计划预览**」——执行前把解析结果打印出来（段数/总时长/每段类型/是否锚尾帧/预计耗时），并做字段校验（拼错就报错，不许静默）
- 方案 B：改成**简化行格式**，一行一段：`秒数 | 类型 | 提示词`，节点内部解析
- 方案 C：节点内结构化输入（ComfyUI 前端做表格，工作量大、兼容性差）

> 推荐 A：改动小、不破坏已有工作流文件、能立刻消除"静默失效"和"跑完才发现错"两大痛点。

### D2 尾帧锚定改成显式四选一（**最关键的一条**）
每段增加 `end_frame` 字段，取值：

| 值 | 含义 | 何时用 | 是否额外渲染草案 |
|---|---|---|---|
| `none` | 不锚尾帧，模型自由延续 | **延续段的默认值** | 否 |
| `auto` | 现状行为：用本段 prompt 生成草案尾帧 | 需要指定落点姿势时 | 是 |
| `hold` | 尾帧 = 首帧（定格） | 需要稳住构图时 | 否 |
| `"<文本>"` | 用单独写的尾帧提示词生成 | 精确指定结束画面 | 是 |

**推荐默认值**：中间延续段 = `none`，**只有最后一段** = `auto`（收尾停住）。
收益：消除"倒退"主因 + 省掉约 9 次草案渲染。

### D3 段类型显式化
把 `continue_from_previous` / `transition_seconds` 收敛成一个 `shot` 字段：

| 值 | 含义 |
|---|---|
| `continue` | 链式：接上一段真实尾帧，无转场 |
| `cut` | 切点：独立起段，按 `transition_seconds` + `transition_mode` 加转场 |

节点顶部保留一个全局 `chain_default`（默认 `continue`），段里可覆盖。

### D4 质量档位控件
新增 `quality` 下拉，一键覆盖三个数字（手动值仍可覆盖）：

| 档 | megapixels | two_pass | two_pass_steps | steps | 用途 |
|---|---|---|---|---|---|
| 预览 | 0.2 | 关 | - | 4 | 验证分镜 |
| 标准 | 0.3 | 开 | 3 | 6 | 全量出片 |
| 精细 | 0.4 | 开 | 4~5 | 6~8 | 成品交付 |

### D5 执行前计划预览
新增 `dry_run` 开关（默认关）：打开后**只打印计划不渲染**：
```
共 10 段 / 60.0 秒 / 预计 ~N 分钟
段1  开场  6.0s  继续  end=auto   -> 需渲染草案
段2  延续  6.0s  继续  end=none   -> 无草案
...
段5  切点  6.0s  切点  转场1.0s   end=none
```

### D6 渲染范围
替代现在的 `force`：
- `render_scope`：全部 / 单段 / 区间
- `segment_from` / `segment_to`：区间端点
- `force`：是否重渲已完成的段（保留）

### D7 单段节点
- `last_frame` 改为**可选**（不接 = 不锚尾帧）
- 与长视频节点对齐：加 `quality` 档位、`two_pass` 保留

### D8 关键帧人工确认闸门（**已实现**）
把「生成首尾帧 → 生成视频」拆成两个可中断的阶段：

| 阶段 | 触发 | 结束后 |
|---|---|---|
| ① 关键帧 | 点运行（`stage = 关键帧 → 确认 → 视频`，默认） | 写 `awaiting_review`，状态变 `awaiting_review`，**不再往下跑** |
| ② 视频 | 面板点「确认关键帧，生成视频」，或 `stage = 继续生成视频` + `resume_job_id` | 复用已确认的关键帧，只渲染分段视频 |

每张关键帧三个动作（按钮字面就是这三个字）：
- **替换**：上传图片 → 存到 `<jobs_dir>/<job>/keyframes/segNN_<side>_manual.png`，写进
  `state["keyframe_overrides"]`，签名变 `manual:<path>`，**优先级高于一切缓存与生成**；
  旧图另存到 `*_original`，供「还原」用
- **重画**：清掉该帧 `*_sha1` + `keyframe_attempts[段][side] += 1`；
  下次进入阶段 ② 时重画，且 keyframe seed 加上 `attempt * 101`（否则同 seed 会画出同一张）
- **还原**：把 `*_original`（路径 / 签名 / prompt_id）放回去，**不跑 GPU、不排队重画**

不可重画的情况（按钮置灰）：链式段的开始帧（继承自上一段尾帧）、`hold` 定格尾帧。

**「还原」置灰的另一种情况（2026-11-01 修）**：`*_original` 只有「替换」才会写。
用 `pipeline.py push` 灌进来的手动帧没有原图，早期实现会走 `sha1=""` 分支把它标成
「待重画」，下次跑关键帧就偷偷重画了。现在这种请求直接 400 拒绝、**不动 state**，
面板用状态里的 `start_has_original` / `end_has_original` 把按钮置灰，并提示改用「重画」。

**关键帧卡片下方的「改词」（2026-11-01 加）**：卡片底部一行 `N 秒 · 提示词摘要 · 改词`，
点开在网格上方展开编辑器（左：首/尾帧缩略图；右：三个文本框；上：秒数），
通过 `POST /h3-long-video/script/{job}/{index}` 写回该任务 `config.json`。
顶栏同时加了任务下拉框（`GET /h3-long-video/jobs`），没有 `h3_job_id` 时自动挂最近的任务。

编辑器三个框对应 `segments[i-1]` 的 `prompt` / `start_frame_prompt` / `end_frame_prompt`：

- **主提示词**：这一段视频用；首/尾帧没单独写时也用它。
- **首帧提示词**：默认折叠（没值时收起），有值自动展开。
- **尾帧提示词**：始终显示——它是"这段结尾长什么样"的唯一入口。

留空 = 回落到主提示词（runner 里就是 `end_frame_prompt or prompt`）。
**改哪一栏只重画哪一帧**：改尾帧词只清 `end` 的 sha1、只重出尾帧，首帧原样；
改主提示词只影响没写专属词的那一侧；只改秒数一张图都不重画。
单独写了首/尾帧词的段，卡片那一行会多出 `首帧词` / `尾帧词` 徽章（悬停看全文）。

**手动帧与「连我自己放的图一起重出」**：`*_source == "manual"` 的帧不会被提示词覆盖
（`push` 灌进来的、面板「替换」上传的都算）。要在这种段上按新词重出，勾编辑器底部的
**「连我自己放的图一起重出」**（只在有手动帧时出现）——后端 `force=true` 会撤掉该侧的
`keyframe_overrides`、attempt+1，把这一帧交回 AI；不勾则只返回一句 note 说明为什么没重画。

**尾帧重画的连锁（2026-11-01 明确）**：`chain` 段的开始帧就是上一段的尾帧。改第 N 段尾帧后，
第 N+1 段的首帧必须换成新的、它的尾帧也要重出（旧尾帧是从旧首帧推出来的），一直传到链尾。
接口在响应里返回 `cascade: [N+1, ...]`，面板据此提示"后面第几段会跟着重出"。

中途那两三分钟里 state 还是旧值，为了不让人误判"继承断了"，`_job_keyframes` 对链式段：

- 首帧**一律走上一段的尾帧 URL**（`start_inherited=true`），上游一变下游立刻跟着变；
- 若记录里的文件还不是上一段当前那张，再置 `start_stale=true`，卡片显示橙色**「待同步」**。
跑完整条链后标记自动消失。判断继承是否成立只看「继承 / 待同步」，二者都表示链没断。

**自由尾帧（`free_end`）**：该段不锚尾帧，卡片上「结束」一侧显示虚线占位「自由尾帧」，
只留一个「替换」按钮（上传图即可把它变回固定锚点）；它下一段的「开始」一侧在视频渲完前
显示「待定首帧」。这两种占位卡不是错误状态，也不阻塞 `--stage videos`。
不想暂停：`stage = 一次跑完（不暂停）`。

**重载之后按钮不能消失（已修）**：早先横幅只看 `state.awaiting_review`，于是「关键帧已经
生成完、但视频阶段挂掉」的历史任务（比如 ComfyUI 重启后被标成 `interrupted`，或闸门之前
的老任务根本没有这个字段）重新加载后一个按钮都没有，只能从头再跑一遍。

现在状态接口多返回三个字段，由服务端判断「该给什么动作」：

| 字段 | 含义 |
|---|---|
| `segment_total` | 这个任务应该产出多少段（config.segments → review_segments → keyframe_total → 现有帧数） |
| `keyframes_ready` | 每段首尾帧都在磁盘上、且没有待重画的帧 |
| `review_state` | `gate`（等确认）/ `resume`（帧齐了但视频没跑完）/ `keyframes`（帧不全，可补齐）/ `null`（没事可做） |

面板按 `review_state` 切文案与动作，且 worker 活着（`running`/`scheduled`）时按钮置灰：

| `review_state` | 横幅标题 | 按钮 | 动作 |
|---|---|---|---|
| `gate` | 关键帧已生成，等待你确认 | 确认关键帧，生成视频 | `POST /h3-long-video/resume/<job>` |
| `resume` | 关键帧已就位，可以继续生成视频 | 继续生成视频 | `POST /h3-long-video/resume/<job>`（关键帧全部复用，不重画） |
| `keyframes` | 关键帧还没生成完 | 继续生成关键帧 | `POST /h3-long-video/keyframes/<job>`（新增，已画好的不重画） |

`keyframes` 这一档只在任务确实跑过又失败/中断时出现（`failed` / `interrupted`），
`unknown`（从没跑过）不会冒出按钮，避免和 ComfyUI 自己的执行按钮打架。

## D9 空间问题：面板塞不下（已实现）

节点里的预览面板被画布尺寸锁死（560px 高），4 段 × 2 帧根本铺不开，横向滚动还会把卡片藏到视野外。
四层解法，从"不改结构"到"彻底跳出画布"：

| 层 | 做法 | 效果 |
|---|---|---|
| ① 自动换行 | 关键帧 / 分段从横向滚动改成 `grid + auto-fill` | 不再有卡片藏到右边，宽度变化自动改列数 |
| ② 密度压缩 | 图片高度改自适应（`height:auto` + `max-height`）、横幅收成一行、按钮 / 标签统一短词 | 820px 宽时 4 段一屏看完，不裁切 |
| ③ 高度可拖 | 面板底部拖柄改高度，写 `node.properties.h3_panel_height` | 想多看就拉高，双击复位 560 |
| ④ 全屏 | `⛶ 全屏` 把面板搬进 `position:fixed` 遮罩（Esc 退出） | 彻底不受画布限制，1400px 宽一屏 4 段大图 |
| ⑤ 独立窗口 | `⧉ 独立窗口` 把面板搬进 `window.open` 的新窗口，可拖到第二块屏 | 画布完全不遮挡；关窗自动搬回 |
| ⑥ 灯箱 | 点关键帧 / 卡片上 `⤢` 打开整屏播放器，←/→ 在同组内翻页 | 单帧能放大到整屏审片，关键帧灯箱里可直接替换/重画/还原 |

实现要点：
- 全屏 / 独立窗口共用一套「搬出去 + 原位占位块 + 搬回来」逻辑（`detachRoot` / `reattachRoot`）；
  独立窗口用 `setInterval` 检测 `popup.closed`，`window.close()` 触发 `beforeunload` 时先清 `node.h3DirectorMode`
  再关，避免递归重入把节点搬两次
- 面板进独立窗口时**样式要复制**（`copyPanelStyles`），灯箱也要跟着搬到同一个 `document`
  （`moveLightboxToDoc`），否则在窗口里点图没反应
- 灯箱是页面级单例，支持 `image` / `video` 两种媒体；`syncLightbox(ui)` 在每次状态刷新时按 `key`
  重新定位，重画/替换后大图自动跟着换；关键帧以外的组（分段/转场/成片）不显示替换按钮
- 卡片按钮必须两个字（替换 / 重画 / 还原），标签最多四个字（继承 / 待重画）：一格只有 ~90px，
  超了会被省略号吃掉，完整说法放 `title` 和灯箱里

## D10 任务命名与删除（已实现）

任务跑多了之后，下拉框里全是一串 `20261101_153045_9f3ab21c`，分不清谁是谁，也没地方删。

### 命名

节点新增 `job_name`（可选，文本，默认空），拼成 **`日期-名称`** 当任务号，也是任务文件夹名：

| 输入 | 任务号 / 文件夹 |
|---|---|
| `宿舍试穿` | `20261101-宿舍试穿` |
| `走位 测试` | `20261101-走位-测试`（空格→`-`） |
| 空 | `20261101_153045_9f3ab21c`（老格式，带随机后缀） |
| 重名（同一天第二次） | `20261101-宿舍试穿-2` |

清洗规则：`<>:"/\|?*` 和控制字符直接删掉，首尾 `-` / `.` / `_` 去掉，最长 40 字。
中文原样保留——`_job_directory` 已从白名单正则改成「黑名单 + 解析后父目录必须是 `JOB_ROOT`」，
所以任务号可以带中文，路径穿越照样挡住。

> `job_name` 放在 optional 的**最后一个**。ComfyUI 的 `widgets_values` 是按顺序存的，
> 插在中间会把老工作流的 `resume_job_id` 顶到新控件上。

### 改名

面板顶栏 `✎ 改名` → `POST /h3-long-video/rename/<job>`，body `{"name": "..."}`：

- **文件夹一起改名**（不是只改显示），照旧用 `YYYYMMDD-名称`；
- 日期用**任务自己那天**，不用今天——否则改个名任务就跳到列表最前；
- `config.json` / `status.json` / `.state.json` 里写死的绝对路径同步改写（`_rewrite_job_paths`），
  不然续跑会找不到首尾帧；改写失败自动把目录挪回去；
- `running` / `scheduled` 一律 409 拒绝（worker 还在往里写）。

### 删除

面板顶栏 `🗑 删除` → `POST /h3-long-video/delete/<job>`：

1. `rmtree` 整个任务目录（首尾帧、日志、参考图、`.state.json`）；
2. 再按 `.state.json` 里记的**绝对路径**删掉它写在任务目录之外的产物（分段视频、转场、关键帧草稿）；
3. 返回 `freed`（字节）+ `outputs`（删掉几个产物）。

不按 seed 去 `h3_long_video/` 里通配：关掉随机 seed 时两个任务可能同 seed，通配会误删别人的片子。
别的任务的 `.state.json` 也引用到的文件会跳过。

`running` / `scheduled` 或正是当前 `_ACTIVE_JOB` 时 409 拒绝；删完面板清空并自动挂到下一个任务上。

下拉框（`GET /h3-long-video/jobs`）现在多返回 `label` / `name` / `date` / `bytes`，
显示成 `20261101-宿舍试穿 · 已完成 · 4/4 段 · 24s · 38MB`。

**删除边界**：成片 `comfy_output_dir/h3_long_video/long_video.mp4` 不动——`output_prefix` 是全局配置，
所有任务共用同一个路径，删了也没意义（下一个任务会覆盖）。要彻底清空历史素材，得手动清
`comfy_output_dir/h3_long_video/` 和 `h3_single_clip/`。

## D11 关键帧来源（全局配置，已实现）

Qwen 出了第二代（2.1），跟 2511 并存。问题不是"换不换模型"，而是**在哪儿选**：
不能让人去改节点连线，也不能手改每个任务的 `config.json`。

### 一个下拉管住整条任务

节点上新增 `keyframe_backend`（放在 optional **最后**，和 `job_name` 一样是为了不打乱
老工作流的 `widgets_values` 顺序）：

| 选项 | 写进 config 的值 | 行为 |
|---|---|---|
| `H3 自己出（默认）` | `h3` | H3 草稿自动出图（`build_keyframe_graph()`） |
| `Qwen-Image-Edit 2511` | `qwen2511` | 代码建图自动出图（`build_qwen_keyframe_graph()`），40–90 秒一张，能转角度但脸会漂 |
| `Qwen-Image-2.1` | `qwen21` | 代码建图自动出图，20–30 秒一张，最像参考但角度跟参考图走 |
| `只用手动图` | `manual` | 不跑 AI，任务标成「等你放图」 |

qwen2511 / qwen21 与 h3 一样走 `ensure_keyframe_chain()`，只是 `run_keyframe()` 按后端分发到
`run_qwen_keyframe()`：一张编辑图要么当某段的首帧（无画布、空 latent），要么当尾帧
（上一帧当画布）。分辨率写死在 `keyframe_width/height`（608×1056，和 H3 草稿同尺寸）。
选 `manual` 才会在进 `ensure_keyframe_chain` 之前返回：

```
[H3] 关键帧来源 = manual：跳过 AI 出图，4 段等人工放图。
[H3] 出好图后在面板上逐张「替换」（或 push 灌进来），再点「确认关键帧，生成视频」。
```

### 面板上的反馈

- 关键帧页顶部一条提示条：`关键帧来源：Qwen-Image-2.1 · Qwen-Image-2.1 自动出图（约 20–30 秒一张，最像参考、角度跟参考走） · 出图后可逐张「替换」`
- 横幅只在 `manual` 且帧不全时说「等你放关键帧」并置灰按钮；h3 和两个 Qwen 后端帧不全时
  照常说「关键帧还没生成完，点继续补齐」；
- 帧放齐后横幅自动变成「关键帧已就位，可以继续生成视频」，按钮恢复。

### 数据流

```
节点下拉 ──> 任务 config.json 的 keyframe_backend
                │
                ├─> run_h3_long_video.py 选建图函数（h3 / qwen2511 / qwen21 / 跳过）
                └─> GET /h3-long-video/status 回传
                        keyframe_backend / _label / _hint
                        └─> 面板提示条 + 横幅文案
```

### 局限：它是整条任务级的

`keyframe_backend` 一个任务只能选一个，**做不到「这段用 2511、那段用 2.1」**。
真要转角度的单张帧，走两步混合流程（2511 出角度底图 → 2.1 糊画布换回原脸），
出好图后在面板上逐张「替换」——替换是逐帧的，路线不受这个下拉限制。
流程和参数见 `Qwen改图.md`「先出角度图、再换回原人脸」。

`example_workflows/` 里的两张 Qwen 工作流保留为**手动调试用**（试提示词、调参数、单张出图），
Director 运行时不依赖它们：

| 后端 | 工作流 |
|---|---|
| 2511 | `example_workflows/Qwen2511-Reference-Edit.json`（转视角用 `...-MultiAngle-Edit.json`） |
| 2.1 | `example_workflows/Qwen21-Reference-Edit.json` |

## D12 扩图确认闸门（已实现）

**问题**：点执行后扩图（参考图1 → 成片比例）直接混在关键帧阶段里做，扩坏了
（人物被拉伸、背景延伸出鬼影）也只能等关键帧全出来才发现，浪费时间还难定位。

**方案**：`confirm_reference_expand` 控件（默认开， widgets_values 最后一位）。
开启时点「执行」只跑 `--stage preexpand`：

1. 把参考图1 扩到成片比例，落盘 `work_dir/reference_expanded.png`；
2. 状态写入任务 `.state.json` → `reference_expand`
   （`status/original/image/source/seed/attempts`），同时顶替
   `config.json` 的 `reference_images[0]`；
3. 面板弹「参考图已扩好，等你确认」卡（缩略图，点开看原尺寸），三个操作：
   - **没问题，生成关键帧** → `POST /h3-long-video/reference/{id}/confirm`，
     标记 confirmed 并直接排队 keyframes；
   - **重扩参考图** → `POST /reference/{id}/reroll`：永远从
     `reference_expand.original` 记录的原图重扩（seed = base_seed + 800000 + 尝试次数，
     不在扩图上叠扩）；
   - **换参考图** → `POST /reference/{id}/replace`：上传自己处理好的图，
     服务端等比放大 + 中心裁切到精确成片尺寸后顶替 `reference_expanded.png`（source=user）。

不需要扩图时（比例差 ≤1%、`keyframe_reference_preexpand=false`、非 Qwen 后端、
`keyframe_align=off`）自动跳过，行为与旧版一致。单段节点不走预扩，无此控件。

参数与 CLI 用法见 `参数配置.md`「扩图确认流程」。
