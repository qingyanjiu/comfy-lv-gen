# MiniMax H3 单段工作流

工作流文件：

`example_workflows/H3-Single-Clip-FirstLastRefs.json`

这个流程只生成一段视频。它不会读取故事板 JSON，不会自动生成首尾关键帧，不会生成转场，也不会拼接其他片段。

## 使用流程

1. 重启 ComfyUI，让新的 `H3SingleClipDirector` 节点完成注册。
2. 导入 `H3-Single-Clip-FirstLastRefs.json`。
3. 在“固定首帧”和“固定尾帧”里各选择一张图片。
4. 在“参考图 1–9”中只连接本段实际需要的身份、脸型、服装或嘴型参考图。
5. 在节点唯一的提示词框里描述这一段的动作、镜头、环境和稳定要求。
6. 设置本段秒数、一采步数和二采步数；需要高清时打开 `two_pass`。
7. 运行工作流。节点内部显示任务状态，完成后可直接播放本次单段视频。

## 图片输入

| 输入 | 作用 |
| --- | --- |
| `first_frame` | 本段必须精确开始的画面 |
| `last_frame` | 本段必须精确结束的画面 |
| `reference_1` | 必选，通常放身份、脸型和全身比例最可靠的图 |
| `reference_2..9` | 可选，放服装、发型、面部、闭嘴嘴宽等补充参考 |

首帧和尾帧是构图锚点，参考图用于稳定人物身份和细节。参考图的说明直接写入提示词，例如：

```text
<Picture3> 定义女主角的脸型、五官、发型、身高比例和服装。
<Picture4> 只用于稳定闭嘴时的嘴宽和嘴角位置，不复制它的背景。
```

编号从固定首帧和尾帧开始算：

- `Picture1`：固定首帧
- `Picture2`：固定尾帧
- `Picture3`：参考图 1
- `Picture4`：参考图 2
- 后续编号依此类推

## 提示词模板

```text
<Picture1>、<Picture2> 分别定义本段首帧和尾帧。
<Picture3> 定义<女主角>的身份、脸型、五官、发型、身高比例和服装。

<女主角>从首帧自然过渡到尾帧，完成指定动作。保持同一人物身份、发型、
服装和身体比例。9:16竖屏完整全身构图，固定全身机位，摄影机不推进、
不后退、不缩放，头顶、身体和鞋底始终完整入镜。

面部稳定，双唇自然闭合，嘴角平直，嘴宽与参考图中的中性表情一致。
不微笑、不露牙、不张嘴、不咧嘴，嘴巴不突然放大。动作和脚步连续，
不穿模、不跳帧、不切镜，无文字、字幕和水印。
```

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `seconds` | 5 | 本段目标时长，最短 5 秒 |
| `steps` | 6 | 一采步数 |
| `two_pass_steps` | 5 | 二采步数，只在 `two_pass=true` 时使用 |
| `sampler` | `res_multistep` | 一采和二采共用的采样器 |
| `scheduler` | `simple` | 一采和二采共用的调度器 |
| `megapixels` | 0.2 | 一采生成画面规模；越高通常越清晰、越慢 |
| `final_width/final_height` | 720×1280 | 最终 9:16 输出尺寸；与生成尺寸不同时用 Lanczos 统一缩放 |
| `ref_image_size` | `match` | 参考图尺寸；`max` 会保留更大的身份参考 |
| `two_pass` | 关闭 | 开启后使用原有二采路径，时间分块固定开启 |
| `seed/randomize_seed` | 随机 | 固定 Seed 可复现同一结果 |

二采内部参数继续使用已经验证的配置：

```text
enable_temporal_chunking = true
chunk_length = 153
temporal_overlap = 17
anchor_strength = 0.99
```

## 模糊问题

正式视频比首尾帧软时，优先检查：

1. `megapixels` 是否低于 0.2。
2. 一采步数是否低于 6。
3. 开启二采时 `two_pass_steps` 是否只有 2–3。
4. 单段是否超过 8–10 秒；动作大的长段更容易出现插值模糊。

首尾帧本身清晰但视频模糊，通常不是参考图失效，而是正式视频采样预算过低或单段动作跨度太大。

H3 一采内部通常先按 32 像素对齐生成，单段流程随后会统一到所选的 720×1280。若二采输出已经是相同尺寸，则不会再次编码。
