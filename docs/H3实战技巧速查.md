## 一、参考图编号 `<Picture N>`

### 【项目】编号顺序：首帧 → 末帧 → 参考图 → 空镜板

`custom_nodes/comfyui-minimax-h3-audio-T8/h3_t8/conditioning.py:431-466` 先判 `first_frame`、再判 `last_frame`，然后才 `for index, image in enumerate(ref_image_values, 1)`；`comfy/text_encoders/minimax.py:218-222` 的 `ref_items` 同样按 `keyframe_images + real_ref_items` 拼。两边顺序一致。

| 编号 | 对应内容 |
|---|---|
| `<Picture 1>` | `first_frame`（若接了） |
| 下一个 | `last_frame`（若接了） |
| 再往后 | `ref_image_0`、`ref_image_1`…（只数非空槽） |
| 最后 | 空镜板 `bg_plate`（若接了） |

**单图出片场景**：无首帧、无末帧、无空镜板 → 唯一参考图就是 `<Picture 1>`。

### 【项目】空槽不占号，接 `last_frame` 整体后移

`sorted_autogrow_items` 跳过值为 `None` 的槽位后重新 `enumerate`。所以清空 `ref_image_0`、只接 `ref_image_1`，那张图自动变 2 号，不会保留 3 号。接上 `last_frame` 后，后面所有参考图编号 +1。

**踩坑实录**：`H3-SelfLift_单图参考.json` 节点 238 接了首帧（247）和参考图（150），prompt 232 原本写 `<Picture 1>` → 指向首帧，参考图被编为 2 号却从未被引用 → 同 seed 换参考图出片一模一样。改成 `<Picture 2>` 后正常。

### 【官方】编号规则本身

`docs/官方参考/Ref2VA-提示词优化器-官方原文.md` §一：同类媒体内按附件出现顺序编号，不同类别独立编号，标签一经分配全文保持同一含义。**官方没有"首帧优先于参考图"这条——那是 T8 节点的实现细节。**

### 【项目】runner 里用占位符，别写死数字

`skill/scripts/run_selflift.py:380-402` 的 `pic_numbers` 已处理偏移（selflift profile 下 first=1、人物参考图从 2 起）。写 `<Picture {pic:1}>` 让 seg_prompt 按实际接线展开。**裸写 `{pic:1}` 会被换成数字 `1`，prompt 变成「1 是唯一的人物参考图」，身份锚失效。**

### 【项目】黑鹤链路的首帧不占号，切链路编号会错位

`run_selflift.py:388-399` 明确按 profile 分叉：SelfLift 的 238 把 first/last 也喂给 Qwen，占 `<Picture N>`；黑鹤走 `MiniMaxH3AddGuide` 只把首帧当 latent keyframe 追加，**不喂图给 Qwen，编号不能后移**。

所以同一份分镜，黑鹤项目第 1 段接首帧不会让字面编号错位；一旦切到 SelfLift，人物就从 2 号起，写死的 `<Picture 1>` 会突然指向首帧。用 `<Picture {pic:N}>` 两条链路都安全。

## 二、参考图质量与多人镜头

### 【项目】参考图的瑕疵会被逐像素复刻，并按景别放大

`SKILL.md:2119` 的机制说明：H3 的 `image_2` 不是"参考它的布局"，而是"照着这张照片重渲染"。锚里任何高频纹理都会被逐像素复刻，**全身景约放大 4 倍**。所以问题不是"锚脏"，是"锚太像照片"。

`pipeline.quant_anchor()` 内置解法：`MeanShift(24,32)` + `kmeans 12 色`，固定 `setRNGSeed(0)` 保证同一张锚结果一致。实测（`SKILL.md:2115`）MeanShift+12 色量化锚的强边缘占比 16.0%，干净且保住布局。

**连续喂回更糟**：`SKILL.md:2192` 四代实验，强边缘 18.9% → 47.3% → 65.6% → 69.9%。对照组"同参数不换图连跑 4 次"逐像素 MAE = 0（后 3 次是节点缓存复用）——累积来自**把生成结果喂回 image_2**，不是跑的次数。

### 【项目】多人一人一张，绝不拼图；关系写进提示词

`SKILL.md:235-245`：4 人拼一张 → 每张脸只占 1/4 画幅，逐个糊，而且模型会把"四人并排"当构图模板复刻出僵尸站位。规矩是：

- 一人一张，**半身或胸像**，脸占画幅 1/3 以上（全身景脸只有 10~15% 高，锁不住人）
- 多张参考的布光/背景/色调尽量一致，否则画风打架
- **关系靠提示词，不靠图**：参考图只说"这人长什么样"，位置、朝向、接触点、遮挡必须写进 body
- 删掉中间一张会自动重排编号（`SKILL.md:538`），别手工维护空槽

### 【项目】上传图一律转 PNG；AI 图先裁水印

`SKILL.md:578`：ComfyUI 的 `LoadImage` **按扩展名**判断格式，`.jpg` 改名 `.png` 会解错。上传前用 PIL 真转 PNG。AI 生成图右下角的水印要先裁掉——水印会被当作画面元素复刻进成片。

### 【项目】手动编辑过的帧喂下游前做 CIE Lab 对齐

`SKILL.md:773`：换头、指令编辑过的帧，色彩统计和原片不同，直接喂下一段会被逐段复刻放大色偏。用 skimage 做 CIE Lab 均值/方差对齐；**不要用 PIL `convert('LAB')`**（它是另一套量化，结果不对）。

## 三、音频控制

### 【官方】对白写在 `<d>`，声音区不重复

`docs/官方参考/Ref2VA-提示词优化器-官方原文.md` §七、§八 + `docs/官方参考/FL2VA-I2VA-L2VA-提示词优化器-官方原文.md`：

- 格式 `<d>[Chinese] 原话</d>`，`<d>` 内**只放语言标签和原话**；身份、ID、动作、语气写在 `<d>` 外
- 说话人按真实发声首次出现顺序分配 `(S1)`、`(S2)`，跨镜不变；被引用主体发声时同时保留标签与 ID
- 原话逐字逐标点保留，不翻译不润色；画外音用 `says in an off-screen voiceover` 且说明画内人物双唇闭合
- `overall_soundscape` 写环境声/物理动作声/非语言人声，**不重复对白**；`non_diegetic_music` 写画外配乐，无配乐写 `N/A`
- 只有用户明确要求全程绝对静音时，`overall_soundscape` 才写 `N/A`

### 【项目】`audio: silence.` 无效

H3 不认这个字段，甚至可能把 "silence" 当声音描述。要"只留对白、其他都不要"：

```
overall_soundscape:
N/A

non_diegetic_music:
N/A
```

对白只在正文的 `<d>` 里。**删掉所有中文引号台词（`"..."`）和"发出XX声""轻声说"这类描述**——在 H3 眼里它们就是发声指令，会诱发乱出人声。

### 【项目】100% 静音走节点，不走提示词

`custom_nodes/comfyui-minimax-h3-audio-T8/h3_t8/conditioning.py:597-598`：

```python
if mode == "lock_source":
    latent = replace_audio_latent(latent, encoded_source, 0.0)
```

`audio_mode` 从 `native` 改 `lock_source`，`drive_audio` 接一段静音 wav（`ffmpeg -f lavfi -i anullsrc=r=32000:cl=stereo -t 20 silence.wav`），strength=0.0 把模型生成的音频 latent 整个替换。提示词层只能"最大程度不生成多余声音"，做不到数学意义的纯人声。

### 【项目】同 seed 不同 MP → 声音不同

`comfy/sample.py:27-34` 的 `prepare_noise()` 对嵌套 latent 用**一个** generator，按 (video, audio) 顺序取随机数。视频 latent 元素数 = 24×107×h×w 随 MP 变，音频噪声起点被挤位。实测 seed=582101、audio latent 固定 1×32×2×40：video 26×48 时 `a[0,0,0,:4]=[-0.144,3.5565,-1.1576,-0.4029]`，video 52×94 时变 `[0.5671,-0.072,-1.2037,-0.0929]`。

第二层：`comfy/ldm/minimax/model.py:353-473` 的 `PackedLayout` 把 text/cond/ref/audio/video 拼成一条序列做联合注意力，音频位置编码的横向端点取自视频 `w_grid`（369 行），视频 token 数随 MP 变——即使修了噪声流，这层也消不掉。

**结论：同 seed 只在 latent 形状也相同时可复现。** 要比对参考图/提示词效果，必须锁死 MP。

### 【项目】出片 cfg 必须 `audio="native"`

`single_panel.py`：默认 off 会让 `to_api._audio_off()` 断开 VHS 的 audio 输入，产物无 `-audio` 后缀，按文件名扫 audio 的页面列表就看不到。

## 四、分辨率、帧率与显存（8GB 5060Ti）

### 【项目】1.2MP 的竖屏高分辨率跑不动

`nodes.py:252` 的 `highres_tiling` 走分块；1.2MP/9:16 → 目标 latent 52×94、832×1504、token 137949，实测两次都卡在 `high_resolution 0/2 [Model Initializing ...]` 30+ 分钟，GPU 99%、日志停更。历史上能跑通的段 latent 多为 12×20 / 16×30 / 26×48，高分辨率总耗时多数 1～3 分钟。**降到 0.5MP 档位再跑。**

### 【项目】分辨率公式

以 base.json 节点 115 的 `multiple=32` 为准（`nodes_resolution.py` 默认 8 不同）：`total = mp × 1024²`，`round(x / 32) × 32`。0.5MP/16:9 → 960×544。

### 【项目】`h3_tiling.py` 是插件作者的，不是官方也不是我们加的

`custom_nodes/comfyui-SelfLift/h3_tiling.py` 来自 `facok/comfyui-SelfLift`，是 `highres_tiling` 开关的实现体。官方 `comfy_extras/nodes_minimax_h3.py` 无任何分块能力；关掉 tiling 在 8GB 上必然 OOM（`_prepare_tiled_sampling` 从 count=1 试起，日志实测选了 tiles=3）。**改完必须重启 ComfyUI（启动时导入）。**

### 【项目】帧数按 17n+5 对齐，别把"秒"当精确时长

`run_selflift.py:1932`：`length = int(17 * round(seconds * fps / 17) + 5)`。24fps 下填 5 秒实际是 `17*7+5=124` 帧 ≈ 5.17 秒。`run_selflift.py:503` 也注明段级 seconds 优先是因为手动按帧切段时各段长度不同。

`run_selflift.py:1314/1394` 切段参考视频写死 `force_rate=24`、`frame_load_cap` 同帧数。**30fps 源会被当 24fps 播，慢 1.25 倍**——取段前先确认源帧率。

### 【项目】换画幅会拉伸源首帧，不是裁切

`web/remake_app.html:744-752` 的 `srcAspectWarn`：带首帧的链路里，节点 238 的 width/height 是连线且内部 resize disabled，等比缩放填满画布。目标画幅比源宽就"横向拉宽"，比源窄就"横向压窄"（人变瘦高）。偏差 <2% 才视为同比例。

**想保住取景**：选与源接近的画幅，或先把源视频裁好再切段。

## 五、种子与可复现性

### 【项目】seed 100000 是坏种子

`SKILL.md:2400-2414` 严格对照（同工作流、同图、同提示词，只改 seed）：

| seed | 全图强边缘 |
|---|---|
| **100000** | **61.8%** |
| 450807536146328 | 6.6% |

用户手跑 5 张同样印证：100000 的两张 61.8 / 62.7%，三个随机 seed 5.5 / 6.3 / 6.7%。**历史上很多"提示词措辞"结论其实是被这个种子污染的**（`SKILL.md:1102` 明确说那些量化/抠图方案是过度方案）。runner 里显式写 100000 会自动替换并警告（`SKILL.md:1128`）。

**做对照实验至少两个随机 seed**，单 seed 的结论不算数。

### 【项目】节点缓存会伪造"可复现"

`SKILL.md:2197`：同参数不换图连跑 4 次，逐像素 MAE = 0——后 3 次是节点缓存复用，根本没重算。所以"同 seed 出片一模一样"要先排除缓存：换图、换 seed 或清节点缓存后再判断，否则会把"没重跑"误判成"参考图无效"。

## 六、出片流程与链路选择

### 【项目】段级 head 整段覆盖全局 head，不是追加

段级 `head` 一旦设置就**整段替换**全局 head。`all` 只出段、不拼接，跑完必须再单独 `merge`，否则拿不到成片。

### 【项目】蒙太奇默认走 SelfLift，别同片混两条链路

2026-11-11 用户判定：长视频默认 `H3-SelfLift_单图参考` ref2va 直出 + 分段接续（尾帧接首帧 + 全片唯一无人空镜板），比旧 Qwen2.1 首尾帧 → Director 链路更快、段间观感更自然。SelfLift 不接首帧时硬锚打平、空间锚点全保留，约快 20%。

旧链路只在**需要逐像素锁死背景**时回退。两条链路别混用：一采 MP 默认黑鹤 0.2 / SelfLift 0.5；MP 夹取只有黑鹤有；首帧节点黑鹤 311 / SelfLift 151；切 SelfLift 时别删 `bc_upscale` / `bc_two_pass`。

### 【项目】复刻台传了人物参考图，首段硬锚自动关

`remake_panel.py:2055`：`anchor = bool(data.get("anchor_first", not bool(user_refs)))`。有上传人物图时默认不锚源首帧，避免源脸锁进 frame0 盖掉参考图身份。想强制锚回去要显式传 `anchor_first=True`。

### 【项目】ComfyUI 重启会刷 `*_updated_at`，全片误标 stale

重启会刷新工作流文件的 updated_at，导致所有段被判为过期。校正到**最早段 mp4 的 mtime 之前**，别按当前时间算。

## 八、把官方结构映射到本项目

官方给的是 Ref2VA **六段式**（`subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music`）和 FL2VA 等**三段式**。本项目的落点是：

| 官方区段 | 本项目对应 |
|---|---|
| `detailed_description` 的正文 | `docs/segment编写规范.md` 的 body（镜 × 四块） |
| `subject_definitions` 的实体标签 | 用 `<Picture {pic:N}>` 引用，由 runner 按接线换算 |
| `overall_soundscape` + `non_diegetic_music` | `docs/视频生成提示词规范.md` 的全局 tail |
| 对白 `<d>[Lang]…</d>` | 见 `segment编写规范.md` §五之一，写法与官方一致 |

**注意**：官方范本（如 `优质样本-Ref2VA-健身房DV自拍.md`）用 `<Subject N>`，runner 不认；参考图一律走 `<Picture {pic:N}>`。只学结构技巧，不照抄实体标签。
