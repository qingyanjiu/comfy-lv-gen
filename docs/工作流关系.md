# 工作流关系

这份文档讲清楚：**哪些工作流、谁喂谁、产出落到哪、想改东西该动哪个文件。**
文件在哪见 `文件位置说明.md`，字段含义见 `分镜JSON.md`。

## 1. 全景：三段流水线

整条链路其实是三件事，每件事都可以单独跑、单独换工具：

```
       ① 出静帧              ② 出动态                 ③ 拼成片
   ┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
   │ Qwen-Image-  │     │ MiniMax H3       │     │ FFmpeg       │
   │ Edit 2511/2.1│ ──> │ 首尾帧插值         │ ──> │ 统一分辨率+拼接│
   │ (改图/转视角)  │     │ (单段 or 多段)     │     │ +淡入淡出     │
   └──────────────┘     └──────────────────┘     └──────────────┘
      example_workflows/    H3 Director 节点         run_h3_long_video.py
      Qwen*.json            + run_h3_long_video.py   的 stitch_segments()
```

关键点：**① 是可选的**。H3 自己也能出关键帧（默认就是这么跑的），Qwen 只是把
「首尾帧长什么样」这件事拿到生图模型上去做，控制力更强、也不用烧 H3 的算力。

### 1.1 ① 段内部本身是两步，不是一步

Qwen 出首尾帧有先后，**不能各写一个 prompt 独立出两张**：

```
Qwen2511-FirstFrame916.json                Qwen2511-Reference-Edit.json
┌──────────────────────────────┐           ┌────────────────────────────────┐
│ 3 个 LoadImage：场景 + 2 张身份图│          │ image_1 = F0（画布，锁住构图）    │
│ → EmptySD3Latent 720×1280    │  ──F0──>  │ image_2/3 = 身份图              │
│ → 首帧 F0（原生 9:16，非裁切）  │           │ → 尾帧 F1（只改肢体，不锁位置）   │
└──────────────────────────────┘           └────────────────────────────────┘
```

独立出的两张，场景、光向、机位、人物尺度一定对不齐，H3 插值时会硬切、飘、地面滑动。
五个实测出来的坑（必须空 latent、别去修镜像、别写「位置不变」、输出必须精确 9:16、
动作幅度要够）见 `关键帧生成.md`。

**示例工作流的连线现状**（打开后别怀疑自己连错了）：

- `H3-Long-Video-Director.json` 有 4 个 `LoadImage`，但只连了 3 根线：`reference_1`、`reference_2`、`first_frame`。
  其中第 3 个 `LoadImage`（id 3）是**断了线的孤儿节点**，`reference_3` 空着；要用第三张参考就自己拉一根过去。
- `H3-Single-Clip-FirstLastRefs.json` 有 11 个 `LoadImage`，只连了 4 个：`first_frame`、`last_frame`、`reference_1`、`reference_2`，
  剩下 7 个是排好的备用位。所以「最多 9 张参考」说的是**节点输入位**，不是示例里接好的数量。
- `Qwen21-Reference-Edit.json` 同理，只接了 `image_1/2/3`，`image_4…10` 要自己在 `TextEncodeQwenImage21` 的 `images` 上点 `+`。

### 2.1 两张主工作流是脚本生成的

`H3-Long-Video-Director.json` 和 `H3-Single-Clip-FirstLastRefs.json` **不是手搓的**：

```
python tools/build_director_workflow.py
```

`tools/build_director_workflow.py` 的 `main()` 里写死了这两个输出路径，控件值直接取 `director.py` 的常量
（`director.STAGE_REVIEW`、`director.KEYFRAME_BACKEND_OPTIONS[0]` 这类）。

**所以给 Director 节点加删控件时，只改 json 不够**：必须同步改脚本里的 `widgets_values` 列表，否则下次
重跑脚本会把值错位。`job_name` 和 `keyframe_backend` 都踩过这个坑——ComfyUI 的 `widgets_values` 是
按顺序存的，新控件插在中间会把后面所有值顶上去。这也是为什么这两个控件都放在 optional 的最后。

`tools/cleanup_comfy_assets.py` 是清 ComfyUI `output/` `input/` 里临时产物的辅助脚本，跟链路无关。

## 3. 三条主线的具体关系

### 3.1 单段：一张图就够

```
LoadImage(首帧) ─┐
LoadImage(尾帧) ─┼─> H3SingleClipDirector ──> run_h3_long_video.py（config 里 single_clip = true）
LoadImage(参考×N)┘        │                         │
                          │                         └─> Shared/output/h3_single_clip/single_<id>_WxH.mp4
                          └─> 面板：首尾帧预览 / 进度 / 成片
```

首帧和尾帧是**你给死的**，H3 只负责中间的插值。想改哪一头，就在 `LoadImage` 换图，
或者在面板里直接看结果重跑。细节见 `单段视频.md`。

### 3.2 长视频：关键帧链才是核心

```
LoadImage(参考×N) + 分镜JSON
        │
        ▼
H3LongVideoDirector  ──起 worker──>  run_h3_long_video.py --stage keyframes
        │                                      │
        │                                      ├─ 5 秒 H3 草稿 → 首帧当开场帧、末帧备用
        │                                      ├─ 段1 尾帧 = 首帧 + 尾帧词再跑一次草稿，取末帧
        │                                      ├─ 段N+1 首帧 = 段N 尾帧（同一张图）
        │                                      └─ free_end 段：不设尾帧，下一段首帧取自渲染视频末帧
        │                                      ▼
        │                          任务目录/.state.json + keyframes/
        │                                      │
        ├─ 面板「关键帧 → 确认」（可替换 / 重画 / 还原 / 改词）
        │                                      │
        └─ 面板「确认关键帧，生成视频」 ───────>  --stage videos
                                               │
                                               ├─ 逐段 build_graph()（首尾帧插值）
                                               ├─ 二采：修开头两帧条纹
                                               └─ FFmpeg 合并 → long_video.mp4
```

几条容易混的规则：

| 规则 | 含义 |
|---|---|
| `chain_segments = true`（默认） | 段 N 的尾帧**就是**段 N+1 的首帧，同一张图，不是"相似的两张" |
| `continue_from_previous = false` | 这一处是硬切：下一段单独出首帧，两段之间插一段转场（`transition_mode = fade`） |
| `hold_composition = true` | 本段不要运动：尾帧 = 首帧，全靠提示词撑动作（默认跟随 `stabilize_full_body`） |
| `free_end = true` | 本段**不设尾锚**：让它自己走，下一段首帧取它**渲染视频的最后一帧**。长距离行走类必用；此时首帧是「待定」，要等视频阶段跑完才有 |
| 改链上某一帧 | 下游全要跟着重画（`cascade`），面板会标「待同步」 |

**每一帧到底从哪来**（`ensure_keyframe_chain()` 的实际优先级，从高到低）：

| 帧 | 来源 |
|---|---|
| 首帧 | 手动替换的 `segNN_start_manual.png` → 上一段的尾帧（链式）→ 上一段视频渲染出的最后一帧（上一段 `free_end`）→ 节点 `first_frame`（仅第 1 段）→ H3 用 `start_frame_prompt` 现画 |
| 尾帧 | 手动替换的 `segNN_end_manual.png` → 首帧本身（`hold`）→ 不要（`free_end`）→ 开场草稿的末帧（第 1 段且尾帧词与整段词相同时）→ H3 用 `end_frame_prompt` 现画 |

「现画」不是画一张图：`run_keyframe()` 是拿 `keyframe_draft_seconds`（现 5 秒）出一段草稿，
**首帧和末帧一趟一起拿到**。所以第 1 段的开场帧和它的草稿末帧是同一个 prompt_id 的产物。

细节见 `长视频流程.md`、`分镜JSON.md`（第 8 节 / 8.5 节）、`关键帧生成.md`。

### 3.3 Qwen 出图 → H3 出片：怎么接

这是**最容易被忽略的一条**：关键帧不一定要 H3 自己画。四种接法，从松到紧：

| 接法 | 怎么做 | H3 还画关键帧吗 |
|---|---|---|
| A. 只做首帧 | Qwen 出图 → 存 `Shared/input/` → `H3-Long-Video-Director` 的 `first_frame` 接过去 | 画（开场帧由你定，后续照旧往后长） |
| B. 关键帧全外包 | Qwen 出全部首尾帧 → `pipeline.py push` 灌进任务目录，或面板逐张「替换」→ `stage = 继续生成视频` | **一张都不画**，直接出视频 |
| C. 单段直接给 | Qwen 出首/尾帧 → 接进 `H3-Single-Clip-FirstLastRefs` 的两个 `LoadImage` | 不涉及（单段没有关键帧阶段） |
| **D. 复刻（有原片）** | 抽原片每刀 first/last → `pipeline.py source_frames` 两帧各从对应原帧独立重绘 → `push → resume` | 一张都不画，且不需要 A 派生 |
| **E. 逐帧精确复刻** | 按时间段抽**每一帧** → `pipeline.py frame_exact` 逐帧重绘 → 直接合成成片 | 一张都不画，且**不经过 H3 视频模型** |

**接法 E 与 D 的分界**：D 只重绘首/尾帧、中间由 H3 插值（动作是模型补的）；
E 把中间每一帧都从对应源帧重绘，动作/机位/光效/画幅/fps/帧数/时长全部继承源片。
E 也因此不适用本页其余接法的 9:16 / 17n+5 / `push` 约定，详见 `SKILL.md`
「逐帧精确复刻」与 `scripts/frame_exact.py`。

**接法 D 为什么单独存在**：复刻有外部真值，一致性来自原片同一个镜头的两帧。
把接法 B 的「尾帧图2 = 本段首帧」套过来，模型会把构图锁死在首帧，拿不到原片尾帧的
拉远 / 换机位，2.1 还容易触发过锐。`source_frames` 用同模型 + 同提示词 + 同 seed +
同预处理尺寸重绘两张原帧，身份 / 服装 / 背景天然同源。详见 `SKILL.md`「一致性来源」。

**接法 D 只有一个入口**：`pipeline.py source_frames --storyboard sb.json [--segs 4,8]
[--force]`。项目侧的驱动脚本只负责把分镜翻译成 pipeline 格式并转发（例如 capsule
项目的 `drive_restyle.py`），**不许另写一套重绘 / 断点 / QA**。生成、重试自愈、
配置指纹、背景质检、state 登记都在 `scripts/source_frames.py` 里。
改完活跃源码记得 `python scripts/sync_repo.py --apply` 同步到本仓库的 `skill/` 副本
（里面的 `align_exposure.py` 等脚本会 `import pipeline as P`，副本不能删但不能直接改）。

**用哪一代 Qwen**：2511（8 步 Lightning，最多 3 张参考，Apache 可商用）和 2.1（8 步
LR-8step，最多 10 张参考，非商用许可）是平级的，换张工作流就行。更实际的分工是
**按能力选**：2.1 更像、更快但角度跟参考图走；2511 能转身回头但脸会漂。细节和实测见
`Qwen改图.md`。
**2026-11-09 补充（复刻实测）**：2511 只擅长小改画风（卡通→卡通时构图 100% 守住），
不适合「CG → 真人」这类大域转移，也不适合「首帧 A 当输入定尾帧」（会把大脸贴到
天空 / 锁死 A 的构图）。正式重绘默认走 2.1 单图 L4；详见 `probe_last_2511.py` 探针。

Director 节点最后那个 `关键帧来源`（`keyframe_backend`）**不是记录性字段**：它决定
`run_h3_long_video.py` 用哪套建图函数出关键帧。`h3` / `qwen2511` / `qwen21` 三个值
**全部是代码自动出图**（分别走 `build_keyframe_graph()` / `build_qwen_keyframe_graph()`），
只有 `manual` 是真的等人工放图——那种情况 runner 才会在进 `ensure_keyframe_chain()` 之前
`return`，把 `.state.json` 标成 `awaiting_review`：

| 选项 | 写进 config 的值 | 谁出图 |
|---|---|---|
| H3 自己出（默认） | `h3` | H3 草稿，`build_keyframe_graph()`，5 秒一段首末帧一起拿 |
| Qwen-Image-Edit 2511 | `qwen2511` | 代码建图：2511 int8 + Lightning **8 步**，39–87 秒一张 |
| Qwen-Image-2.1 | `qwen21` | 代码建图：2.1 int8 + LR-8step **8 步**，18–27 秒一张 |
| 只用手动图 | `manual` | 不跑，你自己放图 / 面板替换 |

`example_workflows/` 里的 `Qwen2511-Reference-Edit.json`、`Qwen21-Reference-Edit.json` 保留为
**手动调试用**（改提示词、试参数、单张出图），Director 运行时不依赖它们，也不用导入 ComfyUI。

**两个 Qwen 后端的图是代码现搭的**，要点：

- 分辨率写死：`keyframe_width=608`、`keyframe_height=1056`（32 的倍数，和 H3 草稿同尺寸），
  不用 `FluxKontextImageScale`（它会把 720×1280 缩成 752×1392，H3 拒收）；
- 2511：有上一帧时上一帧 `ImageScale` 到精确尺寸再 `VAEEncode` 当画布；没有时用
  `EmptySD3LatentImage` 原生构图；
- 2.1：latent 由 `TextEncodeQwenImage21` 从 image_1 生成，所以 image_1 必须先缩到精确尺寸、
  `resolution` 保持 0，其余参考图走 `ImageScaleToTotalPixels` 压到 0.4MP；
- 派生帧（有画布）默认**不喂参考图**——同一个人喂两遍会被画成两个人。换脸流程要用
  `keyframe_qwen_canvas_refs` 打开，并配 `keyframe_qwen_canvas_blur_mp`（糊画布，逼模型重绘）；
- 提示词自动追加「画面中只有同一个人物，不新增人物……」后缀，防止把身份参考图画成多个人
  （`keyframe_qwen_prompt_suffix` 可覆盖）。

**转角镜头（转身 / 回头 / 看侧面）**：2.1 转不了角度，2511 转角后脸会漂。现有做法是
两步混合——2511 出角度底图，再用 2.1 + 糊画布 + 正面参考换回原脸。这条是**手动流程**，
runner 里没有自动串起来；步骤和参数见 `Qwen改图.md`「先出角度图、再换回原人脸」。

选 `manual` 时省掉的是 N 段 × 2 张的推理，日志会明确打印
`[H3] 关键帧来源 = manual：跳过 AI 出图，N 段等人工放图。`

**默认那条路又是谁在画**：`build_keyframe_graph()` 用的是 H3 自己的模型（`config.unet_name`，
现为 `DasiwaMinimaxH3_dasiwaHybridV2_int8`）+ 与正片共用的 `steps`，尾帧靠 5 秒草稿取末帧，
跟 Qwen 毫无关系。所以这两条是**互斥**的路，不是叠加。

还有一个物理断点只影响**手动**出图：手动出的图落在 `Shared/output`，而 `LoadImage` 只读
`Shared/input`，所以要手动拷进 input，或用面板「替换」直接上传。代码出图（h3 / qwen2511 /
qwen21）没有这个问题——`run_qwen_keyframe()` 直接用 `VHS_LoadImagePath` 读绝对路径，
产物就地进 `.state.json`。

接法 B 的价值：关键帧的质量和一致性由 Qwen（多图参考、身份锁定）保证，H3 只负责"把两张图
之间连成动作"，省掉 H3 反复抽卡的时间。实测一张 5 秒有声片约 3 分 20 秒（见 `lab/H3-One-Segment.json`）。

## 4. 谁调谁（代码层面）

```
ComfyUI 前端（web/director.js、web/single_clip.js）
        │  fetch /h3-long-video/*
        ▼
director.py  ── 节点 execute() ──> 写任务 config.json
        │                        └─ 起线程 _run_worker()
        │                              │ subprocess
        │                              ▼
        │                     run_h3_long_video.py
        │                              │ HTTP POST /prompt
        │                              ▼
        └──────────────────────> ComfyUI 本体（真正跑模型）
                                       │
                                       └─ 写 output/ → 状态回 .state.json
```

- **前端只跟路由说话**，不 import Python；
- **director.py 不跑模型**，它只写配置、起进程、读状态；
- **run_h3_long_video.py 不碰 UI**，它认 `config.json` 干完全部活；
- 三者之间的契约只有任务目录里那三个 json：`config.json`（director 写、runner 读）、
  `.state.json`（runner 写、director 读）、`status.json`（**director 自己写自己读，runner 不碰**）。
  任务状态对不上时，先分清这条记录是谁写的。

### 4.1 产物流向（谁产出、落哪、谁读）

| 产物 | 落点 | 谁写 | 谁读 |
|---|---|---|---|
| Qwen 画的关键帧（自动后端） | `Shared/output/h3_long_video/keyframes/{qwen2511,qwen21}_edit_<seed>*.png` | `run_h3_long_video.py` | 面板预览、出视频 |
| 你替换/推送的帧 | `<任务>/keyframes/segNN_{start,end}_manual.png` | `director.py`（面板上传）或 `pipeline.py push` | `run_h3_long_video.py` |
| H3 画的关键帧 | `Shared/output/h3_long_video/keyframes/{first,last}_<seed>*.png` | `run_h3_long_video.py` | 面板预览、出视频 |
| 分段视频 | `Shared/output/h3_long_video/segment_*.mp4` | 同上 | `stitch_segments()` |
| 长片成片 | `Shared/output/h3_long_video/long_video.mp4` | 同上 | 人 |
| 单段成片 | `Shared/output/h3_single_clip/single_<id>_WxH.mp4` | 同上 | 人 |

⚠️ 有两个 `keyframes/` 目录：`Shared/output/h3_long_video/keyframes/` 里是 **AI 画的**
（H3 或 Qwen，看 `keyframe_backend`），`<任务>/keyframes/` 里是 **你替换的**。位置不同、含义不同，别混。

## 5. 想改东西该动哪

| 想改 | 动这里 | 影响面 |
|---|---|---|
| 模型、分辨率、步数、采样器 | `config.json` 的对应键 | 所有任务 |
| 某一段的提示词 / 秒数 / 二采 | 面板「改词」编辑器（写回任务 `config.json`） | 只影响该任务该段 |
| 关键帧怎么画（步数、草稿时长） | `config.json` 的 `keyframe_*` | 只影响还没跑的任务 |
| 图怎么搭（加节点、改连线） | `run_h3_long_video.py` 的 `build_graph()` / `build_keyframe_graph()` | 全部 H3 出片 |
| 面板长什么样、按钮行为 | `web/director.js` / `web/single_clip.js` | 前端，改完 Ctrl+F5 |
| 路由、任务管理（改名/删除） | `director.py` | 改完必须重启 ComfyUI |
| 分镜结构、字段 | `docs/分镜JSON.md` + `_normalize_storyboard()` | 老任务不受影响（配置已落盘） |
| 给节点加 / 删控件 | `director.py` 的 `INPUT_TYPES` **和** `tools/build_director_workflow.py` 的 `widgets_values` | 两处都改，否则脚本重生成时值会错位；改完重启 |
| 关键帧来源的选项文案 / 默认值 | `director.py` 的 `KEYFRAME_BACKEND_OPTIONS`（显示）和 `KEYFRAME_BACKEND_TO_VALUE`（落盘值） | 只影响新任务，老任务已落盘 |
| Qwen 手动调参 / 试提示词 | `example_workflows/Qwen2511-Reference-Edit.json`、`Qwen21-Reference-Edit.json` | 只影响你手点的那一次 |
| Qwen 自动关键帧的模型/步数/尺寸 | `run_h3_long_video.py` 的 `QWEN_KEYFRAME_PRESETS` 与 `config.json` 的 `keyframe_width/height`、`keyframe_qwen_steps` | 只影响还没跑的任务 |

## 6. 常见组合（照着用）

| 目标 | 用哪些 |
|---|---|
| 快速验证一条动作 | `H3-Single-Clip-FirstLastRefs` + 两张图 |
| 想一张图走完全程、先摸流程 | `lab/H3-One-Segment.json`（Qwen 出首尾帧 + H3 出片，22 个节点一张图，实测 3 分 20 秒出 5 秒有声片） |
| 5～10 秒、控制力优先 | Qwen 出首尾帧 → 单段节点（接法 C） |
| 30 秒以上长片 | `H3-Long-Video-Director` + 分镜 JSON（默认让 H3 自己长关键帧） |
| 长片但要求角色脸稳 | Qwen 出全部关键帧 → `push` 灌入 → `继续生成视频`（接法 B） |
| 要多角度/多服装参考一起喂 | `Qwen21-Reference-Edit.json`（10 张参考） |
| 只要转个视角、换个衣服 | `Qwen2511-Reference-Edit` / `Qwen2511-MultiAngle-Edit`，不进 H3 |
