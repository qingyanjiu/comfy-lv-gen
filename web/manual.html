1. 五分钟上手

  1. 导入分镜：点「导入分镜 JSON」，可以选文件、也可以直接粘贴 JSON 或一整段剧情文字（会自动切段）。不知道怎么写就先点「下载模板」，每个字段都带中文说明。JSON 里的 title 就是片名，会连同编号一起写进文件夹名；没写的话用第一段标题当默认名。
  2. 传参考图：页面顶部参考图条带里，给每个人物各传一张半身/胸像，再传一张完全无人的场景空镜板（橙色边框）。这一步不能省——head 里引用的 <Picture N> 必须有真实接线，否则提交会被拒。
  3. 写全局提示词：head 写身份与场景锚，tail 写画风与衔接规则。用 {pic:1} 之类的占位符，别手写编号。
  4. 逐段调整：每段改 body / seed / 承接方式 / 段级参考图。改完不用逐个保存，直接跑片即可（会自动落盘）。
  5. 出片：点「一键跑全片」串行渲染，全部完成后自动拼接；或点「拼接成片」只重拼现有段。
先跑一段看看。 改了参考图或大段提示词时，先「运行本段」验证效果，确认了再跑全片，别一上来等十几分钟。

2. 访问地址与片选择

三个入口，共用同一套页面和算力：

入口地址说明
独立服务（推荐）http://127.0.0.1:8900/双击 tools/serve_app.bat 启动，进程独立，重启不影响 ComfyUI
局域网 / 别的设备http://192.168.x.x:8900/服务监听 0.0.0.0，用本机局域网 IP 即可
内嵌页面http://127.0.0.1:8188/h3-long-video/app挂在 ComfyUI 桌面版下，改后端要重启桌面版
别写 0.0.0.0 当网址。 它是「监听所有网卡」的绑定地址，不是可访问地址；浏览器打开会失败。localhost 会优先解析到 IPv6 ::1，而服务只监听 IPv4，个别浏览器会卡住——统一用 127.0.0.1 最稳。换端口记得服务与网址一致。

片选择下拉

页面左上角的下拉会列出输出目录下所有片，按最近更新时间倒序，格式是「片名 · #编号 · 时间 · 完成段数」。选中即切换，同时更新地址栏 ?cfg=，方便收藏或分享。

更新时间取 segments.json、段视频、成片里最新的修改时间——改提示词、跑完一段、重拼成片都会让它往前排。

片名 · 编号 · 文件夹，三者一一对应

每部片有一个固定编号，就是文件夹末尾的 MMDD_HHMMSS：例如 女生的午后_1112_135157 的编号是 #1112_135157。下拉每项带编号，顶部标签显示「片名 · #编号 · 文件夹名」，去磁盘上找片子不用再靠时间猜。

  • 搜片：下拉左边的输入框可以输片名 / 编号 / 文件夹名，即时过滤；清空恢复全部。
  • 改名：点「改名」输入新片名，会同步做四件事——写 segments.json 的 title、把文件夹改成 名字_编号、把 cfg 里所有指向旧目录的绝对路径换掉、把成片文件名改成 名字_编号_成片.mp4。编号永远不变，所以名字、文件夹、成片始终对得上。
  • 占位名：从模板导入又没写标题的片，页面显示「未命名 #编号」，改名时会拿第一段标题当建议名，直接回车即可。
改名会换掉片目录。 页面会自动切到新路径并刷新；其它还开着旧地址 ?cfg= 的标签页要重新选片。跑片过程中不允许改名，等任务跑完再改。
为什么以前换个地址就「找不到片」？ 浏览器本地存储是按域名隔离的，127.0.0.1:8900 和 192.168.0.66:8900、8188 各存一份「上次打开的片」。现在片列表由服务端提供，任何地址打开看到的都是同一份。

3. 参考图与空镜板

  • 一人一张，绝不拼图。 一张图塞多个人，每张脸占比太小锁不住身份，还会把「几人并排」当构图模板复刻。
  • 半身/胸像，脸占画幅 1/3 以上。 全身景脸只占 10~15%，锁不住具体的人。
  • 两人的服装/发色要明显区分，否则链式段跑几段后两人会越跑越像。
  • 空镜板永远排最后（编号 P(N+1)），必须完全无人、无文字水印、无脏斑——参考图瑕疵会被逐像素复刻放大。
  • 上传的图一律自动转 PNG（网页另存的图常带 .webp 后缀但内容是 JPEG，直接喂会 400）。

段级覆盖

每段卡片下面有「本段参考图」和「背景板」两块，可单独增删/换图：

  • 标「跟随全片」= 用顶部条带的配置；改过之后标「自定义」，并出现「恢复全片」。
  • 「本段不用」让这一段不接背景板，不影响其他段。
  • 典型用法：只有第一段需要挂鞋款/道具参考图时，就只在 s01 挂，近景段不挂——避免模型为了找鞋把镜头推到腿脚特写。
参考图会连「怎么拍」一起学。 H3 的 ref_images 由视觉模型整体理解，主体、构图、景别、机位、光线一起吸收，没有「只取款式」的开关。局部物件图（鞋、包）直接当参考，模型可能把物件当成画面主体摆进来，或跟着切到特写。正确做法是先把它合成到人物身上（Qwen 编辑），或明确写出「穿在她脚上、不作为独立物件出现」。

4. 提示词与 {pic:} 占位符

全局 head / tail 只有一份，所有段共用；{pic:} 占位符会按本段实际接线自动换算成真编号：

写法含义
{pic:1} … {pic:N}第 N 个人物参考图
{pic:plate}场景空镜板
{pic:first}本段首帧（仅链式段有）
{pic?:first}可选版：本段没接该媒体就整行删掉

编号顺序是「首帧 → 人物 1..N → 空镜板」。链式段比首段多一张首帧，所以后面的编号会整体后移一位——这正是要用占位符的原因。

手写 <Picture 3> 是最常见的跑片失败原因。 实际只接了 2 张图却引用了 P3，提交时 strict_prompt_tags 会直接拒绝（报错 1~2 秒，根本没进渲染）。报错信息现在会翻译成中文并提示补图或改占位符。
段级 head 是整段覆盖全局 head，不是追加。 只改全局那一份救不了写了段级 head 的段。多人片建议删掉段级 head，统一用占位符版全局 head。同理段级 tail 覆盖全局 tail。

占位符只支持上述几种；出现裸的 { 会在保存时提示，避免被误解析。

5. 分段卡片逐项说明

6. 跑片、取消与保存

  • 一键跑全片：串行逐段提交，确认上一段真的生成了视频才推进下一段；失败会停下并报出段号，不会静默跳过。全部完成后自动拼接。
  • 运行本段：只跑这一段。重跑后链式尾帧变了，后续段需要按序重出才能接上。
  • 保存所有修改 (N)：一次把所有改过的提示词、seed、全局 head/tail 写回 JSON，N 是未保存字段数。
  • 自动落盘：一键跑全片、每次提交下一段、运行本段之前都会先静默保存——改了提示词直接跑不会跑旧配置。
  • 取消全片：服务端级取消，会中断当前段、清空 ComfyUI 队列，其他标签页也会停。重新点「一键跑全片」即解除。
  • 需重出标记：改了提示词/seed/全局 head/分辨率后，受影响段及之后的段会标 stale。改分辨率会让全片都标，避免新旧尺寸混拼。
不要同时在 8188 内嵌页和 :8900 页点运行。 这是两个进程、各一份任务表，判重互相看不见，会往 ComfyUI 队列塞两笔任务。算力是单队列，不会并行渲染，只会排队等待。

7. 拼接与转场优先级

右上角下拉是全片级，每段卡片里的「承接 + 转场」是段级。优先级：

右上角选择结果
全片硬切 / 全片叠化 / 全片黑场最高优先级，所有接缝统一用该值，段级 link 完全忽略
按每段转场 (auto)才看段级：mode=transition → 用该段的 transition；mode=chain 或没写 link → 固定 0.25s 叠化
段级「转场」下拉在链式承接时是灰的，也不生效。 想让某段用黑场/硬切，必须先把它的「承接」切成「转场」，并保持右上角为「按每段转场」。chain 片里 auto 与「全片叠化」完全等价。

两个阶段别混

  • 生成期：link.mode=chain 才把上段尾帧注入 first_frame，stale 会向后传染；transition 段独立生成、不接首帧。
  • 拼接期：右上角 join 只决定 ffmpeg 用叠化 / 插黑帧 / 直连，不会改已生成的段。「全片硬切」= 仅去掉叠化，链式接缝的帧差不变。

叠化 0.25s、黑场 0.8s 都会改变总时长；硬切不额外加帧。选择会写回片配置，换浏览器/换地址打开也是同一个值，命令行不带 --join 时也沿用。

叠化不一定更平滑。 链式段首帧本来就承接上段尾帧（帧差通常 2~4），叠化只是把两张极像的画面半透明叠在一起，反而多一层重影。觉得接缝「发虚」时优先试「全片硬切」。

8. 分辨率与画幅

工具条上的「百万像素」滑块 + 数值输入 + 画幅下拉，实时显示预估尺寸（如 0.5MP / 16:9 → ≈960×544）。点「应用」写回配置，所有已完成段立刻标「需重出」。

8GB 显存建议 0.5MP 左右，优先 int8 / w4a8 模型；调到 1MP 以上容易 OOM。允许范围 0.1~2.0MP。

9. 预览图、日志与验收

  • 刷新预览：重跑后缩略图没变就点它，强制重建卡片并重拉图片/视频（缓存兜底）。后端也会给媒体 URL 带文件版本号，正常情况下重跑会自动更新。
  • 日志面板：逐行着色（错误红 / 警告橙 / 段标题蓝 / 完成绿），支持复制全部、下载 .log、跟随开关、只看问题。
  • 验收两指标：① 构图——抽上段尾帧与下段首帧算 MAE，<5 即接续正常；② 光线——逐秒算亮度与色温数值曲线，别只目测拼图。
  • 段内出现帧级抖动（相邻帧差尖峰）不是接缝问题，换转场救不了，只能换 seed 重出该段或把段首动作写得更缓。

10. 常见坑与排错

现象原因 / 处理
提交几秒就失败，提示 Picture N 悬空实际接线数与手写编号不符。补空镜板，或改用 {pic:} 占位符
换装 / 换风格不明显画风由参考图锁定，纯提示词权重不够。先用本地 Qwen-Image-Edit 造一张干净的目标参考图
模型切到腿脚特写、把物件摆进画面参考图带景别/主体信号。见第 3 节，清图或合成到人物身上
跨段从站变坐，地面崩段间换姿势。统一姿势，转换在同一段内完成
总有几个段跑失败多半不是并行（ComfyUI 是单队列、无 OOM），而是编号对账失败，原样重跑还会挂
任务卡在「渲染中」但队列是空的ComfyUI 中途重启清了 history。驱动现在会在队列空转 30 秒后提前退出
重跑后预览图还是旧的浏览器缓存。点「刷新预览」；文件时间戳正常就说明模型链路没问题
改了提示词却跑了旧内容老版本页面未自动落盘。现在所有跑片动作前都会自动保存，刷新一次页面即可

11. 改动什么时候生效

改了什么生效方式
出片逻辑 / 状态字段（driver）每次调用都是新进程 → 立刻生效
页面 HTML / JS每次请求现读 → 刷新页面即可，两个入口都一样
常驻后端的路由（panel.py）独立服务要重启 :8900；内嵌页面要重启桌面版
新增 custom_nodes必须重启桌面版（桌面版没有 ComfyUI-Manager）
不要用 Stop-Process 杀桌面版后端。 Desktop 不会自动重启，8188 会变 502；也不要另起一个临时 ComfyUI 抢 8188。

12. 命令行速查

# 建片 / 导入分镜
python run_selflift.py --cfg <片>/segments.json import --src <分镜.json>

# 接线校验（正式跑之前先做，能对出 Picture 编号）
python run_selflift.py --cfg <片>/segments.json graph

# 逐段 / 全片 / 强制重出
python run_selflift.py --cfg <片>/segments.json seg 1
python run_selflift.py --cfg <片>/segments.json all
python run_selflift.py --cfg <片>/segments.json --force all

# 拼接（不带 --join 时按片配置里的 join_mode）
python run_selflift.py --cfg <片>/segments.json merge
python run_selflift.py --cfg <片>/segments.json --join cut merge

# 改全局字段
python run_selflift.py --cfg <片>/segments.json set --megapixels 0.8 --aspect-ratio "9:16 (Portrait Widescreen)"
python run_selflift.py --cfg <片>/segments.json set --join cut
python run_selflift.py --cfg <片>/segments.json set --seg 3 --seed 528329 --body "..."

Windows 下请用 ComfyUI/.venv/Scripts/python.exe，并设 PYTHONUTF8=1 PYTHONIOENCODING=utf-8，否则子进程中文输出会变方块。
